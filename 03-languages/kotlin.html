模块 1

与 Java 互操作

Kotlin 不是"另一个 JVM 语言"那么单纯——它就是为替代 Java 写的，互操作设计到了字节码层面。但默认生成的字节码和 Java 习惯不一样，这是最大的坑源。

Java 代码调用 Kotlin：默认字节码的四个"意外"

Kotlin 写法生成的字节码形态Java 怎么调
class Foopublic final class（默认 final，不可继承）直接 new Foo()。要被继承必须写 open class Foo，方法同理 open fun
fun f(a: Int, b: Int = 0)f(int, int) + f$default 合成方法Java 看不到默认参数，必须 f(1, 0) 全传。加 @JvmOverloads 才会生成 f(int) / f() 重载
object Singleton { fun go() }普通 class + 静态字段 INSTANCESingleton.INSTANCE.go()。加 @JvmStatic 才能 Singleton.go()
val CONST = "x"private 字段 + getCONST()getCONST()。加 @JvmField 才暴露为 public 字段 x
fun topLevel()（文件顶层函数）FileNameKt.topLevel()用 @file:JvmName("Utils") 把类名改成 Utils.topLevel()
// Kotlin 侧：一份同时服务 Kotlin 和 Java 的 API
object UserFactory {
    @JvmStatic
    fun create(name: String): User = User(name)
}

open class Base {
    open fun hello() = "hi"
    fun finalMethod() {}          // 默认 final，子类不能重写
}

class Derived : Base() {
    override fun hello() = "hello"
}

@JvmOverloads
fun greet(name: String, greeting: String = "Hi") = "$greeting, $name"

// Java 侧调用效果：
// UserFactory.create("Tom")            —— @JvmStatic 生效
// new Derived().hello()                —— open 才能 override
// UtilsKt.greet("Tom", "Hi")           —— 默认参数不可见，@JvmOverloads 后可 greet("Tom")

Kotlin 代码调用 Java：平台类型（Platform Types）

Java 方法没有可空性信息，Kotlin 把它的返回类型当成平台类型，显示为 String!：既能当 String 用，也能当 String? 用，编译器都不拦——于是 NPE 就 runtime 见了。

// Java: public String getName() { return null; }
val name: String = javaObj.name   // 编译通过！运行 NPE
val name2: String? = javaObj.name  // 正确：先当可空处理
println(name2?.length ?: 0)     // 0

// 带可空注解的 Java（JetBrains @Nullable / JSR-305 / AndroidX）Kotlin 能识别
// Java: public @Nullable String getMaybe()
val m: String? = javaObj.maybe      // 直接就是 String?，编译期安全
平台类型是 Kotlin 里 NPE 的最后一道暗门。防御三板斧：① 老 Java 库加 org.jetbrains:annotations 依赖并逐步补 @Nullable/@NotNull 注解；② Kotlin 侧拿到 Java 返回值先判空再赋值给非空类型；③ 新代码全用 Kotlin 写，别再把 String! 泄进 Kotlin 的非空世界。

模块 2

空安全：?、!!、lateinit

类型系统层就把 NULL 管住

Kotlin 的可空性是类型级的：String 不可能为 null，String? 才可能。赋值 null 给非空类型是编译错误，不是运行时错误。

写法语义null 时发生什么
s.length非空类型直接访问不可能为 null（编译期保证）
s?.length安全调用：s 为 null 则整条链为 null返回 null（不执行后面的调用）
s!!.length非空断言：我保证它不为 null抛 KotlinNullPointerException
s?.length ?: 0Elvis：左侧为 null 用右侧兜底得到 0
s?.let { ... }仅当 s 非空执行代码块，it 指代 s代码块被跳过
x as? String安全类型转换转换失败返回 null 而不抛 ClassCastException
fun parsePort(text: String?): Int {
    if (text == null) return -1
    return text.toIntOrNull() ?: -1     // 智能转换：判空后 text 被当作非空
}

// 链式调用：一层为 null，后面全部短路
val cityLen = user?.address?.city?.length   // Int? —— 任何一环 null，结果就是 null

// 安全调用 + Elvis + let 组合
val user = findUser(id)
user?.let { println("${it.name} 的余额 ${it.balance ?: 0.0}") }
    ?: println("用户不存在")

// let / run / apply / also / with：把可空检查和逻辑编排合在一起
val result = response?.body
    ?.takeIf { it.isNotBlank() }
    ?.trim()
    ?: "empty"

手段适用限制 / 行为

    }
}

class Config {
    val settings: Map<String, String> by lazy {
        loadFromDisk()          // 第一次访问 settings 时才执行，且只执行一次
    }

!! 是代码 review 的重点对象。它把编译期问题推成运行时崩溃，且没有行号友好信息（KotlinNullPointerException）。唯一可接受的场景：你同时握着 100% 的语义保证（如刚判空过的局部变量、单元测试里明知非空）。业务代码里看到 !!，先问一句"能不能换成 ?.let / ?: 提前返回"。
模块 3

数据类与解构

data class User(
    val name: String,
    val age: Int,
    var email: String? = null          // 默认参数 + 可空，链式构造很方便
)

val u = User("Tom", 28)                // email 用默认值 null
val u2 = u.copy(age = 29)              // 复制一个，只改 age
val (name, age) = u                     // 解构声明：底层是 component1() / component2()
println(u == u2)                     // false：结构性相等（equals 比较所有主构造参数）
println(u == User("Tom", 28))          // true：同名同龄即相等，不需要同一个对象
println(u)                           // User(name=Tom, age=28, email=null) —— 自动 toString

编译器自动生成什么

成员行为
equals / hashCode按主构造函数的参数做结构性比较。类体里额外声明的属性不参与相等判断
toStringUser(name=..., age=..., ...) 一眼看清内容
copy()复制实例并覆盖指定属性。浅拷贝：引用类型字段复制的是引用，两个对象共享同一个子对象
component1..N支撑解构声明，也让你可以写 val (a, b) = pair
getter（无 setter）val 参数只生成 getter；var 参数生成 getter + setter。Java 侧看到 getName() / setName()
copy() 是浅拷贝。如果 data class 里有 List / Map / 自定义可变对象字段，copy 出来的新旧实例共享同一份内部数据。改一边的 list，另一边也变。需要深拷贝就得手写，或者用不可变集合（Kotlinx 的 persistent collections）+ copy。
另外两个限制：① data class 必须有至少一个主构造参数；② 不能是 abstract / open / sealed / inner（但可以是 sealed 类的子类）。data class 之间不能继承，两个字段列表相同的 data class 也不相等（类型不同 equals 直接 false）。

解构的实际用途

// Map 遍历：entry 的解构是 Kotlin 标准语法
for ((key, value) in map) {
    println("$key -> $value")
}

// Lambda 单参数解构（配合 Map.forEach）
map.forEach { (k, v) -> println("$k=$v") }

// 自己写 componentN，普通类也能解构
class Point(val x: Int, val y: Int) {
    operator fun component1() = x
    operator fun component2() = y
}
val (x, y) = Point(1, 2)
模块 4

扩展函数：给别人的类"加"方法

// 声明：接收者类型 + 扩展名
fun String.lastChar(): Char = this[length - 1]

println("Kotlin".lastChar())        // n —— 用起来像原生方法

// 泛型扩展
fun <T> MutableList<T>.swap(index1: Int, index2: Int) {
    val tmp = this[index1]
    this[index1] = this[index2]
    this[index2] = tmp
}

// 可空接收者扩展：把判空逻辑收进函数
fun String?.orDefault(default: String): String = this ?: default

// 伴生对象扩展：给类的伴生对象加方法
fun User.Companion.fromJson(json: String): User =
    User(json.substringAfter("\"").substringBefore("\""), 0)

必须知道的两件事

① 扩展函数不是真正修改类，是编译期的静态分发。它编译成一个静态方法 ExtensionsKt.lastChar(String)，第一个参数是接收者。后果：扩展函数不能被子类重写——基类声明一个扩展、子类声明同名扩展，调用哪个取决于编译期声明的类型，不是运行时类型。Java 视角：就是静态工具方法，只是调用语法糖。
② 扩展不兼容"成员优先"：如果类里本来就有同名成员函数，成员永远赢，扩展被完全遮蔽。给已有类写扩展前，先确认没有同名成员。

标准库五兄弟：let / run / apply / also / with

这五个高频扩展决定了 Kotlin 代码的编排风格。区别只有两点：上下文对象怎么指代（this / it）和返回值是什么。

函数指代方式返回值典型用途
letit（可改名）代码块最后一行判空执行：user?.let { save(it) }；链式转换
runthis代码块最后一行在一个对象上下文里计算并返回结果
applythis对象本身初始化/配置对象：TextView().apply { text = "x" }
alsoit对象本身附加副作用：日志、校验：user.also { log(it) }
with(obj)this代码块最后一行把多个对同一对象的调用收拢到一个块
// apply：配置式初始化（Android 里最常用）
val tv = TextView(context).apply {
    text = "Hello"
    textSize = 16f
    setTextColor(Color.BLACK)
}

// let：空安全 + 链式
val display = user?.name
    ?.takeIf { it.isNotBlank() }
    ?.let { "用户：$it" }
    ?: "匿名用户"

// run：上下文计算
val total = order.run {
    price * quantity - discount
}
模块 5

协程基础：suspend / launch / async

协程解决的是用同步的写法干异步的活：不阻塞线程地等待 IO。Kotlin 协程 = suspend 函数 + CoroutineScope + 结构化并发 + Dispatchers。

挂起函数与协程构建器

概念说明
suspend fun挂起函数。编译成状态机（CPS 转换），可以把执行"暂停"到某个点，让出线程，IO 完成后从断点继续。只能在协程里或其他 suspend 函数里调用
launch { }启动一个不返回值的协程，返回 Job（可 cancel / join）。"发射后不管"
async { }启动一个有返回值的协程，返回 Deferred<T>，await() 拿结果（挂起等待）。并发下载的标配
runBlocking { }桥接函数：阻塞当前线程直到块内协程全部结束。只用于 main() 和测试，业务代码禁用
withContext(d) { }切到指定 Dispatcher 执行并返回结果，块结束后自动切回。挂起函数，最推荐的线程切换方式
suspend fun fetchUser(id: String): User =
    withContext(Dispatchers.IO) {          // 切到 IO 线程池，完成后切回
        http.get("/users/$id").body()
    }

fun main() = runBlocking {
    // 串行：先加载配置再加载用户
    val cfg = loadConfig()

    // 并发：两个请求同时发出
    val profile = async { fetchUser("1") }
    val orders  = async { fetchOrders("1") }
    val p = profile.await()            // 挂起等待，不阻塞线程
    val o = orders.await()
    println("${p.name} 有 ${o.size} 笔订单")

    val job = launch {                  // fire-and-forget
        delay(1000)
        println("后台任务完成")
    }
    job.join()                          // 等它完成
}

// delay 是挂起（让出线程），Thread.sleep 是阻塞（占着线程）
delay(1000)        // ✓ 协程里用这个
Thread.sleep(1000) // ✗ 白占一个线程

结构化并发：协程不是野马

协程必须在 CoroutineScope 里启动。scope 定义协程的生命周期边界：scope 取消，里面所有协程一起取消；scope 会等待所有子协程结束才认为自己完成。这就是结构化并发。

Scope用途
GlobalScope整个进程生命周期。脱离结构化并发，泄漏且不可取消——业务代码不要用
viewModelScopeAndroid：ViewModel 销毁时自动取消
lifecycleScopeAndroid：Activity/Fragment 生命周期结束时取消
coroutineScope { }挂起函数：建子作用域，等待所有子协程完成；子协程失败会取消兄弟并传播异常
supervisorScope { }同上，但一个子协程失败不影响其他子协程（异常不再向上传播）

异常传播：最容易写错的一块

场景行为
launch 里抛异常立即传播给父协程 → 取消父协程和所有子协程；没有 CoroutineExceptionHandler 时可能导致线程崩溃（Android 上直接 crash）
async 里抛异常不立即抛出，异常存在 Deferred 里，直到 await() 才抛出。忘了 await 的 async 等于吞掉异常
CoroutineExceptionHandler只能装在 launch 链上（或根协程）。装在 async 上无效，async 的异常归调用方处理
try-catch 包住 async包不住——要 try-catch await() 那一行
// 正确处理并发里的异常
val handler = CoroutineExceptionHandler { _, e ->
    println("捕获：${e.message}")
}

coroutineScope {
    // 用 supervisorScope 包住多个 async：一个挂不会连坐
    val a = async {
        try { riskyWork() } catch (e: IOException) { fallback() }
    }
    val b = async { otherWork() }
    // 异常处理要么在 async 内部 try，要么在 await 处 try
}

// 注意：try 要包住 await，不是包住 async
val d = async { throw IOException("boom") }
try {
    d.await()
} catch (e: IOException) {
    println("这里才捕获到")
}

Dispatchers：四类线程池

Dispatcher跑在什么线程
Dispatchers.MainAndroid / Swing UI 线程。服务端 JVM 没有 Main，装了 kotlinx-coroutines-javafx/swing 等才有
Dispatchers.IOIO 密集：文件、网络、数据库。默认最多 64 个线程（官方文档 DefaultDispatcher-worker 与 IO 共享线程池，IO 上限 64），超出的任务排队
Dispatchers.DefaultCPU 密集，线程数 = CPU 核心数（至少 2）
Dispatchers.Unconfined不限定线程，在哪个挂起点恢复就在哪个线程继续。测试和极端场景用，生产基本不用
协程的核心心智模型："挂起 ≠ 阻塞"。挂起只是把协程的状态存起来、把线程还给线程池，IO 完成后由框架在合适的线程恢复执行。所以几千个协程可以共享几十个线程——这是协程替代"一个请求一个线程"的底气。配套的 Flow（冷流，协程版的响应式流）处理连续数据流，后续单独学。
模块 6

when 表达式：switch 的完全体

// when 作为表达式：直接产出值，替代 Java 的三元/switch 链
fun describe(obj: Any): String = when (obj) {
    1              -> "数字一"
    in 2..9        -> "小数字"
    is String     -> "长度 ${obj.length} 的字符串"   // 智能转换成 String
    is List<*>    -> "有 ${obj.size} 个元素"
    else          -> "未知类型"                      // 穷尽性兜底
}

// 无参 when：就是清爽的 if-else-if
fun grade(score: Int): String = when {
    score >= 90 -> "A"
    score >= 80 -> "B"
    score >= 60 -> "C"
    else       -> "D"
}

// 分支可以是代码块，值是最后一行
val result = when (status) {
    "paid" -> {
        log("支付成功")
        "已支付"
    }
    "pending" -> "待支付"
    else -> "已取消"
}

与 Java switch 的对比

能力Kotlin whenJava switch（旧）
任意表达式做分支条件✓（==、in 区间、is 类型、逗号并列、无参布尔）仅常量 / 枚举 / String
作为表达式返回值✓（when 有值）✗（语句，要 return）

穷尽性的版本口径：当 when 用作表达式且主题是 enum / sealed 类型 / Boolean 时，Kotlin 编译器要求覆盖所有情况（或写 else）。Kotlin 1.6 起对非穷尽的 when 发出警告，并在此后版本中收紧为编译错误（官方渐进式策略）。工程上的稳妥写法：给每个 when 表达式都写上 else，或者搭配密封类让编译器替你穷尽检查——将来给枚举加新值时，漏改的 when 会直接编译失败，而不是带病上线。
模块 7

密封类：编译期安全的有限状态

密封类把"一个类型的可能性"钉死在一个封闭集合里。编译器知道所有子类，when 就能做穷尽检查——这是 Kotlin 建模状态机的标准手法。

sealed class Result<out T> {
    data class Success<T>(val data: T) : Result<T>()
    data class Failure(val code: Int, val msg: String) : Result<Nothing>()
    object Loading : Result<Nothing>()
}

// 穷尽的 when：编译器保证所有子类都处理到，漏一个编译不过
fun <T> render(r: Result<T>): String = when (r) {
    is Result.Success -> "成功：${r.data}"
    is Result.Failure -> "失败[${r.code}]：${r.msg}"
    Result.Loading     -> "加载中..."
    // 不需要 else —— 编译器知道 Result 只有这三种
}

密封类 vs 枚举 vs 普通类

坑

十个线上坑

1
把 Java 返回值（平台类型 String!）当非空用
编译不报错，运行 NPE。Java 库先补 @Nullable/@NotNull 注解，或 Kotlin 侧显式声明为 String? 再判空。
2
data class 的 copy() 当深拷贝用
copy 是浅拷贝，List / 自定义对象字段新旧实例共享。要独立数据就手动 copy 内部字段，或改用不可变集合。
3
给类写扩展函数，以为子类能"重写"
扩展是静态分发，调用哪个取决于编译期声明类型。且同名成员函数永远优先于扩展，扩展直接被遮蔽。
4
用 GlobalScope.launch 发后台任务
脱离结构化并发：所在组件销毁它还在跑，泄漏且不可取消。Android 用 lifecycleScope / viewModelScope，服务端注入 CoroutineScope。
5
async 的异常没人接
async 失败不会立刻抛出，异常存在 Deferred 里，不 await 就静默吞掉。try 要包住 await()，或者用 supervisorScope 隔离。
6
lateinit 没初始化就访问
抛 UninitializedPropertyAccessException。用 ::prop.isInitialized 先检查；能在构造期确定的属性别用 lateinit，直接初始化或 by lazy。
7
把 == 当 Java 的 == 用
Kotlin 的 == 是 equals（结构相等），=== 才是引用相等。反过来把 Java 的 == 习惯带进 Kotlin，比较对象时得到一堆意外的 false。
8
以为 List 参数不可变就是安全的
Kotlin 的 List 是只读视图，底层可能还是 java.util.ArrayList。Java 侧强转 MutableList 就能改。跨边界传集合时警惕。
9
协程里用 Thread.sleep 做延迟
阻塞线程，白白占用 IO 线程池的 64 个名额之一，高并发下线程耗尽任务全排队。用 delay。
10
给 Java 的 Kotlin API 传默认参数
Java 看不到 Kotlin 默认参数，编译报 "no suitable method found"。暴露给 Java 的函数加 @JvmOverloads。
自测

六道题

1. Java 方法 public String getName() 没有任何注解，Kotlin 中 val name: String = obj.getName() 会怎样？
正确答案：编译通过，运行时 NPE。没有注解的 Java 返回类型在 Kotlin 里是平台类型 String!，既可按非空也可按可空使用，编译器不检查——风险留到运行时。防御：补注解，或 Kotlin 侧显式声明为 String?。
2. data class User(val name: String, val age: Int) 会自动生成哪些成员？
正确答案：equals、hashCode、toString、copy、componentN。相等性只比较主构造参数；copy 是浅拷贝；componentN 支撑解构声明。类体里额外声明的属性不参与 equals。
3. 基类 Base 和子类 Derived 都定义了扩展 fun String.tag()，调用 obj.tag()（obj 编译期声明为 Base）执行哪个？
正确答案：Base 的扩展。扩展函数编译成静态方法，是静态分发，调用哪个取决于编译期声明的接收者类型，与运行时真实类型无关。另外：成员函数永远优先于同名扩展函数。
4. val d = async { throw IOException() }，异常什么时候抛出？
正确答案：await() 时抛出。async 的异常存在 Deferred 里，直到 await 才交给调用方。所以 try-catch 要包住 await()；如果不 await，异常永远不会出现（但协程失败状态还在，join 能观察到取消）。launch 的异常则是立即向父作用域传播。
5. Kotlin 里 a == b 与 a === b 的区别是？
正确答案：== 走 equals()，=== 走引用相等。这和 Java 正好相反（Java 的 == 是引用，equals 是内容）。写 Kotlin 时把 Java 的 == 习惯带过来是最常见的语义错位。
6. when 用作表达式且主题是 sealed class 时，为什么可以不写 else？
正确答案：编译器做穷尽性检查。密封类的子类集合是封闭的，编译器枚举所有可能分支，缺一个就编译失败。将来给 sealed class 加子类，漏改的 when 直接报错——这就是它替代枚举 + if-else 的核心价值。注意：穷尽检查要求 when 是表达式用法。
