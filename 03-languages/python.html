模块 1

Python 是什么，为什么这么流行

一句话：它把"写起来爽"和"生态够大"两件事同时做到了。

特性含义
解释型不需要编译，写完直接跑。改一行立刻看效果
动态类型变量不用声明类型，运行时才确定。灵活但容易出运行时错误（所以有了模块 10 的类型注解）
强类型注意：动态 ≠ 弱类型。"1" + 1 会直接报错，不会偷偷转换
缩进即语法用缩进表示代码块，没有花括号。好处是强制统一风格，坏处是缩进错了程序行为就变了
一切皆对象数字、字符串、函数、类，全都是对象。这是理解 Python 的关键
生态巨大数据分析、爬虫、AI、自动化运维、Web 后端，都有成熟库
学 Python 最大的认知转变：变量不是"盒子"，而是"贴在对象上的名字"。这一条想通了，后面所有"诡异"的行为（模块 11 的十个坑）都会变得理所当然。

match：结构化模式匹配（3.10+）

match command.split():
    case ["go", direction]:        print(f"往 {direction} 走")
    case ["look"]:                 print("环顾四周")
    case ["pick", *items]:         print(f"捡起 {items}")
    case {"action": "quit"}:       print("退出")
    case _:                       print("无效指令")

它比 if/elif 强的地方在于能匹配结构（列表长度、字典键、类型），而不只是比较值。别把它当 C 的 switch 用。

参数的四种形态

def f(a, b=2, *args, c, **kwargs):
    ...

# a      位置参数，必传
# b=2    默认参数，可省略
# *args  收集多余的位置参数成一个 tuple
# c      关键字参数（放在 * 后面，必须用 c=xxx 传）

这里藏着 Python 最著名的坑。默认参数只在函数定义时求值一次，之后所有调用共用同一个对象： 
def add(item, lst=[]):      # 错！
    lst.append(item)
    return lst

add(1)   # [1]
add(2)   # [1, 2]   ← 不是 [2]！那个列表被共享了

# 正确写法：用 None 当哨兵
def add(item, lst=None):
    if lst is None: lst = []
    lst.append(item)
    return lst

作用域：LEGB 规则

变量查找顺序是 Local（函数内）→ Enclosing（外层函数）→ Global（模块级）→ Built-in（内置）。

count = 0
def inc():
    count += 1        # UnboundLocalError！
# 因为函数里对 count 赋值了，Python 就把它当成局部变量
# 正确做法：声明 global
def inc():
    global count
    count += 1
但更好的做法是根本不用 global。全局可变状态会让代码难以测试和推理。函数应该通过参数拿输入、通过返回值给输出。真需要共享状态，用一个类来封装。

lambda：只能写一个表达式的匿名函数

sorted(users, key=lambda u: (u.age, u.name))       # 多级排序
max(words, key=len)                              # 直接用内置函数当 key
list(filter(lambda x: x > 0, nums))

lambda 只适合"传一个简单函数给另一个函数"的场景。一旦有逻辑分支或需要多行，就用 def —— 匿名函数里的复杂逻辑是维护灾难。

闭包与装饰器

# 闭包：内层函数记住了外层函数的变量
def multiplier(n):
    def inner(x):
        return x * n      # n 被"记住"了
    return inner

double = multiplier(2)
double(5)                 # 10

# 装饰器：不修改原函数，给它套一层功能
import functools, time

def timer(func):
    @functools.wraps(func)          # 保留原函数的名字和文档，别漏
    def wrapper(*args, **kwargs):
        t0 = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} 耗时 {time.perf_counter()-t0:.4f}s")
        return result
    return wrapper

@timer
def slow_task():
    time.sleep(1)

slow_task()   # 自动打印耗时

@timer 这一行完全等价于 slow_task = timer(slow_task)。理解了这个等式，装饰器就不神秘了 —— 它就是个接收函数、返回函数的函数。

模块 6

错误处理

try:
    result = 10 / int(user_input)
except ValueError:
    print("输入的不是数字")
except ZeroDivisionError as e:
    print(f"除零错误：{e}")
except (KeyError, IndexError):
    print("键或下标不存在")
else:
    print("一切正常")        # 没出异常才执行
finally:
    print("无论如何都执行")  # 用来释放资源
子句执行时机
try放可能出错的代码
except捕获指定异常并处理
elsetry 里没有出异常时执行
finally无论是否出异常都执行，用于清理
两条铁律：
① 绝不要写裸的 except:。它会连 Ctrl+C 和系统退出都吞掉，让程序无法中断、错误无法定位。至少写 except Exception:，更好是精确捕获具体异常类型。
② 不要用异常做流程控制。能用 if 判断的情况就别 try。

自定义异常与抛出

class InsufficientBalance(Exception):
    """余额不足"""

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientBalance(f"余额 {balance} 不足支付 {amount}")
    return balance - amount

自定义异常让调用方能精确地分别处理不同错误，比返回错误码清晰得多。

EAFP vs LBYL

# LBYL：先检查再操作（Look Before You Leap）
if "key" in d:
    value = d["key"]

# EAFP：直接做，出错再处理（Easier to Ask Forgiveness than Permission）
try:
    value = d["key"]
except KeyError:
    value = None

Python 社区更推崇 EAFP：它避免了"检查通过后、使用前状态又变了"的竞态问题，而且在正常路径上更快。但如果是 .get()、.getattr() 这类现成方法能解决的，优先用它们。

模块 8

面向对象

class Animal:
    species = "动物"              # 类属性：所有实例共享

    def __init__(self, name, age): # 构造方法
        self.name = name           # 实例属性：每个实例独立
        self.age = age

    def speak(self):               # self 就是实例本身，必须显式写
        return f"{self.name} 叫了一声"

    def __str__(self):             # 给 print 用的
        return f"<{self.name}, {self.age}岁>"

    def __repr__(self):            # 给调试用的，理想情况下能重建对象
        return f"Animal(name={self.name!r}, age={self.age})"


class Dog(Animal):                 # 继承
    def __init__(self, name, age, breed):
        super().__init__(name, age)   # 调用父类构造
        self.breed = breed

    def speak(self):                # 重写
        return f"{self.name} 汪汪叫"

@property：把方法伪装成属性

class Circle:
    def __init__(self, r): self._r = r

    @property
    def area(self):                 # 用的时候不加括号：c.area
        return 3.14159 * self._r ** 2

    @property
    def radius(self): return self._r

    @radius.setter
    def radius(self, v):            # 赋值时做校验
        if v < 0: raise ValueError("半径不能为负")
        self._r = v

它让你既能保持 c.radius = 5 这种自然的写法，又能在背后加校验逻辑。这是 Python 里"先简单实现，需要时再升级"的典型手段。

dataclass：写数据类别再手写 __init__

from dataclasses import dataclass, field

@dataclass
class User:
    name: str
    age: int = 0
    tags: list[str] = field(default_factory=list)  # 可变默认值必须这样写

u = User("张三", 28)
u == User("张三", 28)   # True，自动生成了 __eq__
print(u)                 # 自动生成了可读的 __repr__
什么时候用 dataclass：这个类的主要作用是"装数据"，没有复杂行为。什么时候不用：类有大量业务逻辑、需要精细控制初始化过程。
注意 field(default_factory=list) —— 这是模块 5 那个可变默认参数坑的官方解法。
模块 9

迭代器、生成器、上下文管理器

生成器：惰性求值的函数

def read_large_file(path):
    with open(path) as f:
        for line in f:
            yield line.strip()      # 每次产出一个值就暂停，不占内存

for line in read_large_file("huge.txt"):
    process(line)               # 10GB 的文件也只占几 KB 内存

yield 和 return 的区别：return 结束函数并给一个值；yield 暂停函数、给出一个值、下次调用从这里继续。函数里一旦有 yield，它就变成生成器函数，调用它不会执行函数体，只返回一个生成器对象。

# 生成器也能接收值，实现协程式流程
def accumulator():
    total = 0
    while True:
        x = yield total      # yield 的返回值是 send 传进来的值
        if x is None: return
        total += x
什么时候该用生成器：数据量很大、或者你不需要一次性拿到全部结果（比如"找到第一个符合条件的就停"）。什么时候不该用：需要反复遍历同一个结果、需要 len()、需要下标访问 —— 那就老老实实用 list。

上下文管理器：确保资源被释放

# with 保证无论如何都会关闭文件，哪怕中间抛异常
with open("a.txt") as f:
    data = f.read()

# 自己写一个：用装饰器最省事
from contextlib import contextmanager
import time

@contextmanager
def timer(label):
    t0 = time.perf_counter()
    yield                          # yield 之前是进入时执行
    print(f"{label} 耗时 {time.perf_counter()-t0:.4f}s")  # 之后是退出时执行

with timer("查询"):
    do_query()

凡是"用完必须清理"的东西 —— 文件、数据库连接、锁、临时目录 —— 都应该用 with 管理。这是 Python 里最实用的设计模式之一。

Python 是动态类型，但这不意味着不需要类型信息。类型注解让编辑器和静态检查工具帮你在运行前发现问题。

def greet(name: str, times: int = 1) -> str:
    return f"你好 {name} " * times

from typing import Optional, Union, Any, Callable

def find(uid: int) -> Optional[dict]:        # 可能返回 dict 或 None
    ...

def parse(x: int | str) -> None:             # 联合类型，3.10+ 的简洁写法
    ...

def apply(f: Callable[[int], str], x: int) -> str:
    ...

names: list[str] = []                    # 内置泛型写法，3.9+
cache: dict[str, int] = {}
point: tuple[float, float] = (1.0, 2.0)
关键认知：注解在运行时不做任何检查。Python 不会因为你写了 name: str 就阻止你传 int 进去。它的价值在于：① 编辑器自动补全和提示；② mypy 这类工具做静态检查；③ 代码自解释。

模块 11

十个经典陷阱

1
可变默认参数
def f(lst=[]) —— 默认值只在定义时求值一次，所有调用共享同一个列表。用 lst=None 兜底。
2
循环里创建闭包的晚绑定
[lambda: i for i in range(3)] 三个函数都返回 2 —— 它们捕获的是变量 i 而不是当时的值。用 lambda i=i: i 或 functools.partial 固定。
3
is 和 == 用混
== 比的是值，is 比的是"是不是同一个对象"。判断 None 要用 is None，但判断数字和字符串必须用 ==。
4
浅拷贝被当成深拷贝
b = a.copy() 只复制外层。嵌套的列表仍然是共享的，改内层两边一起变。需要彻底独立用 copy.deepcopy()。
5
小整数缓存导致 is 结果诡异
Python 缓存了 -5 到 256 的整数，所以 256 is 256 是 True 而 257 is 257 可能是 False。别依赖这个行为。
6
遍历列表时修改它
边 for 边 remove 会跳过元素。正确做法是遍历副本 for x in list(a):，或者用推导式生成新列表。
7
以为多线程能加速 CPU 密集任务
GIL（全局解释器锁）让同一时刻只有一个线程执行 Python 字节码。CPU 密集用多进程，IO 密集用多线程或 asyncio。
8
用 float 存钱
0.1 + 0.2 != 0.3。金额一律用 decimal.Decimal，或者干脆用整数存"分"。
9
循环里用 += 拼字符串
字符串不可变，每次 += 都新建一个对象，数据量大时是 O(n²)。用 "".join(列表)。
10
函数里给全局变量赋值忘了 global
一旦函数内对某名字赋值，它整个函数内就是局部变量，读之前赋值会报 UnboundLocalError。更好的解法是别用全局变量。
自测

六道题

1. 下面这段代码输出什么？
def f(x, lst=[]): lst.append(x); return lst 然后连续调用 f(1) 和 f(2)
正确答案：[1] 和 [1, 2]。默认参数只在函数定义时求值一次，那个列表被所有调用共享。正确写法是用 lst=None 然后在函数内初始化。
2. a = [1, 2]，然后 b = a，再 b.append(3)。此时 a 是什么？
正确答案：[1, 2, 3]。变量是"贴在对象上的名字"，b = a 只是多贴了一个名字，不复制。要真正独立用 b = a.copy()。
3. 判断一个变量是不是 None，应该怎么写？
正确答案：x is None。is 比较对象身份，None 在全局只有一个实例，所以用 is 最准确也最快。== 可以被自定义的 __eq__ 干扰。
4. 函数里的 yield 关键字的作用是？
正确答案：暂停并产出值。含 yield 的函数变成生成器函数，支持惰性求值，处理大文件时内存占用极低。结束函数是 return。
5. 为什么 CPU 密集型任务用多线程没有加速效果？
正确答案：GIL（全局解释器锁）。所以 CPU 密集任务要用多进程（multiprocessing），IO 密集任务（网络、文件）用多线程或 asyncio 才有效。
6. 下面哪一个是 Python 里"假值"？
正确答案：空列表 []。假值只有这几种：False、None、0、0.0、空字符串、空列表、空字典、空元组、空集合。注意 "0" 是非空字符串（真），[0] 是非空列表（真）。
