先建立一个总认知：Vue 3 = 编译时（模板 → 渲染函数 + patchFlag 优化）+ 运行时（Proxy 响应式 + 虚拟 DOM diff）两套系统协作。React 是"一套运行时打天下"，Vue 把很多优化放在编译期——这就是为什么 Vue 模板写起来更"傻瓜"但能力受模板语法约束。
模块 1

组合式 API：setup、ref/reactive、computed、watch

组合式 API 的核心收益：同一个逻辑关注点的代码聚合在一起，而不是按 data/methods/computed 拆散。setup 是唯一入口，只执行一次。

<script setup>  // 语法糖：顶层声明直接暴露给模板，不用 return，也不用 components 注册
import { ref, reactive, computed, watch, watchEffect, onMounted } from 'vue'

const count = ref(0)                        // 基本类型：ref 包装，JS 里必须 .value
const form = reactive({ keyword: '', page: 1 })   // 对象：reactive 深度代理，直接访问
const users = ref<User[]>([])               // 数组整体替换的场景，也常用 ref

const double = computed(() => count.value * 2)  // 缓存：依赖不变，访问一百次也只算一次

// watch：显式声明监听源，默认懒执行（值变了才跑）
watch(count, (n, old) => console.log(`count: ${old} -> ${n}`))
watch(() => form.page, (p) => fetchUsers(p))      // getter 源：监听派生值

// watchEffect：立即执行 + 自动收集依赖，不用声明"听谁"
watchEffect(() => console.log(`keyword = ${form.keyword}`))  // 立刻打印一次，之后每次变化都打

function inc() { count.value++ }              // JS 里改 ref 必须 .value（模板里会自动解包）

onMounted(() => fetchUsers(form.page))
</script>

<template>
  <button @click="inc">{{ count }} × 2 = {{ double }}</button>   {{!-- 模板里 ref 自动解包，不写 .value --}}
  <input v-model="form.keyword" placeholder="搜索" />
</template>
API适用关键行为
ref()基本类型、整体替换的对象/数组.value 读写；模板自动解包；reactive 内的 ref 也会解包
reactive()对象/Map/Set深度代理；不能整体重新赋值（会断开代理）；解构会丢失响应式
computed()派生状态惰性 + 缓存；依赖不变重复访问不重算；只放纯计算
watch()副作用（请求、日志）懒执行；可拿 old/new；可配 immediate/deep/flush
watchEffect()自动追踪依赖的副作用立即执行；自动收集；拿不到 oldValue
选型一句话：要 old 值、要精确控制触发时机 → watch；依赖来源分散、写了就跑 → watchEffect；只是算个值 → computed。副作用（发请求、改 DOM、写 localStorage）永远不要放 computed——它可能被缓存吞掉不执行。
模块 2

生命周期：从 Options 到 Composition

组合式 API 里没有 beforeCreate/created——setup 本身就替代了它们（组件实例创建后、DOM 挂载前）。

<script setup>
import { onMounted, onBeforeUnmount } from 'vue'

const onResize = () => console.log(window.innerWidth)
onMounted(() => {
  window.addEventListener('resize', onResize)
  const timer = setInterval(poll, 5000)
})
onBeforeUnmount(() => {          // 成对出现，缺一个就是泄漏
  window.removeEventListener('resize', onResize)
  clearInterval(timer)
})
</script>
模块 3

组件通信：props / emit / provide / v-model

<!-- Child.vue：props 下行 + emit 上行，全用编译期宏，无需 import -->
<script setup>
const props = defineProps<{
  title: string
  count?: number          // 可选
}>()
const emit = defineEmits<{
  (e: 'update:modelValue', v: string): void   // v-model 的 update 事件
  (e: 'close'): void
}>()

function onInput(e: Event) {
  emit('update:modelValue', (e.target as HTMLInputElement).value)
}
</script>

<template>
  <input :value="props.modelValue" @input="onInput" />   {{!-- 单向：值从父来，变更通知父 --}}
</template>

<!-- Parent.vue -->
<SearchBox v-model="keyword" @close="onClose" />
// 等价于：:modelValue="keyword" @update:modelValue="keyword = $event"
// 多个 v-model 参数（3.4+ 稳定写法）：
<UserForm v-model:first-name="f" v-model:last-name="l" />
// 编译为：:firstName="f" @update:firstName="..."，一个组件可同时绑多个
通路方向适用场景
props / emit父 → 子 / 子 → 父最常用。props 是只读的，改它父组件不知道
v-model + 参数双向语法糖表单组件；一个组件可同时有多个 v-model:x
provide / inject祖先 → 任意后代跨层级传配置（主题、表单上下文）。默认不响应式，要传 reactive 对象或 ref
attrs 透传父 → 子根元素class/style/事件自动落到子组件根节点；inheritAttrs: false 可关掉手动控制
插槽父 → 子内容区默认插槽、具名插槽、作用域插槽（把子的数据回传给父渲染）
模板 ref父拿子实例ref="childRef" + defineExpose 暴露方法。少用，优先 props/emit
Pinia全局跨页面共享状态。Vue 3 不再内置 event bus，需要时用 mitt
// provide/inject：传 reactive 值才响应式；传常量就只是依赖注入
// 祖先组件
import { provide, reactive, readonly } from 'vue'
const theme = reactive({ color: 'dark' })
provide('theme', readonly(theme))     // readonly 防止后代乱改
provide('size', 14)                     // 常量，无响应式

// 任意深层级后代
const theme = inject<{ color: string }>('theme')       // 拿到的是同一个 reactive 对象，改 color 双方同步
const size = inject<number>('size', 16)              // 第二个参数是默认值（没提供时不报 undefined）
props 铁律：单向数据流。子组件直接 props.count = 5 会报错（readonly），就算绕过（解构时拷贝一份）改也不会上同步父组件，父组件下次重渲染还会把你的修改覆盖回旧值——这是"输入框改了没反应"的经典病因。正确做法只有一条：emit('update:xxx', 新值) 让父组件改。
模块 4

模板语法与指令

<!-- v-if / v-else-if / v-else：真·条件渲染，切换销毁重建 DOM -->
<p v-if="status === 'loading'">加载中…</p>
<p v-else-if="status === 'error'">出错了：{{ error }}</p>
<p v-else>{{ data.name }}</p>

<!-- v-show：切 display:none，DOM 常驻。适合频繁切换（手风琴、折叠面板） -->
<div v-show="open" class="panel">…</div>

<!-- v-for：必须 :key，且用稳定业务 id，禁止用 index -->
<ul>
  <li v-for="(item, i) in visibleList" :key="item.id">
    {{ i + 1 }}. {{ item.name }}
  </li>
</ul>

<!-- v-model 修饰符 -->
<input v-model.trim="keyword" />          <!-- .trim 去首尾空格 -->
<input v-model.number="age" type="number" /> <!-- .number 转数字，非数字原样保留 -->
<input v-model.lazy="email" />             <!-- .lazy 从 input 事件换成 change 事件（失焦才同步） -->

<!-- 事件修饰符 -->
<form @submit.prevent="submit">…</form>      <!-- .prevent = preventDefault -->
<div @click.self="closeMask">…</div>          <!-- .self 只在点自身时触发（点冒泡进来的不算） -->
<input @keyup.enter="search" />               <!-- 按键修饰符：enter/tab/delete/esc/space/up/down/left/right -->
<button @click.once="pay">…</button>          <!-- .once 只触发一次 -->
对比结论
v-if vs v-showv-if 切换开销大（销毁/重建）+ 首次渲染便宜；v-show 首次渲染贵一点、后续切换几乎零成本。频繁切换用 v-show，运行时很少变用 v-if
v-for 的 keykey 是 diff 算法的复用依据。用 index 做 key，列表中间插入/删除时，组件实例和 DOM 会错位复用——输入框内容串台、动画错乱、内部 state 串到别的行
v-html渲染原始 HTML，绝不渲染用户可控内容——存储型 XSS。富文本场景用白名单净化库
v-once / v-memov-once 渲染一次永不更新；v-memo="[a, b]" 依赖数组不变则跳过 diff。极致优化才用
v-for 和 v-if 写在同一元素上是高频错误。Vue 3 中 v-if 优先级高于 v-for：v-if 求值时 v-for 的 item 还没生成，访问它得到 undefined（Vue 2 里恰好相反，所以老代码"能跑"纯属侥幸）。两种正确写法：① 把 v-for 的过滤交给 computed（v-for="item in visibleList"，性能最好）；② 在外面套一层 template 把 v-if 放外层。
模块 5

Pinia 状态管理

Pinia 是 Vue 官方状态管理（Vuex 5 的继任者）。核心优势：没有 mutations、没有嵌套 modules、TS 推导开箱即用、支持 setup 语法。

// stores/user.ts —— setup 语法（推荐，和组合式 API 心智一致）
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useUserStore = defineStore('user', () => {
  const token = ref('')
  const profile = ref<Profile | null>(null)
  const isLogin = computed(() => !!token.value)     // getter

  async function login(u: string, p: string) {      // action：可以 async
    const r = await api.login(u, p)
    token.value = r.token
    profile.value = r.profile
  }
  function logout() { token.value = ''; profile.value = null }

  return { token, profile, isLogin, login, logout }
})

// main.ts —— 必须先安装
app.use(createPinia())

// 组件里使用
const store = useUserStore()
const { isLogin } = storeToRefs(store)      // 解构 state/getter 保响应式；action 可直接解构
store.$patch({ token: 'new' })                  // 批量修改（补丁）
store.$subscribe((mutation, state) => {   // 状态变更订阅：持久化、埋点
  localStorage.setItem('token', state.token)
})
store.$onAction(({ name, after }) => after(() => console.log(name)))
写法说明
setup 语法defineStore('id', () => { ... return {...} })，TS 推导最好，推荐
options 语法defineStore('id', { state, getters, actions })，从 Vuex 迁过来的人熟悉
state 访问store.xxx 直接读写；解构必须配 storeToRefs，否则丢响应式
跨 store 调用action 里直接用另一个 useXxxStore()，无需注册
持久化pinia-plugin-persistedstate，按 store 粒度选择存哪些字段
useXxxStore() 的调用时机：必须在 app.use(pinia) 之后。组件内 setup 里调用天然满足；在路由守卫、axios 拦截器这些"组件外"的地方调用，要确认执行时 Pinia 已安装——提前调用会抛 "no active Pinia" 错误。工程解法：在 main.ts 里装完 pinia 之后再 import 那些模块，或把逻辑挪进组件/action。
模块 6

Vue Router：守卫与懒加载

// router/index.ts
const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    { path: '/', name: 'home',
      component: () => import('@/views/Home.vue') },   // 懒加载：拆成独立 chunk，进页面才下载
    { path: '/user/:id(\\d+)', name: 'user', component: UserView,
      props: true },                                  // 路由参数直接变 props
    { path: '/admin', component: AdminView, meta: { requiresAuth: true },
      beforeEnter: (to) => (isLogin.value ? true : { name: 'login', query: { redirect: to.fullPath } }) },
    { path: '/:pathMatch(.*)*', name: 'notfound', component: NotFound },
  ],
})

// 全局前置守卫：登录校验、权限、进度条开始
router.beforeEach((to, from) => {
  if (to.meta.requiresAuth && !token.value) {
    return { name: 'login', query: { redirect: to.fullPath } }   // 返回地址 = 重定向
  }
})

// 全局后置钩子：埋点（拿不到 next，也别想拦截）
router.afterEach((to) => sendPV(to.fullPath))

// 懒加载 chunk 失败（发版后旧 chunk 404）：兜底刷新
router.onError((err) => {
  if (/ChunkLoadError|Loading chunk/i.test(err.message)) location.reload()
})

// 组件内守卫：离开未保存表单前拦截
onBeforeRouteLeave((to) => {
  if (isDirty.value && !confirm('放弃未保存的修改？')) return false   // false = 取消导航
})

守卫执行顺序与返回值

① beforeRouteLeave（将要离开的组件）→ ② beforeEach（全局）→ ③ beforeEnter（路由独享）→ ④ 加载异步路由组件 → ⑤ beforeRouteEnter（进入的组件，此时实例还没建，用回调拿 this）→ ⑥ afterEach（全局，纯旁观）
返回值语义（Vue Router 4 起 next() 可选，直接 return）：false = 取消本次导航并留在原地；true/undefined = 放行；返回一个路由地址（对象或字符串）= 重定向到那里
懒加载是首屏优化的第一杠杆：每个 () => import() 都拆出一个 chunk，用户只下载当前路由需要的代码。配套动作：路由懒加载 + 组件按需注册 + 大依赖（echarts/xlsx）动态 import。注意 webpackChunkName 魔法注释在 Vite 里用不了，Vite 里靠构建产物的 chunk 名自动分组（manualChunks）。
模块 7

响应式原理：Proxy 与 defineProperty 之争

维度Vue 2 definePropertyVue 3 Proxy
拦截方式递归遍历每个 key，逐属性劫持 get/set代理整个对象，劫持 get/set/deleteProperty/has/ownKeys
新增属性检测不到，要 Vue.set(obj, key, val) 补✓ 正常触发更新
删除属性检测不到✓ deleteProperty 可拦截
数组索引写入检测不到，只能重写 7 个变异方法（push/pop…）绕✓ 索引写入即 set，原生生效
数组 length 变化检测不到✓ length 是属性，照样拦
性能初始化全量递归，深层大对象卡惰性深代理：访问到才代理子对象
Map/Set不支持✓ reactive 支持
代价兼容 IE9+Proxy 无法 polyfill，Vue 3 放弃 IE11
// Vue 2 时代三个"改了不更新"的经典场景：
const state = { list: [1, 2, 3], a: 1 }
state.list[1] = 99          // ✗ 索引写入无 setter，视图不更新
state.list.length = 0       // ✗ length 不是被劫持的属性
state.newKey = 'x'          // ✗ 新增属性，需要 Vue.set(state, 'newKey', 'x')

// Vue 3 的 reactive 下全部正常：
const s = reactive({ list: [1, 2, 3] })
s.list[1] = 99              // ✓
s.newKey = 'x'              // ✓
delete s.newKey             // ✓

ref 为什么存在：Proxy 只能代理对象

基本类型（number/string/boolean）按值传递，没有引用可劫持。Vue 3 的做法是包一层 { value } 对象，用 RefImpl 类给 value 属性加 getter/setter——get 时 track（把当前 effect 记进依赖集合），set 时 trigger（遍历执行所有依赖的 effect）。

// 依赖收集与触发的心智模型（简化版）：
// 每个响应对象的每个 key 对应一个 dep（Set<Effect>）
// get key → track：把"当前正在运行的 effect"加进 dep
// set key → trigger：把 dep 里所有 effect 加进待执行队列，微任务里统一 flush

// computed：带缓存的 effect。_dirty 标志位，依赖没变就不重算
// watch：在 effect 外层包一层 scheduler，变化时由用户回调处理
// 模板渲染：整个 render 函数就是一个 effect，依赖变了重新排队执行

// 不想被代理的：markRaw / toRaw
import { markRaw, toRaw, isReactive } from 'vue'
const raw = markRaw(new HeavyClass())     // 标记为"永不代理"，放进 reactive 也不劫持
const origin = toRaw(reactiveObj)         // 取出被代理前的原始对象（读写绕过响应式）
什么时候需要 markRaw？① 第三方类实例（地图 SDK、编辑器实例）被代理后方法内 this 会指向代理，行为可能诡异；② 巨大的只读数据表（几万行的字典），代理是纯开销。这两个场景不标记，表现为"页面越用越卡"而不是报错，很难查。
模块 8

Vue 3 vs React：机制层对比

维度Vue 3React 18
变化侦测Proxy 依赖收集：精确知道"哪个组件的哪个渲染函数读了哪个 key"不可变数据 + setState 全量触发组件 render，靠 Virtual DOM diff 找差异
更新粒度细粒度：状态变了只重跑依赖它的 effect组件级：父组件 render，子组件默认全 render，需 memo/useMemo 手动优化
视图层模板字符串，编译期生成渲染函数 + patchFlag 动态标记，diff 能跳过静态分支JSX，编译产物就是运行时的 createElement 调用，无额外优化信息
逻辑复用组合式 API / composablesHooks
样式方案scoped CSS、CSS ModulesCSS-in-JS（styled-components/emotion）、Tailwind
状态管理PiniaRedux / Zustand / Jotai / MobX（无官方答案）
TS 支持script setup + 泛型组件好；模板类型推导弱，靠 vue-tsc 补JSX 即类型，推导最完整
上手曲线模板 + 指令对初学者友好；SFC 单文件自包含JSX 自由度高，但对 JS 功底要求高
跨端弱（uni-app / NativeScript 等非主流）React Native 一统移动端
一句话总结设计哲学：Vue 是"编译时 + 细粒度响应式"，把优化做在框架里，开发者写起来更声明式；React 是"显式不可变数据 + 运行时调度"，把控制权交给开发者，灵活但心智负担重。选型上：后台管理系统、快速交付、国内团队 → Vue；大前端团队、跨端、JS 功底好 → React。两个都值得学，底层思想（组件化、单向数据流、虚拟 DOM）完全互通。
避坑

十个线上坑

1
解构 reactive 对象，响应式丢失
const { keyword } = form 之后改 form.keyword，keyword 不更新——解构出来的是普通值的快照。用 toRefs(form) 解构，或干脆不破坏引用直接用 form.keyword。
2
v-for 和 v-if 写在同一个元素上
Vue 3 里 v-if 优先级更高，访问不到 v-for 的 item（undefined），且每次渲染都要先过滤一遍。过滤逻辑交给 computed，或者外层套 template。
3
v-for 用 index 当 key
列表头部插入/删除时，组件实例按位置错位复用：输入框内容串到别的行、内部 state 错乱、过渡动画抽搐。必须用稳定业务 id；实在没有就用内容哈希。
4
setup 同步代码里读模板 ref，拿到 null
const el = ref(null) 在 setup 执行时 DOM 还没挂载。必须等 onMounted；v-if 控制的元素在条件翻转时 ref 还会先变 null 再重建。
5
子组件直接改 props
单向数据流：改了父组件不知道，父组件下次重渲染还覆盖回旧值。必须 emit('update:xxx', v) 让父组件改，或用 v-model 语法。
6
watch reactive 对象时以为能拿到"旧值"
watch(reactiveObj, cb) 默认 deep，回调里的 old 和 new 是同一个代理引用（已被改过）。要拿旧值得在变更前深拷贝，或 watch getter 返回原始字段。
7
provide 一个普通值当"响应式配置"
provide('cfg', { color: 'dark' }) 传的是普通对象，后代改了祖先不感知、祖先改了后代也不更新。传 reactive/ref 包装过的值才有响应式。
8
路由切换后旧请求返回覆盖新数据
快速切换 tab/路由，第一个请求后返回，把第二个页面的数据覆盖成旧内容。用 AbortController 取消旧请求，或用自增 requestId 守卫丢弃过期响应。
9
大数据对象/类实例直接进 reactive
几万行的字典、第三方 SDK 实例被 Proxy 后：内存和访问开销翻倍，实例方法里 this 指向代理还可能行为异常。用 markRaw 标记，读取用 toRaw。
10
在 app.use(pinia) 之前调用 useXxxStore()
路由守卫、请求拦截器里提前拿 store，直接抛 "no active Pinia"。确保 Pinia 安装后再执行这些模块，或把逻辑挪进组件/action 内。
自测

六道题

1. <li v-for="item in list" v-if="item.ok" :key="item.id"> 有什么问题？
正确答案：改用 computed 过滤。Vue 3 中 v-if 优先级高于 v-for，同元素上 v-if 求值时 item 尚未生成，结果为 undefined；即使"能跑"也是每次渲染白跑一遍循环。正确写法：v-for="item in visibleList"，visibleList = computed(() => list.filter(i => i.ok))。
2. const form = reactive({ keyword: '' }); const { keyword } = form; 之后 form.keyword = 'x'，keyword 的值是？
正确答案：还是旧值 ''。解构是把值拷出来，普通变量和响应式系统再无瓜葛。修法：const { keyword } = toRefs(form)，或始终通过 form.keyword 访问。
3. setup 里 const el = ref(null)，模板里 <div ref="el">，在 setup 同步代码中读 el.value 得到？
正确答案：null。setup 执行时机早于 DOM 挂载，模板 ref 只在 onMounted 之后才被赋值。另外如果这个 div 包在 v-if 里，条件翻转时 ref 会先置 null 再重建，读写都要判空。
4. watch 和 watchEffect 的关键区别是？
正确答案：watch 懒执行 + 显式源 + 可拿旧值；watchEffect 立即跑 + 自动追踪。watch 默认只在源变化后触发（除非 immediate: true），适合"变化后发请求"；watchEffect 适合"先跑一遍再说，之后自动重跑"。副作用都不该放 computed。
5. 相比 Vue 2 的 Object.defineProperty，Vue 3 的 Proxy 主要解决了什么？
正确答案：新增属性、删除属性、数组索引/length 全部可侦测。defineProperty 只能劫持已有 key，数组索引写入没 setter 可拦，所以 Vue 2 要重写 7 个变异方法、要 Vue.set。代价是 Proxy 无法 polyfill，Vue 3 放弃 IE11。
6. 全局前置守卫里 return { name: 'login', query: { redirect: to.fullPath } } 与 return false 的区别？
正确答案：前者重定向、后者取消。Vue Router 4 起守卫返回值语义：false = 取消本次导航；返回路由地址（对象/字符串）= 重定向；true/undefined = 放行。登录守卫跳登录页并带 redirect 参数，就是"登录完跳回原页面"的标准实现。
