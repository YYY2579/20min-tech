Shell 脚本面试：手写题、健壮性与那些致命坑

set -euo pipefail 不是万能药，$@ 和 $* 差一个引号就能吃掉你的参数——脚本题的分数，全在边界上。

20:00
读之前先写一行：统计 access.log 里访问量前 10 的 IP。写完再问自己——文件 10G 呢？IP 里有空格呢？中途失败了呢？
开始前

20 秒写完的答案，被三个追问打穿

面试官出题：把 /var/log/app 下超过 7 天的 .log 删掉。候选人 20 秒写完一行：

find /var/log/app -name "*.log" -mtime +7 | xargs rm -f

语法没错，日常也这么用。然后面试官问了三个问题，一个都没答上来：文件名里有空格会怎样？目录不存在呢？删错了能回滚吗？

这就是脚本题的真实评分方式。它不考你记不记得 -mtime 的单位是天，它考的是——你在写之前，有没有想过这段代码会在什么情况下出错。上面那一行有三个洞：文件名带空格会被 xargs 拆成多个参数；目录不存在时 find 报错但管道整体可能仍然「成功」；rm -f 删完没有回滚路径，也没有先打印一遍确认。

更常见的版本是统计题。写完 awk '{print $1}' access.log | sort | uniq -c | sort -rn | head，面试官接着问：日志 10G 的时候这个命令有什么问题？head 提前退出会不会让前面的 sort 收到 SIGPIPE？加了 pipefail 之后整条管道会不会变成失败？这三个问题的答案，决定了你是「会背命令」还是「运维过东西」。

边界具体形态不处理的后果
空没传参数、文件为空、目录里没有匹配项变量为空导致命令作用到错误的路径；通配符不匹配时把字面量 *.log 当成文件名
怪文件名含空格、换行、引号、以 - 开头被拆成多个参数、被当成选项、被 glob 展开成一片
错中途某个命令失败、磁盘满、网络断脚本继续往下跑，产出一个「看起来成功」的半成品
重重复执行、并发执行、cron 重叠数据被切两次、备份互相覆盖、日志被截断两遍
这篇的组织方式：先把骨架和三个必考真坑讲透（set -e 失效、while read 的 subshell、$@ 不加引号），再给 8 道能直接跑的手写题，每题都有完整脚本、逐行解释和「面试官会怎么追问」。脚本是可以背的，边界感背不出来，只能靠一遍遍踩。

面试落点：拿到题先说一句「我先确认三个前提：输入从哪来、失败能不能重试、要不要并发」，然后再动手。这句话本身就是加分项，因为它证明你知道脚本的难点不在语法。

模块 1

面试为什么爱考脚本：它是一道压缩过的系统设计题

一道「写个日志切割脚本」的题，看起来在考 for 循环，实际上在考五件事：你怎么定义输入、怎么处理失败、怎么保证能重跑、怎么让别人看懂、怎么验证它真的干了该干的事。这五件事，和设计一个备份系统没有区别，只是规模小到能在一张纸上写完。

所以评分点非常固定，几乎每个面试官心里都有一张这样的表：

维度及格线加分项
能跑复制下来贴进终端，能产出正确结果不依赖当前目录、不依赖交互输入
边界没参数时给出用法而不是报一堆错空输入、怪字符、缺目录都有明确行为
失败关键命令失败时停下，退出码非 0失败时清理临时文件，日志里有原因
幂等跑两次不会把数据搞坏第二次跑能识别「已经做过」并跳过
可读有函数、有变量名、不写一行 200 字符的管道有 usage、有注释说清「为什么这么写」

写之前先问三个问题，这三个问题决定脚本的形态：

输入从哪来？命令行参数、环境变量、还是读一个文件？参数就要处理缺省；读文件就要处理文件不存在和格式错误。
失败了能不能重试？能重试的（拉取、探测）就加重试和退避；不能重试的（删除、覆盖）就必须先 dry-run，把要做的动作打印出来。
要不要并发？要并发就得考虑输出交错、失败聚合、以及「并发写同一个文件」这种会互相踩的情况。
面试怎么说：「我先确认几个前提：这个脚本是手工跑还是 cron 跑？输入是参数还是配置文件？失败之后是重跑整个脚本，还是只重跑失败的那部分？这三点会影响我要不要加锁、要不要 dry-run。」——问完再写，你的稿子会比别人短，但分数更高。

还有一个现实建议：边写边说。很多人闷头写三分钟，写完再解释，面试官全程只能看到你的头顶。正确的节奏是写一行说一句「这里我用 ${1:?}，没传参数就直接退出，避免后面拿空变量去 rm」——你的思考过程本身就是评分内容。

模块 2

脚本骨架：五行开头，挡住一半的坑

一个能被别人接手、能进 cron、出事能查的脚本，开头是固定的。这不是风格问题，是把最容易忘的几件事，变成不用记的默认值。

#!/usr/bin/env bash
set -euo pipefail
IFS=$'\n\t'

readonly SCRIPT_NAME="${0##*/}"
readonly WORK_DIR="$(cd "$(dirname "$0")" && pwd)"

usage() {
  printf '用法: %s <目录> [-n 保留天数]\n' "$SCRIPT_NAME" >&2
  exit 2
}
log()  { printf '[%s] %s\n' "$(date '+%F %T')" "$*" >&2; }
die()  { log "错误: $*"; exit 1; }

TMP_DIR=""
cleanup() { [[ -n "$TMP_DIR" ]] && rm -rf -- "$TMP_DIR"; }
trap cleanup EXIT
行作用与注意点
#!/usr/bin/env bash用环境里的 bash，而不是写死 /bin/bash。凡是用了 [[ ]]、数组、${var,,} 的脚本，都不能用 sh 跑
set -euo pipefail三件事：-e 命令失败就退出；-u 用未定义变量报错；pipefail 让管道的退出码取最后一个非零值，而不是永远看最后一个命令
IFS=$'\n\t'把默认的「空格 Tab 换行」收窄成「换行 Tab」，让 for 循环不会因为文件名带空格被拆开。代价见下面的警告
${0##*/}从路径里取脚本名，报错时显示 backup.sh 而不是 /opt/x/y/backup.sh
cd "$(dirname "$0")" && pwd取脚本自己所在的绝对路径，避免脚本依赖「你在哪个目录执行它」。这一行是 cron 里最常见的翻车点
usage / log / die三个小函数：用法、带时间戳的日志、失败退出。日志写 >&2，让它进 stderr，不污染正常输出
trap cleanup EXIT无论正常退出、报错退出还是被 Ctrl-C，都执行清理。用单引号是延迟展开，双引号会立刻展开成空字符串
IFS 的副作用，几乎没人第一次就想到：设成 $'\n\t' 之后，while read -r a b 就不再按空格分列了，整行会全塞进 a。所以凡是按空格解析的地方（比如读 df 的输出），必须显式写 while IFS=' ' read -r a b。想省事，就别全局改 IFS，改成在 read 前面局部指定。

还有一个常被问到的点：为什么日志要写 stderr？因为 stdout 可能要拿去做管道输入或者被重定向成结果文件。日志混进 stdout，会让「脚本的输出」变成一锅粥——下游 awk 解析到一行「[2026-01-01] 开始备份」就报错了。

面试怎么说：「我一般固定用 set -euo pipefail 加 trap ... EXIT 做清理，参数用 ${1:?用法} 兜住，日志走 stderr。但我不会完全依赖 set -e，因为它在几种情况下是失效的。」——最后半句会直接引出下一个问题，而那个问题你已经在下面准备好了。

模块 3

引号：$@ 不加引号，参数会被吃掉

先看一个实验。三个写法，看着只差一对引号，行为完全不同：

set -- "a b" c

printf '[%s]\n' "$@"     # [a b]  [c]        两个参数，空格被保住
printf '[%s]\n' $@       # [a]  [b]  [c]     被按空格拆成三个
printf '[%s]\n' "$*"     # [a b c]           全部合成一个

"$@" 是「每个位置参数各算一个词」，$@（不加引号）则先做分词（按 IFS 拆）再做通配符展开（glob），然后才传给命令。"$*" 是把所有参数用 IFS 的第一个字符连起来，当成一个词。

为什么这是「真坑」而不是「细节」？因为它在正常输入下完全看不出问题，只在两种情况下爆炸：参数带空格（文件名、路径、带空格的参数值），以及参数里含 * 或 ?（会被当前目录的文件名替换掉）。看这段：

# 反例：看起来人畜无害
for f in $@; do
  rm -rf "$f"
done

# 如果调用是 ./clean.sh "*"，那么 $@ 不加引号会先做 glob，
# 展开成当前目录的所有文件，于是 rm -rf 删掉了整个目录
# 加引号之后，它就是一个字面量 "*"，rm 只会报「没有这个文件」

正确姿势只有一条：转发参数一律用 "$@"，遍历参数也一律用 "$@"。函数里转发也是同理：

main() {
  parse_args "$@"        # 对：原样转发
  parse_args $@          # 错：参数在这里已经被拆过一遍了
}

变量与数组：加引号是默认动作

除了 "$@"，其他变量也一律加双引号。经典错误是 [ $x = "ok" ]——当 x 为空时，这一行会变成 [ = "ok" ]，直接报 unary operator expected。加了 "$x" 就永远是一个参数，不会消失。

写法含义
${var:-默认值}为空或未定义时用默认值（不改变 var）
${var:=默认值}为空或未定义时赋默认值并返回
${var:?错误信息}为空或未定义时打印错误并退出——读必填参数就用它
${var%后缀} / ${var#前缀}最短匹配删除。取文件名 ${f##*/}、取扩展名 ${f##*.} 都是这个家族
${#arr[@]}数组长度；遍历用 "${arr[@]}"，同样必须加引号
${var,,} / ${var^^}转小写 / 大写，bash 4 起支持。用 sh 跑会直接报错

set -u 是这一切的保险：开了它，用了未定义变量会立刻报错退出，而不是安静地展开成空字符串。安静的空字符串是脚本里最难查的 bug，因为它让 rm -rf "$DIR"/* 变成 rm -rf /*。

一个血亏的写法：rm -rf $DIR/*。当 DIR 为空时，它等于 rm -rf /*。正确写法是 rm -rf -- "${DIR:?}"/ 后面再跟明确的子目录，并且先用 [[ -n "$DIR" && "$DIR" != "/" ]] 挡一道。凡是 rm -rf 加上变量，都要先问一句「它为空会怎样」。

面试落点：「参数转发我用 "$@"，不用 $@ 也不拼字符串。因为不加引号会先分词再 glob，参数带空格就被拆开，参数里含星号会被展开成文件名——这两种在正常测试里都看不出来。」

模块 4

判断与测试：一个 > 就能让你的脚本创建文件

先看一段能跑、但是错的代码：

a=10
b=9
if [ $a > $b ]; then
  echo "a 更大"
fi
# 结果：不打印，且当前目录多了一个叫 9 的空文件

原因是 [ ] 里的 > 是重定向，不是比较。这一行被解析成「执行 [ 10 ]，同时把 stdout 重定向到文件 9」。于是判断永远为真（非空字符串），文件被创建，而你什么都看不到。正确的写法是 -gt，或者用 (( a > b ))。

[ ] 和 [[ ]] 的差别

能力[ ]（POSIX test）[[ ]]（bash 关键字）
变量为空不加引号就语法错误不做分词，空值安全
字符串通配不支持，要配合 case[[ $f == *.log ]] 直接可用
正则不支持[[ $s =~ ^[0-9]+$ ]]
逻辑组合-a / -o（已不推荐）&& / ||，短路求值
大小比较只能用 -gt -lt -ge -le同左，或直接用 (( ))

结论很简单：写 bash 就用 [[ ]]，只有在必须兼容 sh 时才用 [ ]，且每个变量都加引号。面试里被问「两者的区别」，答「[[ ]] 是 bash 的关键字，不做词分割和 glob，所以空变量安全，还支持通配和正则；[ ] 是普通命令，参数会先被 shell 处理」就够完整了。

数值、字符串、文件

类别写法注意
数值(( a > b ))、[ "$a" -gt "$b" ]别用 >；(( )) 的结果为 0 时返回 1，所以 set -e 下 (( 0 )) 会直接退出
字符串[[ -z "$s" ]] 为空、[[ -n "$s" ]] 非空-z 和 -n 是最容易记反的一对，记法：z 是 zero
文件-e 存在、-f 普通文件、-d 目录、-s 非空、-r/-w/-x 权限、-L 软链-e 会跟随软链，软链断了要用 -L 判断
比较新旧f1 -nt f2、f1 -ot f2按 mtime 比较，做增量备份时常用

还有一个 case 的用法值得记，处理「子命令」特别干净，比一长串 if/elif 可读：

case "${1:-}" in
  start|stop|restart) systemctl "$1" myapp ;;
  status)             systemctl is-active myapp ;;
  *)                  usage ;;
esac

面试落点：「数值比较我用 (( ))，字符串和文件用 [[ ]]。因为 [ $a > $b ] 里的 > 会被当成重定向，不报错，但会悄悄创建一个文件——这个坑我在自己机器上踩过。」

模块 5

while read 的 subshell：计数器永远是 0

这是 shell 里最经典的一道题，也是面试官最爱看的一道——因为它没法靠背，只能靠理解进程模型。看代码：

count=0
printf 'a\nb\nc\n' | while read -r line; do
  count=$((count + 1))
done
echo "$count"
# 期望 3，实际输出 0

原因：管道的每一段都在独立的子 shell 里执行。右边的 while 跑在子进程里，它对 count 的修改只发生在子进程的内存里；子进程一退出，这个值就没了。父 shell 里的 count 从头到尾都是 0。

四种修法，各有适用场景：

修法写法适用与代价
进程替换done < <(command)最常用，bash 专有。循环跑在当前 shell，变量能带出来
重定向文件done < file最稳，不启动额外进程。能读文件就别用管道
lastpipeshopt -s lastpipe让管道最后一段在当前 shell 执行。要求 job control 关闭，交互式 shell 里默认不生效，容易时灵时不灵
换工具直接用 awk 统计最省事，也是面试官最想看到的答案之一
# 修法 A：进程替换（推荐）
count=0
while read -r line; do
  count=$((count + 1))
done < <(printf 'a\nb\nc\n')
echo "$count"        # 3

# 修法 B：直接读文件
count=0
while IFS= read -r line; do
  count=$((count + 1))
done < /etc/hosts
echo "$count"

# 修法 C：换 awk，一行搞定（大文件也更快）
awk 'END { print NR }' /etc/hosts

顺带说清三个 read 的细节，这三个都是真实会咬人的：

一定要写 -r：不加 -r，反斜杠会被当成转义符吃掉。处理 Windows 换行、正则、JSON 时，不加 -r 就是灾难。
一定要写 IFS=：默认 read 会吃掉行首行尾的空白。读配置文件、读缩进过的 YAML 片段时，缩进会消失，导致你后面判断全错。
最后一行没有换行符会漏读：read 读到 EOF 但没有换行时返回非零，循环直接结束，最后一行被丢掉。稳妥写法是 while read -r line || [[ -n "$line" ]]。
同一个坑的另一个变体：for f in $(find . -name '*.log') 也是子 shell 加分词的双重问题——先被命令替换拼成一个字符串，再按 IFS 拆开，文件名带空格就散架。遍历文件名只能用 glob（for f in ./*.log）或 find -print0 配 read -d ''。

面试落点：「while read 接管道的话，循环体在子 shell 里，变量改不回父 shell。我一般改成 done < <(...)，或者干脆用 awk 做聚合，因为 awk 处理大文件还快一个量级。」

模块 6

set -e 的六个失效场景，和 trap 的正确写法

很多人以为加了 set -e 就万事大吉。实际上它有六种情况完全不生效，其中两种几乎每个脚本都会遇到。面试官问「set -e 有什么坑」，能答出三个以上的人不多。

#场景说明
1命令出现在 if / while / until 的条件里条件本来就要允许失败，所以整条命令的失败被忽略
2命令是 && / || 链里非最后一个cmd || true 就是靠这个吞掉失败，用多了等于关掉了 -e
3管道里非最后一个命令失败没有 pipefail 时，只看最后一个命令的退出码
4函数在条件上下文里被调用最坑的一个：函数体内所有命令的 -e 全部失效
5local x=$(cmd)local 自己的返回值是 0，掩盖了命令替换的失败
6(( 表达式 )) 结果为 0算术结果为 0 时返回 1，-e 会让脚本退出——反向误伤
# 场景 4：函数在 if 里被调用，函数内部的 set -e 集体失效
set -e
check() {
  false                      # 期望在这里退出
  echo "不该执行到这里"
}
if check; then
  echo ok
fi
echo "脚本继续往下跑"        # 实际会打印：两个 echo 都执行了

# 场景 5：local 掩盖失败
f() {
  local out="$(false)"       # local 返回 0，-e 不触发
  echo "还在继续"
}
f

# 场景 6：反向误伤
set -e
n=0
(( n++ ))                    # 自增前的值是 0 → 返回 1 → 脚本直接退出
echo "永远到不了这里"

所以正确的做法是不把 set -e 当唯一保险。关键命令显式判断，用 || 加 die 收口，比依赖隐式行为可靠得多：

cp -- "$src" "$dst" || die "复制失败: $src"
tar -czf "$out" -C "$dir" . || die "打包失败: $dir"
# 一定要拿到返回值，就别用 local 直接接
out="$(curl -fsS "$url")" || die "请求失败: $url"
# 算术自增要写成不会返回非零的形式
n=$((n + 1))

trap：清理、以及被打断时留下证据

trap 有两个常用信号：EXIT（任何原因退出都触发）和 INT TERM（Ctrl-C 与被 kill）。清理逻辑必须挂在 EXIT 上，因为脚本可能从任何一行退出。

WORK="$(mktemp -d)"
trap 'rm -rf -- "$WORK"' EXIT
trap 'echo "被中断，退出码 130" >&2; exit 130' INT TERM
# 注意单引号：变量在触发时才展开。写成双引号会在 trap 那一刻就展开成空

# 想在出错时打印「是哪一行挂的」，用 ERR 加 set -E
set -E
trap 'echo "第 $LINENO 行失败，命令: $BASH_COMMAND" >&2' ERR
退出码含义
0成功
1通用错误。自己写脚本时，用它表示「跑了但结果不对」
2用法错误（参数缺失、参数非法）。区分它和 1，调用方才能决定要不要重试
126找到了文件但没有执行权限
127命令不存在（常见于 cron 里 PATH 不全）
130被 Ctrl-C 中断（128 + 2）
137被 SIGKILL 杀掉（128 + 9），容器里常见于 OOM
面试怎么说：「set -e 我当成默认保险，不当成唯一保险。它至少在四种情况下不生效：命令在条件里、在 && 链里、函数被条件调用时整个函数体失效、还有 local x=$(cmd) 会掩盖失败。所以我关键步骤都显式 || die，清理统一挂在 trap ... EXIT 上。」
模块 7

文本处理组合：空格、换行、和那个 141

文件名的两大杀手是空格和换行。前者让参数被拆开，后者让「一行一个文件」的假设直接失效。所有「把 find 的输出喂给另一个命令」的写法，都要先回答一个问题：文件名里如果有空格，会怎样？

# 反例：文件名 "my report.log" 会被拆成两个参数
find . -name '*.log' | xargs rm -f

# 正例：用 NUL 分隔，任何字符都不会被误拆
find . -name '*.log' -print0 | xargs -0 rm -f --

# 正例：不用 xargs，直接交给 find 自己执行（更稳）
find . -name '*.log' -exec rm -f -- {} +

# 正例：确实要循环时，用 read -d ''
while IFS= read -r -d '' f; do
  printf '处理 %s\n' "$f"
done < <(find . -name '*.log' -print0)
写法行为什么时候用
-exec cmd {} \;每个文件启动一次进程文件少，或需要单文件独立失败
-exec cmd {} +批量传参，一次启动文件多，追求速度。首选
xargs -0按 NUL 分隔读参数上游能输出 -print0 时
xargs -r输入为空时不执行命令（GNU）防止空输入时命令裸跑。BSD/macOS 不支持，注意环境
xargs -n1 / -P8每次一个参数 / 并发 8 个并发场景，见下一节

管道提前关闭：141 是怎么来的

这条命令在日志很大时会偶发失败：

set -euo pipefail
zcat access.log.gz | awk '{print $1}' | sort | uniq -c | sort -rn | head -n 10
# 偶尔返回 141，脚本直接退出

原因是 head 读够 10 行就退出并关闭读端，上游的 sort 再往管道里写就会收到 SIGPIPE，退出码是 128 + 13 = 141。没开 pipefail 时整条管道只看 head 的状态，返回 0；开了 pipefail，141 就浮上来，set -e 立刻让脚本退出。这不是 bug，是 pipefail 和「提前退出」的正常互动。

三种处理：把限量交给 awk（它读完整个输入但只打印前 N 行，不产生 SIGPIPE）；用 || true 显式接受；或者对这个管道关掉 pipefail（不推荐，容易连别的问题一起吞掉）。

# 推荐：让 awk 负责限量，管道里没人提前退出
awk '{ c[$1]++ } END { for (ip in c) printf "%d\t%s\n", c[ip], ip }' access.log \
  | sort -k1,1nr \
  | awk -v n=10 'NR <= n { printf "%6d  %s\n", $1, $2 }'

面试落点：「find | xargs 我不用，因为文件名带空格会被拆开，改成 -print0 配 xargs -0，或者干脆 -exec {} +。另外开了 pipefail 之后，| head 会通过 SIGPIPE 让上游返回 141，这一条我一般用 awk 限量来避开。」

模块 8

并发：xargs -P、wait、和防止自己踩自己

批量操作 200 台机器，串行跑要一小时，面试官一定问「能不能快点」。并发在 shell 里只有两种实现：xargs -P，或者 & 加 wait。两种都有各自的坑。

xargs -P：最省事，但拿不到细粒度结果

printf '%s\n' host1 host2 host3 \
  | xargs -P 8 -n 1 -I{} ssh -o ConnectTimeout=5 {} uptime

三个必须知道的行为：输出会交错（多个进程同时写 stdout，一行可能被另一行插进来，所以最好让每个任务写自己的文件）；退出码只有 123（任何一个子命令失败，xargs 返回 123，你无法知道是哪个失败，除非把结果写下来）；函数不能直接用（子进程是新 shell，除非 export -f）。

& 加 wait：能聚合结果，但要自己管并发数

pids=()
for h in "${HOSTS[@]}"; do
  while (( $(jobs -rp | wc -l) >= MAX )); do
    sleep 0.2
  done
  check "$h" &
  pids+=("$!")
done

fail=0
for p in "${pids[@]}"; do
  wait "$p" || fail=1
done
exit "$fail"

这段里有三个关键点。$! 是刚启动的后台进程 pid，必须马上存下来，否则后面没法 wait 到具体某一个。wait "$p" 的返回值就是那个任务的退出码，所以可以精确聚合失败。jobs -rp 统计正在跑的后台任务数，用来限制并发。

如果 bash 是 4.3 以上，可以用 wait -n 等「任意一个结束」，比轮询更优雅；5.1 以上还有 wait -n -p var，能把结束的 pid 存进变量。写之前先看一眼版本，面试时说明版本依赖，是加分项。

问题表现解法
输出交错两行日志粘在一起每个任务写独立文件，最后合并
并发写同一文件内容被覆盖、行被截断加 flock，或改成追加并保证单行原子写
cron 重叠上一次没跑完，下一次又起来flock -n 加锁，拿不到锁就退出
把机器打满并发 50 个 tar，IO 直接饱和并发数按资源定，不是越大越好
# cron 防重叠：拿不到锁就安静退出，退出码 0 避免报警刷屏
exec 9>/var/lock/backup.lock
flock -n 9 || { echo "已有实例在跑，退出"; exit 0; }

# 或者写在 crontab 里，一行搞定
# */30 * * * * flock -n /var/lock/backup.lock /opt/scripts/backup.sh
并发最容易忽略的一条：子进程改不了父进程的变量。所有 & 起来的任务，对全局变量的修改都会在结束时消失。要收集结果，只能靠返回值、临时文件、或者管道——这也是为什么并发脚本最后总有一段「汇总」代码。

面试落点：「简单批量我用 xargs -P，但它只能告诉我 123；需要知道哪台失败就用 & 加 wait 逐个收退出码。另外 cron 里一律加 flock -n，否则任务一慢就会叠起来。」

题 1：按天切割日志，并清理过期文件

#!/usr/bin/env bash
set -euo pipefail

LOG_DIR="${1:?用法: $0 <日志目录> [保留天数]}"
KEEP_DAYS="${2:-7}"
STAMP="$(date +%Y%m%d)"

[[ -d "$LOG_DIR" ]] || { echo "不是目录: $LOG_DIR" >&2; exit 2; }

shopt -s nullglob
for f in "$LOG_DIR"/*.log; do
  target="$f.$STAMP"
  if [[ -e "$target" ]]; then
    echo "跳过（今日已切）: $f" >&2
    continue
  fi
  mv -- "$f" "$target"
done

if [[ -f /run/myapp.pid ]]; then
  kill -USR1 "$(cat /run/myapp.pid)" || true
fi

find "$LOG_DIR" -maxdepth 1 -type f -name '*.log.[0-9]*' -mtime +"$KEEP_DAYS" -delete
行说明
${1:?用法: ...}必填参数，缺失时打印用法并以非零码退出，不会带着空变量往下跑
${2:-7}可选参数，默认保留 7 天
[[ -d "$LOG_DIR" ]] || { ...; exit 2; }先挡一道：目录不存在就退出。退出码 2 表示用法/环境错误，便于上层区分
shopt -s nullglob没有匹配文件时，循环体执行零次，而不是把字面量 *.log 当成文件名去 mv
target="$f.$STAMP"切成 app.log.20261021，沿用 logrotate 的命名习惯，后面好清理
[[ -e "$target" ]] && continue幂等：同一天跑第二次时跳过，不会覆盖已有的归档
mv -- "$f" "$target"-- 结束选项解析，防止文件名以 - 开头被当成参数
kill -USR1通知进程重新打开日志文件。只 mv 不重开，进程仍然写旧 inode，磁盘空间不会释放
find ... -mtime +7 -delete清理 N 天前的归档。-mtime +7 是「修改时间早于 7 个 24 小时」

追问：没有 USR1 怎么办？用 copytruncate 的思路——先 cp 再 : > "$f" 清空原文件。代价是复制和清空之间会丢一小段写入，所以能重开就重开。

题 2：批量改名，默认只打印不执行

#!/usr/bin/env bash
set -euo pipefail

DIR="${1:?用法: $0 <目录> [--apply]}"
APPLY=0
[[ "${2:-}" == "--apply" ]] && APPLY=1

[[ -d "$DIR" ]] || { echo "不是目录: $DIR" >&2; exit 2; }

shopt -s nullglob nocaseglob
n=0
for f in "$DIR"/*.jpg; do
  n=$((n + 1))
  base="${f##*/}"
  ext="${base##*.}"
  ext="${ext,,}"
  new="$(printf '%s/img-%03d.%s' "$DIR" "$n" "$ext")"
  if [[ -e "$new" ]]; then
    echo "跳过，目标已存在: $new" >&2
    continue
  fi
  if (( APPLY )); then
    mv -- "$f" "$new"
  else
    printf 'mv %q %q\n' "$f" "$new"
  fi
done
echo "扫描 $n 个文件" >&2
行说明
APPLY=0; [[ ... ]] && APPLY=1默认 dry-run，只有显式传 --apply 才真改。批量改名不 dry-run 是不负责任
nocaseglob让 *.jpg 也能匹配 .JPG，避免两套扩展名写两遍
${f##*/}去掉目录前缀，只留文件名（## 是最长匹配删除）
${base##*.}取最后一个点之后的部分作为扩展名
${ext,,}转小写，bash 4 起支持。用 sh 跑会报错
printf '%s/img-%03d.%s'生成补零的序号，保证排序稳定（img-001 不会排到 img-010 后面）
[[ -e "$new" ]] && continue目标已存在就跳过，不覆盖。这一条能救回一次误操作
printf 'mv %q %q\n'%q 会把带空格的路径转义成可复制的形式，dry-run 的输出可以直接拿去执行

追问：为什么不用 rename？因为 rename 有两个互不兼容的版本（Perl 版和 util-linux 版），语法完全不同，换台机器就跑不了。面试里写可移植的脚本，比写最短的脚本得分高。

题 3：HTTP 健康检查，带重试和退避

#!/usr/bin/env bash
set -euo pipefail

URL="${1:?用法: $0 <url> [重试次数]}"
RETRIES="${2:-3}"
TIMEOUT="${TIMEOUT:-5}"

for ((i = 1; i <= RETRIES; i++)); do
  code="$(curl -sS -o /dev/null -w '%{http_code}' --max-time "$TIMEOUT" "$URL" || true)"
  if [[ "$code" == "200" ]]; then
    echo "OK   $URL (第 $i 次)"
    exit 0
  fi
  echo "第 $i 次失败 http_code=$code" >&2
  if (( i < RETRIES )); then
    sleep $((i * 2))
  fi
done

echo "FAIL $URL 连续 $RETRIES 次未通过" >&2
exit 1
行说明
TIMEOUT="${TIMEOUT:-5}"允许用环境变量覆盖，比再加一个位置参数更灵活
curl -s -o /dev/null -w '%{http_code}'丢弃响应体，只取状态码。-sS 是「静默但保留错误信息」
--max-time硬超时，防止一个卡住的连接把整个检查拖死
|| true必须加：curl 连不上时返回非零，命令替换的赋值会继承这个状态，set -e 会让脚本在第一轮就退出，重试逻辑根本跑不到
[[ "$code" == "200" ]]只认 200。要接受 2xx/3xx 就写 [[ "$code" == 2* || "$code" == 3* ]]
sleep $((i * 2))线性退避（2s、4s）。要更稳就改成指数：$(( 2 ** i ))
exit 1全部失败用 1，和参数错误的 2 区分开，监控才能分清「服务挂了」和「脚本写错了」

追问：如果返回 200 但内容是错的呢？那就不是健康检查，是业务校验。加一个内容断言：curl -fsS "$URL" | grep -q '"status":"ok"'，或者检查关键字段。只查状态码的健康检查，会被一个「200 但数据库连不上」的接口骗过去。

题 4：备份并只保留最近 N 份

#!/usr/bin/env bash
set -euo pipefail

SRC="${1:?用法: $0 <源目录> <备份目录> [保留份数]}"
DST="${2:?用法: $0 <源目录> <备份目录> [保留份数]}"
KEEP="${3:-7}"
STAMP="$(date +%Y%m%d-%H%M%S)"

[[ -d "$SRC" ]] || { echo "源目录不存在: $SRC" >&2; exit 2; }
mkdir -p -- "$DST"

WORK="$(mktemp -d)"
trap 'rm -rf -- "$WORK"' EXIT

tar -czf "$WORK/backup-$STAMP.tar.gz" -C "$SRC" .
mv -f -- "$WORK/backup-$STAMP.tar.gz" "$DST/"

count="$(find "$DST" -maxdepth 1 -name 'backup-*.tar.gz' | wc -l)"
if (( count > KEEP )); then
  find "$DST" -maxdepth 1 -name 'backup-*.tar.gz' -printf '%T@\t%p\n' \
    | sort -rn \
    | tail -n +$((KEEP + 1)) \
    | cut -f2- \
    | while IFS= read -r old; do
        rm -f -- "$old"
      done
fi
行说明
mkdir -p -- "$DST"目录不存在就建，已存在不报错
WORK="$(mktemp -d)"先在临时目录打包，成功后再移入目标目录。否则打包失败会留下一个半截的 tar，看起来像备份成功
trap 'rm -rf -- "$WORK"' EXIT单引号延迟展开，任何方式退出都清理临时目录
tar -czf ... -C "$SRC" .-C 先切换目录再打包，避免归档里出现一长串绝对路径
mv -f同一文件系统内是原子操作，所以不会出现「一半的备份文件」
-printf '%T@\t%p\n'输出「mtime 时间戳 + Tab + 路径」。用 Tab 分隔，是为了后面 cut -f2- 能完整保留带空格的路径
sort -rn 加 tail -n +$((KEEP+1))按时间倒序，跳过最新的 KEEP 个，剩下的就是要删的。用 tail 而不是 head，是为了避开 SIGPIPE
cut -f2-去掉第一列，还原纯路径
while IFS= read -r old逐行删除，路径带空格也不会被拆开

追问：-printf 在 macOS 上没有怎么办？BSD 版 find 没有 -printf。可移植的写法是用 ls -1t 配 tail（但文件名带空格时会出问题），或者干脆用 stat 加排序。面试时说清「这个脚本假定 GNU coreutils」，比假装跨平台可信。

这四道偏「运维实战」，考的是并发、聚合和退出码设计。共同点是：单个失败不应该中断整轮，所以这几道脚本都故意不开 set -e。

题 5：批量探测 host:port 是否可达

#!/usr/bin/env bash
set -uo pipefail

LIST="${1:?用法: $0 <host:port 列表文件> [并发数]}"
JOBS="${2:-8}"

probe() {
  local target="$1" host port
  host="${target%:*}"
  port="${target##*:}"
  if timeout 2 bash -c "exec 3<>/dev/tcp/$host/$port" 2>/dev/null; then
    printf 'UP   %s\n' "$target"
    return 0
  fi
  printf 'DOWN %s\n' "$target"
  return 1
}
export -f probe

grep -v '^[[:space:]]*$' "$LIST" \
  | xargs -P "$JOBS" -n 1 bash -c 'probe "$1"' _
行说明
set -uo pipefail故意不写 -e：探测失败是正常结果，不该让脚本中途退出
local target="$1" host port一行声明多个 local。local 只能在函数内用
${target%:*}去掉最后一个冒号之后的部分，得到 host
${target##*:}去掉最后一个冒号之前的部分，得到 port。用 ## 而不是 #，是为了兼容 IPv6 写法里带多个冒号的情况
timeout 2 bash -c "exec 3<>/dev/tcp/..."用 bash 的 /dev/tcp 伪设备建立连接。三层嵌套：timeout 限时、bash 提供 /dev/tcp、exec 打开文件描述符
export -f probe把函数导出到环境变量，子 bash 才能调用。不加这行，xargs 起的进程会报 command not found
xargs ... bash -c 'probe "$1"' __ 占住 $0，参数才从 $1 开始。-n 1 保证每次只传一个目标

追问：为什么不用 nc -z？因为 nc 的实现有多个版本（netcat-openbsd 和传统版），参数不兼容，而且不少生产机根本没装。/dev/tcp 是 bash 内建的，只要有 bash 就能用——但要注意 sh 里没有这个特性。

题 6：统计访问量 TopN 的 IP

#!/usr/bin/env bash
set -euo pipefail

LOG="${1:?用法: $0 <access.log> [N]}"
N="${2:-10}"

[[ -r "$LOG" ]] || { echo "读不到: $LOG" >&2; exit 2; }

awk '{ c[$1]++ } END { for (ip in c) printf "%d\t%s\n", c[ip], ip }' "$LOG" \
  | sort -k1,1nr \
  | awk -v n="$N" 'NR <= n { printf "%6d  %s\n", $1, $2 }'
行说明
[[ -r "$LOG" ]]可读性检查。不要用 -f 就完事，管道输入、软链、权限不足都要考虑
{ c[$1]++ }用第一列（客户端 IP）做关联数组的键，计数。$1 的具体位置取决于你的 log_format
END { for (ip in c) ... }遍历顺序是哈希序，不可依赖，所以后面必须排序
sort -k1,1nr按第 1 个字段、数值、倒序。写 -k1,1 而不是只写 -k1，否则会把第二列（IP）也带进比较
awk -v n="$N" 'NR <= n'用 awk 限量，不用 head：head 提前退出会让 sort 收到 SIGPIPE，开了 pipefail 就变成 141

追问：日志 10G 怎么办？三点：awk 是流式的，内存只跟「不同 IP 的数量」有关，不跟文件大小有关，所以这道题本身能扛；瓶颈在 sort，它要读完全部输入，可以改成堆或 sort -S 调缓冲区；真要更快就 zcat 加 split 分段并行，再合并。能把「内存跟什么有关」说清楚，比背参数值钱。

题 7：磁盘使用率巡检，用退出码区分告警级别

#!/usr/bin/env bash
set -uo pipefail

WARN="${WARN:-80}"
CRIT="${CRIT:-90}"
rc=0

while read -r fs total used avail pct mount; do
  pct="${pct%\%}"
  [[ "$pct" =~ ^[0-9]+$ ]] || continue
  if (( pct >= CRIT )); then
    printf 'CRIT %3s%%  %s  (%s)\n' "$pct" "$mount" "$fs"
    rc=1
  elif (( pct >= WARN )); then
    printf 'WARN %3s%%  %s  (%s)\n' "$pct" "$mount" "$fs"
    [[ "$rc" -eq 0 ]] && rc=2
  fi
done < <(df -P -x tmpfs -x devtmpfs -x overlay 2>/dev/null | awk 'NR>1')

exit "$rc"
行说明
WARN="${WARN:-80}"阈值从环境变量来，脚本不用改就能在别的机器上调
while read ... done < <(...)用进程替换而不是管道，循环在当前 shell 跑，rc 才能带出来
pct="${pct%\%}"去掉百分号。% 要转义，否则被当成模式的一部分
[[ "$pct" =~ ^[0-9]+$ ]]非数字就跳过，防止 df 的某些行（比如表头）把算术判断搞崩
(( pct >= CRIT ))数值比较用 (( ))，不用 -ge 也不会有 > 重定向的坑
df -P -x tmpfs ...-P 强制单行输出（防止长设备名换行），-x 排除不需要管的伪文件系统
exit "$rc"退出码即结论：0 正常、2 警告、1 严重。监控系统直接读退出码就能分级

追问：df 和 du 对不上怎么办？三种常见原因：文件被删除但进程还握着句柄（lsof +L1 能看到）、inode 满了（df -i）、挂载点被覆盖（新目录挂上去，原来的文件还在下面）。这一问其实是 Linux 排障题，答得好能顺手把话题带到你熟的地方。

题 8：并发在多个主机上执行命令，并汇总失败

#!/usr/bin/env bash
set -uo pipefail

HOSTS="${1:?用法: $0 <hosts.txt> [并发数]}"
MAX="${2:-4}"
fail=0
pids=()

check() {
  local h="$1"
  if ssh -o BatchMode=yes -o ConnectTimeout=5 -o StrictHostKeyChecking=accept-new \
        "$h" true 2>/dev/null; then
    printf 'OK   %s\n' "$h"
    return 0
  fi
  printf 'FAIL %s\n' "$h" >&2
  return 1
}

while read -r h; do
  [[ -z "$h" || "$h" == "#"* ]] && continue
  while (( $(jobs -rp | wc -l) >= MAX )); do
    sleep 0.2
  done
  check "$h" &
  pids+=("$!")
done < "$HOSTS"

for p in "${pids[@]}"; do
  wait "$p" || fail=1
done

exit "$fail"
行说明
pids=()先声明数组，后面存每个后台任务的 pid
BatchMode=yes禁止交互式输入密码。不加这个，脚本会卡在密码提示上永远不返回
ConnectTimeout=5连接超时，防止一台坏机器拖住整个并发池
[[ -z "$h" || "$h" == "#"* ]] && continue跳过空行和注释行，让 hosts 文件可以带说明
jobs -rp | wc -l统计正在运行的后台任务数。-r 只列运行中的，-p 只输出 pid
done < "$HOSTS"重定向而不是管道，否则 while 在子 shell 里，pids 数组出了循环就空了
check "$h" & 加 pids+=("$!")后台启动并立刻记下 pid。$! 只保留最后一个后台进程的 pid，所以必须马上存
wait "$p" || fail=1逐个收尸，任何一个是非零就标记失败。不要只写一个 wait——那拿不到单个任务的返回值

追问：200 台机器、每台 30 秒，怎么在 2 分钟内跑完？并发数至少 50。但真正的瓶颈通常是 ssh 握手和 DNS，所以更实际的做法是用 pssh 之类的批量工具，或者先预热连接复用（ControlMaster）。面试时先算一遍数：「200 台乘 30 秒是 100 分钟，除以 2 分钟需要 50 并发」，把算术说出来，比给一个数字更有说服力。

模块 11

10 个坑：脚本题的失分全在这

这十条不是语法错误，是语法正确但行为错误——所以它们能通过你的自测，然后在生产上炸。

1
set -e 当成万能保险
命令在 if 条件里、在 && 链里、函数被条件调用时整个函数体失效、local x=$(cmd) 掩盖失败、(( 0 )) 反向误伤。关键步骤一律显式 || die。
2
while read 接管道，变量带不出来
管道每段都在子 shell 里，循环体内的赋值出了循环就没了。改成 done < <(cmd) 或 done < file，或者干脆用 awk 聚合。
3
$@ 不加引号
会先按 IFS 分词、再做 glob 展开。参数带空格被拆开，参数里含 * 被替换成文件名。转发和遍历一律用 "$@"。
4
[ $a > $b ] 做数值比较
> 在 [ ] 里是重定向，不报错但会创建一个以数字命名的文件，判断还永远为真。用 -gt 或 (( ))。
5
find | xargs 处理文件名
空格和换行会把一个路径拆成几个参数，rm 删错文件。用 -print0 配 xargs -0，或者直接 -exec {} +。
6
rm -rf $DIR/*
DIR 为空时等于 rm -rf /*。用 ${DIR:?} 挡空值，再加一道「不能是根目录」的判断，变量前后都加引号。
7
管道里 | head 配 pipefail
head 读够就退出，上游收到 SIGPIPE 返回 141，整条管道失败。用 awk 'NR<=n' 限量，或显式接受这个退出码。
8
脚本依赖「在哪个目录执行」
cron 的工作目录和你登录时不一样，相对路径全部失效。开头用 cd "$(dirname "$0")" 定位，或者全程用绝对路径。
9
cron 里不写出完整 PATH
cron 的 PATH 通常只有 /usr/bin:/bin，/usr/local/bin 下的命令直接 127。要么在脚本里显式 export PATH，要么全部写绝对路径。
10
cron 任务不加锁
上一次没跑完，下一次又起来，两份备份互相覆盖、日志被切两次。用 flock -n，拿不到锁就安静退出。
自测

六道题

1. printf 'a\nb\n' | while read -r l; do n=$((n+1)); done; echo $n 输出 0，正确的原因和修法是？
正确答案：子 shell 隔离。管道的每一段都在独立进程里，n 的修改只存在于子进程内存。改成进程替换或输入重定向，循环就跑在当前 shell；用 awk 聚合也可以。
2. 下面哪种情况下 set -e 不会让脚本退出？
正确答案：函数在条件上下文里被调用。此时函数体内所有命令的 -e 全部失效。单独 false 会退出；x="$(false)" 的赋值会继承命令替换的状态，同样会退出。
3. set -- "a b" c 之后，printf '[%s]\n' $@ 和 printf '[%s]\n' "$@" 的区别是？
正确答案：不加引号会被分词。不加引号的 $@ 先按 IFS 拆分再做 glob 展开，"a b" 变成 a 和 b 两个词；加了引号才是「每个位置参数一个词」。参数里含 * 时还会被展开成文件名。
4. [ $a > $b ] 这种写法的问题是什么？
正确答案：重定向。这一行被解析成「执行 [ $a ] 并把输出重定向到文件 $b」，所以判断永远为真、文件被悄悄创建。数值比较要用 -gt 或 (( a > b ))。
5. 文件名叫 my report.log 时，下面哪种写法最安全？
正确答案：用 NUL 分隔。前两种都会把带空格的路径拆成两个参数，第一种还可能连错文件。第三种用 -print0 加 -0，任何字符都不会被误拆；-exec {} + 也可以。
6. 一个每 30 分钟跑一次的备份脚本，怎么防止两次执行重叠？
正确答案：文件锁。flock -n 拿不到锁立即返回非零，可以让脚本安静退出（退出码 0，避免刷告警）。sleep 只是推迟冲突，后台运行会让重叠更严重——上一次还没跑完，下一次已经在跑了。

术语一句话解释
子 shell由当前 shell fork 出来的新进程，变量互不影响。管道每段、$( )、( ) 都会产生

pipefail让管道的退出码取最后一个非零值，而不是永远取最后一个命令的
SIGPIPE / 141下游提前关闭管道时上游收到 SIGPIPE，退出码 141（128 + 13）
IFS内部字段分隔符，决定 read 和分词怎么切。改它会影响所有 read
glob / nullglob通配符展开。开了 nullglob，没有匹配时展开成空而不是保留字面量
