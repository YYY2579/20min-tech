二十分钟掌握命令行工具箱

命令行的威力不在单个命令，而在管道：每个工具只做一件事，组合起来解决从没设计过的问题。这篇讲的是 grep / sed / awk / jq / find / xargs 的组合套路。

开始前

准备三样东西

这篇的每个命令都能直接跑。先在本地造一点数据，比只看不练有效十倍。

# 1. 造一份假日志（2000 行，字段：IP 时间 方法 路径 状态码 字节）
for i in $(seq 1 2000); do
  echo "10.0.$((RANDOM%3)).$((RANDOM%250)) [17/Oct/2026:10:00:00] GET /api/v$((RANDOM%3)) $((RANDOM%2?200:500)) $((RANDOM%9000))"
done > access.log

# 2. 造一份 JSON
printf '[{"id":1,"user":"a","amount":120},{"id":2,"user":"b","amount":80}]' > orders.json

# 3. 确认工具箱齐了（缺哪个装哪个）
for c in awk sed grep sort uniq cut find xargs jq; do
  command -v $c >/dev/null && echo "ok  $c" || echo "MISS $c"
done
工具典型来源缺了怎么办
grep / sed / awk系统自带一般都有。精简镜像（alpine）里可能缺 awk，装 gawk 或 busybox
jq需要单独安装apt install jq / brew install jq
find / xargs系统自带macOS 上是 BSD 版，部分参数（如 -print0）行为有差异
ssiproute2老系统可能只有 netstat（net-tools 包）
lsof / fuser需要单独安装apt install lsof psmisc
Linux 和 macOS 的差异要提前知道：sed -i 在 macOS 上必须带备份后缀（-i ''）；sort、find、xargs 都是 BSD 版，参数略有不同；--line-buffered 是 GNU grep 的扩展。文中的命令以 GNU 工具链为准。
模块 1

管道思维：把一个动作拆成一条流水线

管道的本质是：上一个命令的 stdout 变成下一个命令的 stdin。每个工具只负责一件事，组合起来就是任意复杂的数据处理。

# 需求：找出访问量最高的 10 个 IP
awk '{print $1}' access.log \
  | sort \
  | uniq -c \
  | sort -rn \
  | head -10

# 每一步各自的作用：
# awk 取第 1 列（IP）→ sort 排序（uniq 只处理相邻重复）
# → uniq -c 去重计数 → sort -rn 按次数倒序 → head 取前 10

这条链里没有任何一个命令知道"统计 IP"这件事。它们各自只做：取列、排序、去重计数、再排序、截断。这就是 Unix 哲学：写小的、只做一件事的程序，用管道把它们连起来。

阶段典型工具职责
获取cat / find / curl / ls把数据弄进来
筛选grep / awk / jq select去掉不要的行或字段
变换sed / awk / jq / tr改格式、抽字段、重组结构
聚合sort / uniq / awk / jq计数、分组、求和
输出head / column / tee / jq -r截断、对齐、落盘

三个必须先建立的习惯

先看数据长什么样。head -3 file、jq '. | keys'、awk -F, '{print NF}'。字段数、分隔符、有没有表头，决定了后面所有命令怎么写。
一步步搭，别一次写完。每加一个管道就回车看一次输出。写一条十段管道然后调试，是最慢的方式。
先小样本验证，再跑全量。head -1000 access.log | ... 跑通再换成全文件。避免一条错命令扫了 50GB。
管道的两个边界要记住：① 只有 stdout 会进管道，stderr 默认直接打到终端（要一起走就加 2>&1）；② 管道里每个命令是独立进程，不共享变量，所以状态要靠在流里传递。
模块 2

文本三剑客：各管一段

grep、sed、awk 都能处理文本，但定位完全不同。用错工具，命令会变得又长又难懂。

工具处理单位擅长不擅长
grep行按模式找行：过滤、计数、反选改内容、按列处理
sed行按模式改行：替换、删除、插入跨行统计、按列计算
awk行 + 字段按列处理：抽取、计算、聚合、格式化复杂多行结构（该用 perl/python）

grep：只负责"哪些行"

# 常用组合
grep -i "error" app.log            # 忽略大小写
grep -c "ERROR" app.log            # 只输出匹配行数
grep -v "healthcheck" access.log  # 反选：排除健康检查
grep -n "timeout" app.log         # 带行号
grep -A3 -B1 "Exception" app.log # 带上下文：后 3 行、前 1 行
grep -E "5[0-9]{2} " access.log     # 扩展正则（等价 egrep）
grep -r "TODO" --include="*.go" .  # 递归搜目录，限定后缀
grep -rl "old_api" .              # 只列出文件名（配合批量替换）
grep -o '[0-9]\{1,3\}\.[0-9]\{1,3\}' # 只输出匹配到的片段，不是整行
管道里的 grep 一定要加 --line-buffered。grep 默认按块缓冲（4KB 左右），在 tail -f | grep 这种场景下，你会看到"日志明明打了，屏幕上却没有"。加 --line-buffered 强制逐行输出。

sed：只负责"改成什么"

# 基本替换（只替换每行第一处）
sed 's/old/new/' file
# 全局替换 + 原地修改（-i 会直接改文件）
sed -i 's/old/new/g' file
# macOS 的 -i 必须带一个备份后缀参数，空字符串表示不备份
sed -i '' 's/old/new/g' file

# 按行号操作
sed -n '10,20p' file             # 只打印 10-20 行（-n 关掉默认输出）
sed '5d' file                    # 删除第 5 行
sed '/^$/d' file                 # 删除空行
sed '1i\# header' file          # 第 1 行前插入

# 按内容范围截取（比 grep 更适合"从 A 到 B"）
sed -n '/BEGIN/,/END/p' file

# 引用捕获组：& 表示整个匹配，\1 表示第一个括号
sed -E 's/([0-9]+)ms/\1 milliseconds/' file

awk：按列处理的主力

# 基本结构：pattern { action }
awk '{print $1, $3}' file           # 打印第 1、3 列（默认按空白分割）
awk -F, '{print $2}' data.csv        # 指定逗号分隔
awk -F'\t' '{print NF}' file       # NF = 当前行的字段数

# 内置变量
# NR  已读的总行数      FNR 当前文件的行数
# NF  字段数            $0  整行内容
# FS  输入分隔符        OFS 输出分隔符

# 条件过滤
awk '$9 == 500' access.log        # 第 9 列等于 500 的行
awk '$3 > 1000 {print $1, $3}' file
awk 'NR>1 && NR<=100' file         # 跳过表头，取前 100 行

# 求和与平均
awk '{sum += $3} END {print sum, sum/NR}' file

# 分组统计（awk 版的 group by）
awk '{cnt[$1]++} END {for (k in cnt) print cnt[k], k}' file

# 输出时改分隔符
awk -F, 'BEGIN{OFS="\t"} {print $1, $3}' data.csv
怎么选：只需要"留下哪些行" → grep；只需要"把 A 换成 B" → sed；只要涉及"第几列"或"算点什么" → awk。用 sed 去处理列，会写出没人能维护的正则。
模块 3

jq 实战：JSON 的 awk

jq 是 JSON 的通用处理器。它的定位和 awk 一样：按结构取数据、做变换、做聚合。掌握七八个表达式，就能覆盖日常九成需求。

先记住两个基础

表达式含义输入 → 输出
.原样输出（配合格式化）任意 JSON → 美化后的 JSON
.[]展开数组的每个元素 / 对象的每个值[1,2,3] → 三个独立的 1 2 3
.field取字段{"a":1} → 1
.[0]取数组下标[10,20] → 10
.a.b[0].c链式取值一路取到目标字段
.a // "default"字段不存在或为 null 时取默认值避免输出 null
# 常用开关
jq '.' data.json              # 格式化输出
jq -c '.' data.json            # 紧凑输出（一行，适合再传给别的工具）
jq -r '.name' data.json        # 原始字符串，去掉引号
jq -s '.' a.json b.json         # slurp：把多个文件合成一个数组
jq '.' <(curl -s api/users)   # 直接处理命令输出

八个可直接用的表达式

# ① 遍历数组，取需要的字段（构造新对象）
jq '.[] | {id, name, total: (.items | length)}' orders.json
# 输入 [{"id":1,"name":"A","items":[...]}] → {"id":1,"name":"A","total":3}

# ② 按条件筛选
jq '.[] | select(.status == "error")' logs.json
jq '[.[] | select(.code >= 500)] | length' logs.json   # 统计 5xx 数量

# ③ 提取某一列，求和 / 求平均
jq '[.[].amount] | add' orders.json
jq '[.[].amount] | add / length' orders.json

# ④ 映射：对每个元素做变换
jq 'map(.price * .qty)' items.json
jq 'map({sku, sum: (.price * .qty)})' items.json

# ⑤ 分组统计（group_by 内部会先排序）
jq 'group_by(.user) | map({user: .[0].user, count: length})' logs.json
# → [{"user":"a","count":12},{"user":"b","count":7}]

# ⑥ 排序后取 Top N
jq 'sort_by(-.amount) | .[0:5] | map({id, amount})' orders.json

# ⑦ 输出 TSV（给 awk / sort / Excel 用）
jq -r '.[] | [.id, .user, .amount] | @tsv' orders.json

# ⑧ 对象转数组 / 取所有 key
jq 'to_entries | map(select(.value > 100))' metrics.json
jq 'keys' config.json
jq '[paths(scalars)] | .[0:10]' config.json       # 列出所有叶子路径

两个高频组合

# JSON Lines（每行一个 JSON）逐行处理
jq -r 'select(.level == "ERROR") | "\(.ts) \(.msg)"' app.jsonl

# 用外部变量（避免字符串拼接注入）
jq --arg uid "42" '.[] | select(.user_id == $uid)' orders.json
jq --argjson min 100 '[.[] | select(.amount >= $min)] | length' orders.json

# 合并两个文件（按 key 关联）
jq -s '.[0] as $users | .[1] | map(. + {user: ($users[.user_id] // "unknown")})' \
   users.json orders.json
三个容易踩的点：① .[] 和 .[]? 不同，后者在输入不是数组时静默返回空而不是报错；② select 必须放在管道后面，select(.[] ...) 是错的；③ 处理超大文件时 jq 会全部读进内存，几 GB 的 JSON 要考虑流式方案（--stream 或先用 split 切分）。
模块 4

find 与 xargs：批量操作的正确姿势

这两个命令的组合是"对一批文件做某件事"的标准解法。但它们的参数语义差异很大，用错会静默出错。

find：先把文件找出来

# 按名字 / 类型 / 大小 / 时间
find . -name "*.log"
find . -type f -name "*.tmp"              # f=普通文件 d=目录 l=软链
find . -type f -size +100M                   # 大于 100MB（+ 大于，- 小于）
find . -type f -mtime +7                     # 修改时间在 7 天前
find . -type f -mmin -30                     # 30 分钟内修改过
find . -newer reference.txt                  # 比某个文件新
find . -maxdepth 2 -name "*.yaml"           # 限制搜索深度
find . -type f -not -path "./node_modules/*" # 排除目录

-exec 与 xargs 的取舍

方式特点什么时候用
-exec cmd {} \;每个文件启动一次进程几乎不用，文件多了极慢
-exec cmd {} +批量传参，一次启动处理多个首选。安全，不用管文件名特殊字符
| xargs cmd拼参数，可控制批次大小和并行需要 -P 并行、-n 控制每批数量时
| xargs -0 cmd用 NUL 分隔，能处理空格和换行配合 find -print0，生产环境必须用这个
# ✗ 危险：文件名带空格会被拆成多个参数
find . -name "*.log" | xargs rm
# 文件名 "my report.log" 会变成两个参数：my 和 report.log

# ✓ 正确：NUL 分隔，任何字符都不会被误拆
find . -name "*.log" -print0 | xargs -0 rm -f

# ✓ 或者干脆用 -exec +，不需要 xargs
find . -name "*.log" -exec rm -f {} +

# 先用 echo 验证要删什么（重要习惯）
find . -name "*.log" -print0 | xargs -0 -n1 echo

xargs 的关键参数

# -n 每次传几个参数
xargs -n 1 echo                       # 一行一个
xargs -n 10 cmd                      # 每 10 个一组调用一次

# -I 占位符：把参数放到命令中间（注意：-I 隐含 -L 1，会变慢）
find . -name "*.png" -print0 | xargs -0 -I{} mv {} backup/{}

# -P 并行度（-P 0 表示用满所有 CPU）
find . -name "*.jpg" -print0 | xargs -0 -P 8 -n 1 convert_to_webp

# -r 输入为空时不执行命令（GNU 扩展，避免空跑）
grep -rl "old" . | xargs -r sed -i 's/old/new/g'

# -t 打印实际执行的命令（调试必备）
find . -name "*.tmp" -print0 | xargs -0 -t rm
批量删除前必须做的三件事：① 把 rm 换成 echo 先看清单；② 确认 find 的路径是绝对路径或明确的相对路径（. 在哪个目录下执行很关键）；③ 用 -print0 | xargs -0，不要用裸管道。
模块 5

统计类组合：sort / uniq / cut / paste / comm

这一组工具处理的是"结构化文本"，也就是每行若干列、列之间有固定分隔符的数据。它们的共同前提是：输入必须是有序的（uniq 和 comm 尤其严格）。

核心套路：排序 → 去重计数 → 再排序

# 万能模板：统计每个值出现了多少次
cut -d, -f2 data.csv | sort | uniq -c | sort -rn | head -20
#   取第 2 列        排序      计数        按次数倒序     取前 20
命令作用关键参数
sort排序（默认字典序）-n 数字 / -r 倒序 / -k2 按第2列 / -t, 分隔符 / -u 去重 / -h 人类可读大小
uniq去重（只处理相邻重复）-c 计数 / -d 只显示重复 / -u 只显示不重复
cut按列切分-d' ' 分隔符 / -f1,3 取第1和第3列 / -c1-10 按字符
paste按行横向合并多个文件-d, 用逗号连接 / -s 每个文件合成一行
comm比较两个已排序文件-12 只显示共有 / -23 只显示左边独有
join按公共列做连接（类似 SQL join）-1 2 -2 1 指定两边的连接列
# uniq 的陷阱：不排序直接 uniq，什么都不会去掉
printf 'a\nb\na\n' | uniq       # 输出 a b a（a 不相邻）
printf 'a\nb\na\n' | sort | uniq  # 输出 a b（正确）

# sort 的数字排序：不加 -n 会按字典序
printf '10\n9\n100\n' | sort       # 10 100 9
printf '10\n9\n100\n' | sort -n    # 9 10 100

# 按第 3 列数字倒序，逗号分隔
sort -t, -k3,3 -rn data.csv

# comm：找出两个名单的差集与交集
comm -12 <(sort a.txt) <(sort b.txt)   # 共有
comm -13 <(sort a.txt) <(sort b.txt)   # 只在 a 里
comm -23 <(sort a.txt) <(sort b.txt)   # 只在 b 里

# paste：把两列拼在一起
paste -d, names.txt scores.txt
为什么要 LC_ALL=C：默认的 locale 排序规则会按语言习惯处理大小写和重音，速度也慢。处理纯 ASCII 数据（日志、ID）时加 LC_ALL=C sort，能快 2~5 倍，而且结果可预测。
模块 6

系统类组合：端口、句柄、进程

排障时最常问的三个问题：这个端口被谁占了？这个文件被谁打开了？这个进程在干什么？

查端口

# ss 是现代 Linux 的默认工具（netstat 已过时）
ss -lntp                       # 所有 TCP 监听端口 + 进程
ss -lntp | grep :8080        # 只看 8080
ss -tnp state established      # 已建立的连接（看谁在连你）
ss -s                          # 汇总统计（连接数、TIME_WAIT 数量）

# lsof：更通用，能看端口也能看文件
lsof -i :8080                  # 谁占用了 8080
lsof -i -P -n | grep LISTEN
lsof -p 12345                  # 这个进程打开了哪些文件
lsof +D /var/log               # 谁在用这个目录下的文件

# fuser：最直接，还能顺手杀掉
fuser -n tcp 8080              # 输出占用该端口的 PID
fuser -k -n tcp 8080           # 直接杀掉（危险，先确认）
fuser -vm /data                # 谁在使用这个挂载点

查进程

# 按内存排序看前 10 个进程
ps -eo pid,ppid,rss,pcpu,etime,cmd --sort=-rss | head -11

# 用 awk 过滤：CPU 超过 50% 的进程
ps aux | awk 'NR==1 || $3 > 50 {print $2, $3, $11}'

# 找出某个服务的所有进程（含子进程）
pgrep -af "order-service"
pstree -p -a <pid>

# 看进程的线程数和状态
ps -o pid,nlwp,stat,cmd -p <pid>
# stat: R 运行 S 睡眠 D 不可中断(IO等待) Z 僵尸

# 持续观察（每 2 秒刷新）
pidstat -p <pid> 2
top -H -p <pid>                 # 看线程级 CPU

磁盘与文件

# 找出大目录（-h 人类可读，-d1 只看一层）
du -h -d1 /var | sort -rh | head

# 找出大文件
find /var -type f -size +500M -exec ls -lh {} + 2>/dev/null

# 磁盘 inode 用尽（现象：明明有空间却写不进去）
df -i

# 已删除但被进程占用的文件（df 和 du 对不上的经典原因）
lsof +L1 | head
df 显示满但 du 加起来没那么多？大概率是有进程还持有已删除文件的句柄 —— 文件在目录里看不见，但磁盘块没释放。用 lsof +L1 找出来，重启对应进程即可释放。
模块 7

并行与批处理

单个任务 1 秒、一共 1000 个文件，串行要 17 分钟。并行的收益接近线性 —— 直到撞上 CPU 或 IO 的上限。

xargs -P：最省事的并行

# 8 个并发，每个进程处理 1 个文件
find . -name "*.jpg" -print0 | xargs -0 -n 1 -P 8 ./convert.sh

# 用满所有 CPU（-P 0）
find . -name "*.png" -print0 | xargs -0 -n 1 -P 0 optipng -quiet

# 保留退出码：有任何一个失败就返回非 0
find . -name "*.json" -print0 | xargs -0 -n 1 -P 4 jq empty
echo "exit=$?"
任务类型建议 -P原因
CPU 密集（压缩、转码）= nproc超过核数只是互相抢占
IO 密集（读小文件、发请求）nproc × 2~4线程大部分时间在等
调用远程 API2~8注意对方限流，别把自己封了
写同一个文件 / 数据库1并发写会互相覆盖或死锁

GNU parallel：功能更全

# 基本用法：::: 后面是参数列表
parallel -j 8 convert {} {.}.webp ::: *.png
# {} 完整文件名，{.} 去掉扩展名，{/} 只要文件名，{//} 只要目录

# 带进度条和日志
parallel --bar --joblog /tmp/jobs.log -j 8 ./process.sh ::: input/*.csv

# 从文件读参数（一行一个）
parallel -j 4 -a urls.txt curl -sS -o /dev/null -w "%{http_code} {}\n"

# 组合两个列表（笛卡尔积）
parallel echo {1}-{2} ::: a b c ::: 1 2

# 失败重试 3 次
parallel --retries 3 ./flaky_task.sh ::: 1 2 3 4 5

tmux：并行跑多个长任务

有些任务不适合用 xargs 批量跑（比如要观察每个任务的实时输出）。这时用 tmux 分屏，每个 pane 跑一个。

# 建一个会话，命名
tmux new -s batch

# 在会话里分屏（前缀键默认是 Ctrl+b）
# Ctrl+b %     左右分屏
# Ctrl+b "     上下分屏
# Ctrl+b 方向键 切换 pane
# Ctrl+b d     脱离会话（任务继续跑）
# tmux attach -t batch   重新连上

# 脚本化：给每个 pane 发送命令

模块 8

十个实战组合

下面十条覆盖了日常八成场景。建议直接抄下来改路径，比从零想快得多。

① 日志里访问量最高的 IP

awk '{print $1}' access.log \
  | sort | uniq -c | sort -rn | head -20

# 排除内网 IP 和健康检查
awk '$1 !~ /^10\./ && $7 != "/health"' access.log \
  | awk '{print $1}' | sort | uniq -c | sort -rn | head

② 批量重命名（改扩展名）

# 先干跑，确认输出正确
for f in *.jpeg; do echo mv "$f" "${f%.jpeg}.jpg"; done

# 确认后去掉 echo 执行
for f in *.jpeg; do mv "$f" "${f%.jpeg}.jpg"; done

# 用 rename（Perl 版，支持正则）
rename 's/^IMG_(\d+)/photo-$1/' *.jpg
# 注意：util-linux 的 rename 语法完全不同，先 rename --version 确认

# 给所有文件加前缀
for f in *; do mv "$f" "2026-$f"; done

③ 找出占空间最大的文件

# 目录级别
du -h -d1 . | sort -rh | head -20

# 文件级别，超过 100MB
find . -type f -size +100M -exec ls -lh {} + | awk '{print $5, $9}' | sort -rh

# 排除 .git 和 node_modules
du -h -d2 --exclude=.git --exclude=node_modules . | sort -rh | head

④ 统计各状态码的分布

awk '{print $9}' access.log | sort | uniq -c | sort -rn

# 带百分比
awk '{c[$9]++; t++} END {for (k in c) printf "%s\t%d\t%.2f%%\n", k, c[k], c[k]*100/t}' access.log \
  | sort -k2 -rn

# 只要 5xx 的 URL Top 10
awk '$9 ~ /^5/ {print $7}' access.log | sort | uniq -c | sort -rn | head

⑤ 按时间段筛日志

# 方式一：按行内容范围（适合有明确起止标记）
sed -n '/2026-10-17 10:00:00/,/2026-10-17 10:05:00/p' app.log

# 方式二：awk 做字符串比较（时间格式统一时最可靠）
awk '$1" "$2 >= "2026-10-17 10:00:00" && $1" "$2 <= "2026-10-17 10:05:00"' app.log

# 方式三：ISO8601 格式可以直接字符串比较
awk '$1 >= "2026-10-17T10:00" && $1 < "2026-10-17T10:05"' app.log

# 只要这个时间段内的 ERROR
awk '$1 >= "2026-10-17T10:00" && $1 < "2026-10-17T10:05" && /ERROR/' app.log

⑥ 去重但保留原始顺序

# sort -u 会改变顺序，uniq 要求相邻。用 awk 的关联数组保序
awk '!seen[$0]++' file.txt

# 按某一列去重（保留该列第一次出现的整行）
awk -F, '!seen[$2]++' data.csv

# 统计每个 key 第一次出现在第几行
awk -F, '!seen[$2]++ {print NR, $2}' data.csv

⑦ 合并多个 CSV（只保留一个表头）

# FNR 是当前文件的行号，NR 是总行号
awk 'FNR==1 && NR!=1 {next} {print}' part*.csv > merged.csv

# 跳过每个文件的前两行（注释 + 表头）
awk 'FNR>2' part*.csv > merged.csv

# 加一列来源文件名
awk 'FNR==1 {print "source," $0; next} {print FILENAME "," $0}' part*.csv

⑧ CSV 转 JSON

# 方式一：awk 拼 JSON（适合规整的 CSV，注意转义）
awk -F, 'NR==1 {for(i=1;i<=NF;i++) h[i]=$i; next}
         {printf "{\""; for(i=1;i<=NF;i++) printf "%s\":\"%s\"%s", h[i], $i, (i<NF?",":""); print "}"}' data.csv \
  | jq -s '.' > data.json

# 方式二：jq 直接处理 CSV（自动处理引号内的逗号）
jq -R -s 'split("\n") | map(select(length>0) | split(","))
  | .[0] as $h | .[1:] | map(. as $r | [$h, $r] | transpose | map({(.[0]): .[1]}) | add)' \
  data.csv

⑨ 监控文件变化

# 实时跟踪并高亮关键字（--line-buffered 保证不卡缓冲）
tail -f app.log | grep --line-buffered -E "ERROR|WARN"

# 只看包含某个 trace_id 的行
tail -f app.log | grep --line-buffered "a3f9c2"

# 文件被轮转后自动重新打开（-F 比 -f 更可靠）
tail -F /var/log/app.log

# 监听目录变化（inotify-tools）
inotifywait -m -e modify,create,delete /data/incoming

# 周期性执行并对比输出
watch -n 2 'ss -s | head -5'

⑩ 批量替换（跨文件）

# 第一步：先看会改哪些文件
grep -rl "old_api_host" --include="*.py" .

# 第二步：确认命中行
grep -rn "old_api_host" --include="*.py" .

# 第三步：执行（-r 空输入不报错，-0 处理空格文件名）
grep -rlZ "old_api_host" --include="*.py" . \
  | xargs -0 sed -i 's/old_api_host/new_api_host/g'

# macOS 版 sed 需要备份后缀
grep -rlZ "old" . | xargs -0 sed -i '' 's/old/new/g'

# 第四步：用 git diff 复查
git diff --stat
批量替换的黄金流程：列出 → 确认 → 执行 → 复查。任何一步跳过都可能造成不可逆的破坏。特别是 sed -i 没有回收站，改错了只能靠 git 恢复。
常见坑

十个命令行中的典型错误

1
用裸管道把文件名传给 xargs
文件名带空格或换行就会被拆成多个参数，可能误删文件。必须用 find -print0 | xargs -0。
2
uniq 之前忘了 sort
uniq 只处理相邻重复行。不排序直接 uniq，输出和输入一模一样，而且不会有任何报错。
3
sort 数字列忘了 -n
按字典序排，10 会排在 9 前面，100 会排在 10 前面。数字列一律加 -n，带单位的加 -h。
4
tail -f | grep 看不到输出
grep 按块缓冲，日志太少填不满缓冲区就不输出。加 --line-buffered。
5
在 macOS 上直接抄 Linux 的 sed -i
BSD sed 的 -i 必须带备份后缀，sed -i '' 's/a/b/'。不带参数会报错或产生意外文件。
6
comm 用了没排序的文件
comm 要求两边都严格有序，否则输出完全错误且不报错。写成 comm -12 <(sort a) <(sort b)。
7
用 grep 去解析 JSON
JSON 可以跨行、字段顺序不固定、字符串里可能含 {。用 jq，一行命令就替代十几行正则。
8
批量删除前不 dry-run
把 rm 换成 echo 先看清单，只要多花 5 秒。删错了没有撤销，只能从备份恢复。
9
并行度开太高压垮下游
100 个并发去调同一个 API，会触发限流甚至被封 IP；写同一个数据库会锁等待。先算清楚下游的承受能力。
10
一次性写完十段管道再调试
出错时不知道是哪一段的问题。每加一段就回车看一次输出，是最快的做法。
自测

六道题

1. 统计日志里访问量最高的 IP，正确的顺序是？
正确答案：先 sort 再 uniq -c。uniq 只处理相邻重复，必须先排序。少了这一步，输出和输入一样。
2. 要处理文件名里可能含空格的一批文件，最安全的写法是？
正确答案：-print0 | xargs -0。用 NUL 分隔，任何字符都不会被误拆。裸管道会把 "my report.log" 拆成两个参数。
3. 要从 JSON 数组里筛出 status 为 error 的元素，jq 表达式是？
正确答案：.[] | select(...)。先展开数组，再对每个元素做筛选。select 必须放在管道后面，作用于单个元素。
4. df 显示磁盘已满，但 du 统计的目录加起来远小于总容量。最可能的原因是？
正确答案：已删除但仍被打开的文件。用 lsof +L1 找出来，重启对应进程即可释放。文件在目录里看不见，但磁盘块还占着。
5. 1000 个小文件要做 CPU 密集的处理（比如压缩），-P 应该设多少？
正确答案：约等于核数。CPU 密集任务超过核数只会互相抢占，反而更慢。IO 密集可以设到 2~4 倍核数。
6. 要按列做计算（求和、分组计数），最合适的工具是？
正确答案：awk。grep 只负责选行，sed 只负责改内容，只有 awk 天然按字段处理并支持计算与聚合。用 sed 算列会写出无法维护的正则。
