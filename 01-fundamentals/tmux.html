开始前

装好、开一个、再退出

# 安装
apt install tmux          # Debian / Ubuntu
yum install tmux          # RHEL / CentOS
brew install tmux         # macOS

# 版本：3.x 和 2.x 的部分默认键位、复制模式行为不同
tmux -V

# 开一个命名会话（强烈建议总是命名）
tmux new -s work

# 在 tmux 里：先按 Ctrl-b，松开，再按 d —— 这叫 detach
# 回到普通终端后，看会话还在不在
tmux ls

# 重新接回去
tmux attach -t work

# 彻底结束
tmux kill-session -t work
先建立正确预期：tmux 保护的是"会话"，不是"机器"。
服务器重启、tmux server 被 kill、磁盘写满导致进程被杀 —— 这些情况下会话一样会没。tmux 只保证你的 SSH 连接断了、笔记本合盖了、Wi-Fi 切了的时候，里面跑的进程还活着。
真正要保命的任务，还得配 systemd、supervisor 或任务队列，别把 tmux 当进程守护用。
模块 1

为什么需要终端复用

没有 tmux 的时候，一个 SSH 连接就是一个 shell。连接断了，shell 收到 SIGHUP，里面跑的东西跟着死。这是 Unix 终端几十年的默认行为。

需求没有 tmux有 tmux
跑长任务断网就中断；用 nohup 能活，但输出只能重定向到文件，没法回去交互进程挂在 tmux server 上，断线不影响，重连后原地继续
同时看多个东西开多个 SSH 窗口，或者在本地开多个终端标签一个连接里分屏，还能同步操作多个 pane
远程协作共享屏幕，延迟高、看不清两个人 attach 同一个会话，各自独立的光标，同一份现场
保留上下文重连后 cd 到哪、跑过什么、滚上去的日志，全没了滚动缓冲、命令历史、目录、正在跑的前台进程，全在

和 nohup / screen 的对比

方案能力局限
nohup cmd &忽略 SIGHUP，输出到 nohup.out不能交互，不能分屏，不能多人共享，进程管理靠 ps
screen会话复用、detach/attach功能老、配置语法古怪、分屏弱、活跃度低
tmux会话 + 窗口 + 面板、复制模式、脚本化、多人共享需要学前缀键；默认配置不算好看
systemd service开机自启、崩溃重启、日志进 journal不是给人交互用的，适合真正的后台服务
一句话区分：要"人回来继续操作"用 tmux；要"机器自己保证一直跑"用 systemd。前者是工作台，后者是生产线。很多团队用 tmux 跑生产任务，机器一重启就全没了 —— 这是用错了工具。
模块 2

三层模型：理解 tmux 的钥匙

tmux 的所有命令都围绕三个层级。分不清这三层，就会出现"我明明建了新窗口，怎么找不到了"这类问题。

# 层级关系

tmux server                        # 后台常驻进程，管理所有会话
│
├── session "work"                 # 一次工作现场，可被多个客户端 attach
│   ├── window 0 "editor"          # 一个窗口 = 一屏，占满整个终端
│   │   ├── pane 0  (vim)          # 窗口里切出来的一块
│   │   └── pane 1  (shell)
│   ├── window 1 "server"
│   │   ├── pane 0  (npm run dev)
│   │   └── pane 1  (logs)
│   └── window 2 "db"
│       └── pane 0  (psql)
│
└── session "debug"                # 另一个独立现场，窗口互不相干
    └── window 0 "shell"
层级是什么什么时候用它
session一个独立的工作现场，有自己的窗口集合、当前目录、环境变量按项目 / 按任务分：work、debug、deploy
window占满整个终端的一屏，相当于浏览器的一个标签页按角色分：编辑、跑服务、看日志、数据库
pane窗口内切分出来的一块，每个 pane 是一个独立的伪终端需要并排对照时用：左边改代码、右边看测试输出

三个容易混淆的对应关系

  • session 不是"连接"。一个 session 可以被多个客户端同时 attach（多人协作），一个客户端也可以随时切到别的 session。连接断了，session 还在。
  • window 不是"进程"。一个 window 可以有很多 pane，每个 pane 里跑各自的进程。关掉 pane 里的 shell，pane 就消失；关掉 window，里面所有 pane 一起消失。
  • pane 不是"分屏布局"。布局是 window 的属性（select-layout），pane 是实际存在的终端。换布局不会杀掉 pane，只是重新排列。
命名习惯决定你能不能用好 tmux：
① session 按项目命名：tmux new -s blog、tmux new -s api。别用默认的 0、1、2 —— 一周后你根本不知道哪个是哪个。
② window 按角色命名：edit、run、log、db。用 Ctrl-b , 改名。
③ pane 不用命名，但可以 Ctrl-b q 显示编号，按数字直接跳。
模块 3

前缀键与核心操作

tmux 的所有快捷键都是两段式：先按前缀键 Ctrl-b，松开，再按命令键。这个设计是为了不和终端里的程序抢键位。

# 前缀键的按法（新手最常错的地方）
按住 Ctrl → 按一下 b → 两个键都松开 → 再按命令键

# 例：分屏
Ctrl-b 松开 %      # 左右分（vertical split，两个 pane 并排）
Ctrl-b 松开 "      # 上下分（horizontal split，一上一下）

# 记法：% 像一条竖线，所以是左右分；" 像两条横线，所以是上下分

最常用的十几个键

按键作用备注
Ctrl-b ?列出所有键位忘了就按这个，比查文档快
Ctrl-b ddetach，脱离会话最重要的一键。会话继续在后台跑
Ctrl-b c新建 windowcreate
Ctrl-b ,重命名当前 window养成习惯，别留一堆 "bash"
Ctrl-b n / p下一个 / 上一个 windownext / previous

Ctrl-b w列出所有 window 供选择窗口多了比按 n 快

Ctrl-b "上下分屏新 pane 在下方
Ctrl-b o循环切换 pane两个 pane 时最顺手
Ctrl-b 方向键按方向切 pane比 o 更精准

调整 pane 大小

# 方法一：命令模式（精确，可重复）
Ctrl-b : resize-pane -L 10      # 向左扩 10 列
Ctrl-b : resize-pane -R 10
Ctrl-b : resize-pane -U 5
Ctrl-b : resize-pane -D 5

# 方法二：按住前缀键 + 方向键（3.x 支持连续调整）
Ctrl-b 然后按住 Ctrl + 方向键

# 方法三：直接选布局，让 tmux 帮你算
Ctrl-b Alt-1 ~ Alt-5     # 五种预设布局
Ctrl-b : select-layout tiled

# 平均分配
Ctrl-b : select-layout even-horizontal
Ctrl-b : select-layout even-vertical
前缀键按不出来？三种常见原因：
① 在 tmux 里又开了 tmux（嵌套），Ctrl-b 被内层吃掉了。按两次 Ctrl-b 可以把一次字面量传给内层。
② 终端或 IDE 把 Ctrl-b 绑走了（比如某些终端的"向上翻页"）。换前缀键，见模块 6。
③ 用了 screen 键位模式（set -g prefix C-a 但没 unset 旧的），两个前缀都在，容易混。
模块 4

会话管理：命名是第一步

# 新建并命名
tmux new -s blog
tmux new-session -s blog -c ~/code/blog     # 指定起始目录
tmux new -s blog -n editor                  # 同时命名第一个 window

# 列出所有会话
tmux ls
# blog: 3 windows (created Sat Oct 17 10:12:03 2026) (attached)
# debug: 1 windows (created Sat Oct 17 09:40:11 2026)

# 接回去
tmux attach -t blog
tmux a -t blog                # 简写
tmux attach -d -t blog        # 把其他客户端踢掉，自己独占

# 在 tmux 内部切换会话
Ctrl-b s                     # 列出会话并选择
Ctrl-b : switch-client -t debug

# 重命名
tmux rename-session -t blog blog-old

# 结束
tmux kill-session -t blog
tmux kill-server              # 干掉所有会话（慎用）

# 退出所有客户端但保留会话
Ctrl-b d

为什么命名这么重要

不命名命名
一周后 tmux ls 看到 0: 2 windows、1: 5 windows、2: 1 windows，完全不知道哪个是哪个blog: 3 windows、api: 4 windows，一眼定位
脚本里只能靠编号，重启后编号可能变脚本可以按名字幂等地创建 / 复用
多人协作时说不清"你 attach 到哪个""attach 到 deploy" 一句话说清
# 幂等创建：存在就 attach，不存在就新建（写进 shell 函数最实用）
tmux new -A -s blog
# -A = attach if exists, otherwise create

# 脚本里判断会话是否存在
if tmux has-session -t blog 2>/dev/null; then
  tmux attach -t blog
else
  tmux new -s blog
fi

# 一次性建好一套开发环境（见模块 7 的完整版）
tmux new -d -s dev
tmux new-window -t dev -n edit
tmux new-window -t dev -n run
tmux attach -t dev
推荐的会话划分方式：一个项目一个 session，而不是一个任务一个 session。
比如做后端，就 tmux new -s api，里面开四个 window：edit（编辑器）、run（服务）、log（tail 日志）、db（数据库客户端）。
这样"切项目"就是 Ctrl-b s 换个 session，"切角色"就是 Ctrl-b 2 换个 window。两层各司其职，比开十个 SSH 窗口清楚得多。
模块 5

复制模式与滚屏

tmux 有自己的滚动缓冲，鼠标滚轮在 tmux 里默认不生效（或者被鼠标模式接管）。要看历史输出，必须进复制模式。

# 进入复制模式
Ctrl-b [

# 默认是 emacs 键位；建议改成 vi（见模块 6）
Ctrl-u / Ctrl-d     # 上 / 下翻半屏
Ctrl-b / Ctrl-f     # 上 / 下翻整屏
g / G                # 跳到缓冲区顶部 / 底部（vi 模式）
/pattern             # 向上搜索，n / N 跳转
?pattern             # 向下搜索
q 或 Esc            # 退出复制模式

# 选中并复制（vi 模式）
Space                # 开始选择
移动光标              # 选择范围
Enter                # 复制到 tmux 缓冲区并退出
Ctrl-b ]             # 粘贴缓冲区内容

三种"剪贴板"别搞混

剪贴板谁在用怎么进 / 怎么出
tmux buffertmux 自己维护的缓冲区栈Ctrl-b ] 粘贴；tmux list-buffers 查看
系统剪贴板你的桌面（Windows/macOS/Linux GUI）复制模式下按 Enter 不一定能进系统剪贴板，取决于配置和终端
终端自己的选区终端模拟器（iTerm2、Windows Terminal）按住 Shift 拖动可以绕过 tmux 的鼠标捕获
# 让 tmux 把复制的内容送到系统剪贴板（OSC 52）
# 需要终端支持 OSC 52（iTerm2、Windows Terminal、kitty、alacritty 等较新版本）
set -g set-clipboard on

# 某些终端需要显式开启，或者用 external 模式
set -g set-clipboard external

# 兼容方案：复制后手动导出（Linux 有 xclip 时）
tmux show-buffer | xclip -selection clipboard
# macOS
tmux show-buffer | pbcopy

# 把整个滚动缓冲区存成文件
tmux capture-pane -t 0 -p -S - > ~/pane-history.txt
# -S - 表示从缓冲区最开头开始

# 管理缓冲区
tmux list-buffers
tmux save-buffer ~/clip.txt
tmux delete-buffer -b 0
版本差异会让人怀疑人生：tmux 2.4 之前，复制模式的默认键位和现在不一样；2.4 之后引入了 mode-keys 与更接近 vi 的行为；3.x 又调整了鼠标和 set-clipboard 的处理。
如果你照着某篇老教程按键没反应，先 tmux -V 看版本，再看 Ctrl-b ? 里当前环境的实际绑定 —— 以运行时为准，别以文章为准。

history-limit：滚多少行

# 默认 2000 行，跑一次构建日志就冲没了
set -g history-limit 50000

# 注意：这个值只对"新建的 pane"生效
# 已经开着的 pane 不会追溯变大，需要重开

# 代价：每个 pane 都可能吃几十 MB 内存
# 50 个 pane × 50000 行 × 每行几百字节 ≈ 几百 MB，小机器要克制
模块 6

配置：二十行就够用

配置文件是 ~/.tmux.conf。改完执行 tmux source-file ~/.tmux.conf，或者 Ctrl-b :source-file ~/.tmux.conf。

# ~/.tmux.conf —— 最小可用集

# ===== 前缀键：改成 Ctrl-a（手更顺，且不和 Ctrl-b 翻页冲突）=====
unbind C-b
set -g prefix C-a
bind C-a send-prefix        # 连按两次 Ctrl-a 可以把一次传给内层程序

# ===== 基础行为 =====
set -g mouse on                    # 鼠标选 pane、滚轮滚屏、拖动调大小
set -g base-index 1                # window 从 1 开始编号（和键盘 1 对齐）
setw -g pane-base-index 1          # pane 也从 1 开始
set -g renumber-windows on         # 关掉中间窗口后自动补编号
set -g history-limit 50000         # 滚动缓冲行数
set -g escape-time 10              # 关键：默认 500ms，会让 Vim 的 Esc 明显延迟
set -g focus-events on             # 让 vim 等程序知道 pane 失焦
set -g default-terminal "tmux-256color"
set -ga terminal-overrides ",*256col*:Tc"   # 真彩色

# ===== 分屏：用更顺手的键，并且继承当前目录 =====
bind | split-window -h -c "#{pane_current_path}"
bind - split-window -v -c "#{pane_current_path}"
bind h select-pane -L
bind j select-pane -D
bind k select-pane -U
bind l select-pane -R

# ===== 复制模式用 vi 键位 =====
setw -g mode-keys vi
bind -T copy-mode-vi v send-keys -X begin-selection
bind -T copy-mode-vi y send-keys -X copy-selection-and-cancel

# ===== 状态栏 =====
set -g status-interval 5
set -g status-left "[#S] "
set -g status-right "%H:%M %d-%b"
set -g status-style "bg=#1f2430,fg=#c8d3f5"
set -g pane-border-style "fg=#3b4261"
set -g pane-active-border-style "fg=#82aaff"

# ===== 快捷键：重载配置 =====
bind r source-file ~/.tmux.conf \; display "config reloaded"

# ===== 从 tmux 里直接开新会话时，自动带上当前目录 =====
bind c new-window -c "#{pane_current_path}"
配置项为什么值得改
escape-time 10最容易被忽略的一条。默认 500ms 是为了区分"单独的 Esc"和"转义序列"，代价是 Vim 里按 Esc 后要等半秒才退出插入模式
mouse on能用鼠标选 pane、滚屏、拖边框。但会抢走终端的文本选择，需要按 Shift 绕过
base-index 1键盘上 1 在最左边，编号从 1 开始更符合直觉（默认从 0 开始）
renumber-windows on关掉 2 号窗口后，3 号自动变 2 号，编号永远连续
pane_current_path新分屏 / 新窗口直接落在当前目录，不用重新 cd
default-terminal决定 $TERM，影响颜色和按键。设错会导致颜色发灰、Ctrl-方向键失灵
status-interval状态栏刷新间隔，默认 15 秒。放时钟的话会觉得"时间不动"
配置写错会导致 tmux 起不来。如果改完 ~/.tmux.conf 后 tmux new 直接报错退出，用这个方式跳过配置启动：
tmux -f /dev/null new -s rescue
然后在里面把配置改回去。改配置前先备份，或者用 tmux -f ~/.tmux.conf.new new -s test 先验证。
模块 7

脚本化：一条命令拉起开发环境

tmux 的每个操作都有命令行形式。这意味着你可以把"打开项目要做的五件事"写成一个脚本，一条命令搞定。

# 完整例子：一条命令建好 4 窗口 + 分屏的开发环境
#!/usr/bin/env bash
set -euo pipefail

SESSION=blog
DIR=~/code/blog

# 已存在就直接接回去，避免 duplicate session 报错
if tmux has-session -t "$SESSION" 2>/dev/null; then
  exec tmux attach -t "$SESSION"
fi

# 第一个窗口：编辑器（后台创建，不立即 attach）
tmux new-session -d -s "$SESSION" -n edit -c "$DIR"
tmux send-keys -t "$SESSION:edit" 'vim .' C-m

# 第二个窗口：跑服务，右侧再分一个看日志
tmux new-window -t "$SESSION" -n run -c "$DIR"
tmux send-keys -t "$SESSION:run" 'npm run dev' C-m
tmux split-window -h -t "$SESSION:run" -c "$DIR"
tmux send-keys -t "$SESSION:run.2" 'tail -f logs/app.log' C-m

# 第三个窗口：数据库
tmux new-window -t "$SESSION" -n db -c "$DIR"
tmux send-keys -t "$SESSION:db" 'psql blog_dev' C-m

# 第四个窗口：一个空 shell，留给临时命令
tmux new-window -t "$SESSION" -n shell -c "$DIR"

# 回到第一个窗口，调整布局
tmux select-window -t "$SESSION:edit"
tmux select-layout -t "$SESSION:run" even-horizontal

# 最后 attach
exec tmux attach -t "$SESSION"

脚本里常用的子命令

命令作用
new-session -d -s name后台创建会话（-d 不 attach）
new-window -t s -n name在指定会话里建窗口并命名
split-window -h/-v -t s:w水平 / 垂直分屏
send-keys -t s:w.p 'cmd' C-m向指定 pane 发送按键，C-m 等于回车
select-window / select-pane切到指定窗口 / 面板
select-layout tiled套用预设布局
has-session -t name存在返回 0，不存在返回 1
kill-session -t name结束会话
list-sessions -F "#{session_name}"只输出会话名，方便脚本处理
capture-pane -p -S -把 pane 的全部缓冲输出到 stdout
# 用 tmux 跑一个长任务，并等它结束（CI 场景）
tmux new-session -d -s build -c "$PWD"
tmux send-keys -t build './build.sh; echo $? > /tmp/build.exit' C-m

# 轮询等待
while tmux has-session -t build 2>/dev/null; do
  sleep 5
done
cat /tmp/build.exit

# 更优雅的同步机制：wait-for
tmux new-session -d -s job 'make test; tmux wait-for -S done'
tmux wait-for done        # 阻塞，直到有人 -S 发信号
# 注意：wait-for 的 channel 名是全局的，别和别的脚本撞名

# 把 pane 的所有输出落盘（相当于 script 命令）
tmux pipe-pane -t build -o 'cat >> /tmp/build.log'
send-keys 有两个坑：
① 时序。new-session -d 返回时，shell 可能还没准备好接收输入。稳妥做法是在发送前 sleep 0.3，或者发送一个无害命令探测。
② 引号。send-keys 'echo "hi"' 里的引号会被 shell 先解释一层。复杂命令建议写进脚本文件，然后只发送 ./script.sh。
另外 C-m 是回车，C-c 是中断，Escape 要写成 Escape（不是 Esc）。
模块 8

与 SSH 配合：远程开发的标准工作流

这是 tmux 最值钱的用法。核心只有一句话：先连服务器，再进 tmux，所有工作都在 tmux 里做。顺序反了，保护就失效了。

本地 → 服务器：ssh deploy@10.0.0.5。这一步建立的连接随时可能断，所以不要在这里直接跑长任务。
服务器 → tmux：tmux new -A -s work。存在就接回去，不存在就新建。之后所有命令都在 tmux 的 pane 里执行。
网络断了：SSH 断开，但 tmux server 还在，里面的进程继续跑。你的编辑器、构建、日志 tail 都活着。
重新连上：再 ssh 一次，再 tmux attach -t work。现场原样恢复，连光标位置和滚动历史都在。
主动离开：按 Ctrl-b d detach，而不是 exit 或关窗口。exit 会结束 pane 里的 shell，如果那是最后一个 pane，会话就没了。
# 写进本地 ~/.ssh/config，连上就自动进 tmux
Host dev
  HostName 10.0.0.5
  User deploy
  RequestTTY force
  RemoteCommand tmux new -A -s work
# 这样 ssh dev 一条命令就到工作现场

# 如果不想自动进，但想快速接回
ssh dev -t 'tmux attach -t work || tmux new -s work'

# 多人协作：两个人 attach 同一个会话
# A：tmux new -s pair
# B：ssh 上来后 tmux attach -t pair
# 两人看到同一份输出，各自有独立光标（不是屏幕共享）
# 注意：默认两人都能输入，想只读可以 attach -r
tmux attach -r -t pair        # 只读模式

tmux + SSH + mosh 的分工

层解决什么失效场景
SSH加密传输、身份认证网络切换、IP 变化、长时间空闲被 NAT 清理
moshUDP 传输、漫游、断线自动恢复、本地回显不支持端口转发；需要放行 UDP
tmux会话与终端解耦，进程不随连接死服务器重启、tmux server 被杀
# 最稳的远程开发组合
mosh deploy@10.0.0.5 -- tmux new -A -s work

# 网络抖动由 mosh 扛，进程存活由 tmux 扛
# 即使 mosh 自己断了重连，tmux 里的现场也一直在

# 嵌套 tmux 时，内层的 prefix 要换掉，否则按键被外层吃掉
# 本地 tmux 用 C-a，远程 tmux 用 C-b，或者反过来
# 判断当前是否在 tmux 里：
echo $TMUX
一条命令记住整个工作流：mosh host -- tmux new -A -s work。
它做了四件事：建立抗抖动的连接、恢复或创建会话、把 shell 放进会话、断线后可以原样回来。把它做成 alias 或 SSH config，你就不需要再记别的了。
常见坑

九个真实踩过的坑

1
用 exit 离开，而不是 detach
exit 会结束 pane 里的 shell。如果那是最后一个 pane，window 关闭，session 也跟着结束。离开请按 Ctrl-b d。
2
在 tmux 里再开 tmux，前缀键失灵
内层把 Ctrl-b 吃掉了。按两次 Ctrl-b 可以穿透一层；长期方案是给内外层设不同的 prefix，或者用 $TMUX 判断后禁止嵌套。
3
把 history-limit 调到几十万
每个 pane 都按上限预留缓冲，几十个 pane 就能吃掉几百 MB 到 GB 级内存。50000 行对绝大多数场景足够。
4
没改 escape-time，Vim 里 Esc 有明显延迟
默认 500ms 是为了区分单独 Esc 和转义序列。设成 10ms 后 Vim 手感立刻正常。这是"tmux 让 Vim 变卡"的最常见原因。
5
开了 mouse on 后选不中文字
鼠标事件被 tmux 捕获了。按住 Shift 再拖动，可以绕过 tmux 直接用终端的选区。或者临时 Ctrl-b :set -g mouse off。
6
脚本里直接 tmux new -s name，第二次运行报 duplicate session
用 tmux new -A -s name，或者先 has-session 判断。幂等是脚本的基本要求。
7
复制模式下按 Enter 没进系统剪贴板
Enter 只把内容放进 tmux 的 buffer。要进系统剪贴板，需要 set-clipboard on 且终端支持 OSC 52，或者用 tmux show-buffer | pbcopy/xclip。
8
把 tmux 当进程守护用
服务器重启、OOM Killer、tmux server 被 kill，会话全没。需要开机自启和崩溃重启就用 systemd，tmux 只负责"人回来还能接着操作"。
9
改了 .tmux.conf 没生效
配置只在启动时读。要 tmux source-file ~/.tmux.conf。另外 history-limit 这类选项只对新建 pane 生效，老 pane 不会追溯。
自测

六道题

1. tmux 的三层结构中，一个 window 里可以有多个什么？
正确答案：pane。层级是 server → session → window → pane。一个 session 有多个 window，一个 window 有多个 pane，反过来不成立。
2. 要离开 tmux 但让里面的任务继续跑，应该？
正确答案：Ctrl-b d（detach）。exit 会结束 shell，最后一个 pane 退出会导致会话结束。关终端窗口通常也能保活，但不如 detach 明确。
3. Ctrl-b % 和 Ctrl-b " 分别是什么？
正确答案：左右分、上下分。记法：% 像一条竖线（竖着切），" 像两条横线（横着切）。
4. 为什么建议把 escape-time 从默认的 500 改成 10？
正确答案：第二项。默认值是为了区分"单独按 Esc"和"转义序列的开头"，代价是 Esc 要等超时。终端和程序都支持现代转义序列时，10ms 足够。
5. 脚本里要"存在就接回去，不存在就新建"，最简洁的写法是？
正确答案：tmux new -A -s name。-A 表示 attach if exists，否则创建。直接 new 在会话已存在时会报 duplicate session。
6. 远程开发时，正确的顺序是？
正确答案：第一项。tmux 必须运行在服务器上，才能保证 SSH 断开时进程不被 SIGHUP 杀掉。本地 tmux 里跑 ssh，断线后 ssh 客户端本身还是会退出。
