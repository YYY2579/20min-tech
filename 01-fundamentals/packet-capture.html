十分钟学会抓包与分析

从零到能自己抓到一个包、看懂它、并知道下一步查什么。不用先学网络原理。

10:00
计时开始后，每读完一节就往下滚 —— 目标是在归零前滚到底。
0-1 分钟

抓包到底在抓什么

别被"协议分析"四个字吓到。抓包的本质极其朴素。

抓包 = 让你的网卡把流过的数据"复印"一份给软件看。
分析 = 用过滤器把 99% 的噪声删掉，只留下你关心的那几十个包。

一个包 = 四层套娃

网卡上跑的是以太网帧，里面裹着 IP 包，IP 里裹着 TCP 段，TCP 里才装着真正的应用数据。分析时所有困惑，本质都是"我该看哪一层"。

层典型长度你能读到什么
以太网头14 B源/目的 MAC 地址 —— 只在局域网内有意义，跨网就换了
IP 头20 B源/目的 IP、TTL、协议号 —— 决定这个包去哪儿
TCP 头20 B端口、序号、标志位 SYN ACK FIN RST
应用数据可变HTTP 明文可直接读；HTTPS 是 TLS 密文，只能看长度和时间
最重要的一句话：抓包点决定你能看到什么。在你自己电脑上抓，只能看到你这台机器的流量；想抓别人的，得靠交换机镜像口、路由器分流或代理中间人。
1-3 分钟

选工具：30 秒决策

不要纠结，按你的场景对号入座。90% 的人只需要第一个。

场景工具理由
Windows / Mac 看网页、查故障Wireshark图形界面，过滤器最强，免费。首选，没有之一
Linux 服务器上抓tcpdump服务器通常没有图形界面，命令行抓完存成 pcap 拿回本地用 Wireshark 看
只想看 App / 手机的 HTTPS 内容Charles / Fiddler / mitmproxy代理式抓包，装个证书就能解密 HTTPS，比 Wireshark 省事得多
接口调试、改请求重放Charles / Postman能改包重发，Wireshark 做不到
关键区别：Wireshark 是"旁路监听"，看到的是真实网络；Charles 是"中间人代理"，看到的是解密后的内容但会改变流量路径。排查网络问题用前者，调试业务接口用后者。

Wireshark 装完只做一件事

安装时勾选 Npcap（Windows 抓包驱动），装完重启。打开后你会看到一长串网卡列表 —— 选有流量跳动的那张（通常是"以太网"或"WLAN"）。

3-5 分钟

第一次抓包：五步

选网卡。双击有流量波动的那个。不确定就先都试一遍，抓两秒看看有没有包。
点开始。Wireshark 左上角蓝色鲨鱼鳍图标。包会疯狂滚动 —— 这是正常的，别慌。
制造一个明确的动作。在浏览器打开一个网站，或者 ping baidu.com。有目标才有信号。
点停止。红色方块。现在你有几万个包了，接下来全靠过滤。
过滤。在顶部绿色输入框敲 dns 回车 —— 你会立刻看到刚才的域名解析请求。恭喜，你已经会分析了。
新手最容易踩的坑：一上来就想"看全部包"。永远不要。永远先想清楚"我在找什么"，然后用过滤器把它捞出来。
5-7 分钟

过滤器 = 分析的全部功力

这一节值 80 分。记住 12 条，你就能应付绝大多数场景。点右侧按钮直接复制。

先分清两种过滤器：顶部绿色输入框是显示过滤器（抓完之后筛，最常用）；捕获前设置的叫捕获过滤器（抓的时候就丢，语法是 BPF，如 tcp port 80）。新手只用绿色的就够了。

定位流量

ip.addr == 192.168.1.5只留和这个 IP 有关的包（收发都算）
ip.src == 10.0.0.1 && ip.dst == 8.8.8.8精确指定源和目的
tcp.port == 443指定端口，HTTP 是 80，HTTPS 是 443
tcp.port == 3306抓 MySQL 数据库交互
!ip.addr == 192.168.1.5排除某台机器（叹号 = 非）

按协议筛

http所有 HTTP 请求响应，明文可见
http.request.method == "POST"只看 POST，找表单提交和接口调用
http.host contains "taobao"按域名筛，抓包时最实用的一条
dns域名解析过程，排查"域名解析对不对"
tls.handshakeHTTPS 握手，能看出用的什么证书、什么域名

抓异常（排障核心）

tcp.flags.syn == 1 && tcp.flags.ack == 0所有建连请求 —— 看谁在连谁
tcp.flags.reset == 1RST 包 —— 连接被拒绝或强制断开
tcp.analysis.retransmission重传包 —— 网络丢包的铁证
tcp.analysis.zero_window接收方缓冲区满，发送方被迫停 —— 接收端处理不过来
杀手锏：右键任意一个包 → Follow → TCP Stream。Wireshark 会把整条会话的请求和响应按顺序拼成一整段文本给你看。调接口、看明文密码、还原一次完整交互，全靠它。
7-9 分钟

读懂一个包

Wireshark 界面分三栏：上=包列表，中=分层协议树，下=十六进制原始字节。日常分析只用上两栏。

先认三次握手

任何一条 TCP 连接的开头都是这三行，它不是废话，是你判断"通不通、慢在哪"的第一现场：

# 抓包列表里，同一个 TCP 流的开头
No.1  Client → Server   SYN            Seq=0
No.2  Server → Client   SYN, ACK       Seq=0, Ack=1
No.3  Client → Server   ACK            Seq=1, Ack=1
No.4  Client → Server   HTTP GET /index.html   ← 到这里才是业务数据

看 No.1 和 No.2 之间的时间差，那就是网络往返延迟 RTT。只有 1ms 说明网络很健康；有 300ms 说明链路远或拥塞。

HTTP 请求长什么样

GET /api/user?id=42 HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0 ...
Cookie: session=abc123

──── 分隔线上下就是请求和响应 ────

HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 27

{"name":"张三","vip":true}

看到没？HTTP 是完全明文的。这也是为什么现在全站必须上 HTTPS。

HTTPS 你还能看到什么

能看到
目标 IP 和端口、TLS 握手、SNI 里的域名、证书信息、每个包的大小和时间
看不到
URL 路径、请求参数、Cookie、响应内容 —— 全是密文，除非用代理装证书解密
想解密 HTTPS？两条路：① 用 Charles/mitmproxy 做代理，装根证书；② 在浏览器里导出 SSLKEYLOGFILE 交给 Wireshark。前者简单，后者不改流量路径。
9-10 分钟

四个真实分析场景

学到这里，你缺的只是"看到现象 → 想到过滤什么"的条件反射。

网站打开很慢
过滤 tcp.analysis.retransmission 看重传多不多；再看握手 RTT 和 http.time > 1（响应超过 1 秒的请求）。慢在网络还是在服务器，一目了然。
连不上某个服务
过滤 tcp.flags.reset == 1。有 RST → 对端拒绝（端口没开或防火墙）；只有 SYN 没有 SYN-ACK → 包发出去了但没人回，多半被墙或路由不通。
接口报错但日志没记录
过滤 http.request 或 http.host contains "你的域名"，右键 Follow TCP Stream，直接把原始请求响应导出来对。
怀疑数据外泄
过滤 dns 看有没有可疑域名解析；过滤 !ip.addr == 你的网关 看有没有异常外连；统计 → 会话，按流量排序找大户。
合法红线：只能抓自己有权管理的网络和设备。抓公司网络、他人流量、解密他人 HTTPS 通信，在很多地区涉嫌违法。学习请在自家路由器下练。
自测

三道题，检验你是不是真会了

1. 你想只看访问 baidu.com 的 HTTP 请求，过滤表达式该写什么？
正确答案：http.host contains "baidu"。ip.addr 只认 IP 不认域名；dns 只能看到解析过程，看不到 HTTP 请求本身。
2. 抓包看到大量 tcp.analysis.retransmission，最可能说明什么？
正确答案：网络链路丢包。重传是 TCP 的补救机制，出现大量重传说明包在路上丢了，通常是链路质量或拥塞问题。
3. 抓 HTTPS 流量时，下面哪一项你仍然能看到？
正确答案：TLS 握手和证书里的域名。TLS 握手本身是明文（含 SNI 域名和证书），但握手之后的应用数据全部加密。
附录

随身速查卡

Wireshark 必背快捷键

快捷键作用
Ctrl + E开始 / 停止抓包
Ctrl + K直接开始抓包（跳过选网卡）
Ctrl + /光标跳到过滤器输入框
Ctrl + Alt + Shift + TFollow TCP Stream（我最常用的一个）
Ctrl + F在包内容里搜字符串
Ctrl + G跳到指定编号的包
Ctrl + M给包打标记（先标重点，回头慢慢看）

tcpdump 常用命令

# 抓 100 个包，存成文件拿回本地用 Wireshark 打开
sudo tcpdump -i eth0 -w cap.pcap -c 100

# 实时看某个 IP 的流量，不解析域名（快）
sudo tcpdump -i eth0 -nn host 8.8.8.8

# 只看 80 端口，打印 ASCII 内容
sudo tcpdump -i eth0 -nnA tcp port 80

# 抓 DNS 查询
sudo tcpdump -i eth0 -nn port 53
下一步怎么练：打开 Wireshark，抓 30 秒自己的日常上网流量，然后依次过滤 dns、tcp.flags.syn == 1、tls.handshake，把每条都看懂。三轮之后，你就算真正入门了。
