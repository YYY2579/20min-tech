开始前

先确认你手上是哪个 Vim

很多人第一次在服务器上敲 vim，发现没有语法高亮、不能分屏、方向键乱跳，就断定"Vim 难用"。其实是他装到了精简版。先花十秒确认版本和编译特性。

# 看版本和编译特性（输出很长，重点看括号里的 + 和 -）
vim --version | head -5

# 只关心几个关键特性
vim --version | grep -o '[+-]clipboard\|[+-]python3\|[+-]terminal\|[+-]syntax'

# 官方交互式教程，25 分钟左右，比任何文章都值
vimtutor

# 中文版（如果系统装了中文帮助）
vimtutor zh
你敲的命令实际是什么能力边界
vi通常是 /etc/alternatives/vi 指向的符号链接可能指向 vim.tiny，也可能是完整 vim。行为取决于发行版
vim完整版 VimDebian/Ubuntu 上默认包可能是 vim-tiny，需要 apt install vim
vim.tiny最小构建，约 300KB无语法高亮、无分屏、无插件、无 undo 持久化，只保证 vi 兼容
nvimNeovim，Vim 的 fork内置 LSP、Lua 配置、异步任务。配置文件是 init.lua 或 init.vim
先看清楚再动手：如果 vim --version 里显示 -clipboard，那么 "+y 复制到系统剪贴板是不会生效的，不是你的用法错了。要么装 vim-gtk3（Debian 系带 clipboard 的构建），要么用 :w !pbcopy 这类管道方案。
另外，生产服务器上不要为了好看去装一堆插件。改配置用 sudoedit /etc/nginx/nginx.conf，它会用你的 vimrc 编辑，但以 root 权限写回，不会把文件属主改成 root。
模块 1

为什么 2026 年还值得学

不是因为"用 Vim 显得专业"，而是因为有三个场景它没有替代品。

场景为什么非它不可
只有终端的机器POSIX 标准把 vi 列为必备工具（Single UNIX Specification 的基础工具集里就有它）。任何一台最小化安装的 Linux、任何一个 alpine 容器、任何一台网络设备，几乎一定有 vi。VS Code 不一定能装，vi 一定在。
SSH 链路很差Vim 是按键级交互，一次 ciw 只发三个字节；图形编辑器要同步整个文件、光标位置、滚动条，几十毫秒的延迟就让人抓狂
改配置文件nginx、sshd、systemd unit、crontab、Kubernetes YAML，改三五行的场景，打开 IDE 的时间够改十次
大文件与批量编辑几百 MB 的日志，Vim 关掉语法高亮和 swap 后仍能打开并搜索；图形编辑器往往直接卡死。:%s 一次处理十万行是常规操作

效率的复利来自"可组合"

普通编辑器的快捷键是笛卡尔积的穷举：复制一行、删除到行尾、选中括号内，各有一个独立快捷键，N 个功能就要 N 个键位。Vim 是语法生成：6 个操作符 × 20 个动作 ≈ 120 种组合，而你只需要记住 26 个原子。代价也很实在 —— 前两周效率会下降一半，第四周才开始反超。

一个务实的建议：不要试图"全面转 Vim"。先把 Vim 用在服务器改配置和本地快速改文件这两个场景，IDE 继续用。等肌肉记忆长出来了，你自然会想装 Vim 插件。反过来，一上来就卸载 IDE、装 50 个插件，大概率一周后放弃。
模块 2

核心语法：操作符 + 动作

这是整篇文档唯一必须记住的公式。理解了它，后面的命令都是"填空"。

[次数] 操作符 [次数] 动作/文本对象

# 读法：动词 + 名词
d          # 动词：delete（其实是剪切）
w          # 名词：word，到下一个词首
dw         # 删掉从光标到下一个词首的内容

c          # 动词：change，删除并进入插入模式
i"         # 名词：inside double quotes，引号内部
ci"        # 清空引号里的内容并开始输入 —— 改字符串的神技

y          # 动词：yank，复制
ap         # 名词：a paragraph，整个段落（含后面的空行）
yap        # 复制整段

为什么"操作符 + 动作"比快捷键表强：因为它是生成式的。你新学一个动作（比如 }` 跳到下一个空行），立刻就能用在所有操作符上：d}、c}、y}、>}。而快捷键表里，你得多记四条。这就是为什么 Vim 的命令数量看起来吓人，实际要背的很少。

模块 4

文本对象：Vim 真正的杀手锏

文本对象（text object）是"名词"的另一种形式，语法是 i 或 a 加一个范围符号。i = inner（内部，不含边界），a = around（含边界或周围空白）。

对象选中范围典型用法
iw / aw当前词 / 当前词 + 一个空格ciw 改掉光标所在的词，不用管光标在词中间还是词首
iW / aW空白分隔的"大词"处理 user.name、a-b-c 这种带标点的串
i" / a"双引号内 / 含引号ci" 改字符串值
i' / a'单引号内 / 含引号同上
i` / a`反引号内 / 含反引号Shell 命令替换、Markdown 行内代码
i( / ib圆括号内ci( 改函数参数
i[ / i{ / iB方括号 / 花括号内ci{ 改代码块内容
it / atHTML/XML 标签内 / 含标签cit 改标签之间的文字
ip / ap当前段落 / 段落 + 后置空行dap 删整段，比 d} 干净
is / as当前句子 / 句子 + 空格改英文文档时有用

{"name": "old-value", "age": 30}
# 光标停在 old-value 中间，直接：
ci"new-value<Esc>

# 场景二：改函数调用的参数（会自动处理嵌套）
result = compute(alpha, beta + gamma, delta)
# 光标在 beta 上：
ci(x, y<Esc>

# 场景三：删掉一个完整的 if 块内部

# 场景四：数字前缀 = 向外扩一层
# 在 ((a + b) * c) 里，光标在 a 上
di(        # 删掉 a + b（最内层）
d2i(       # 删掉 (a + b) * c（往外一层）

# 场景五：可视模式选中后调整端点
viw        # 选中当前词
v          # 进入字符可视模式
V          # 行可视模式
Ctrl-v     # 块可视模式（列编辑）

gv         # 重新选中上一次的选区
为什么文本对象比正则更高效：正则描述的是"文本长什么样"，你得先把模式写对；文本对象描述的是"光标在什么结构里"，Vim 用语法分析（而不是字符串匹配）去找边界。
所以 ci" 能正确处理转义引号 "a\"b" 和跨行的字符串，而你自己写的 "[^"]*" 会被转义引号骗过去。结构感知 > 模式匹配，这是文本对象的核心价值。

模块 5

寄存器与宏

寄存器是 Vim 的"剪贴板槽位"。不理解寄存器，你会觉得 dd 删掉的东西"莫名其妙又回来了"；理解了它，你能把删除、复制、宏串成流水线。

常用寄存器

寄存器内容用法
""无名寄存器，最近一次 d/c/y/x 的内容p 默认从这里取
"0最近一次 yank 的内容只被复制写入，不被删除覆盖
"1 - "9删除历史，带换行的删除依次挤入 1→9"1p 粘贴上一次删掉的多行块
"-小删除（行内删除，不含换行）不污染 "1
"a - "z26 个具名寄存器"ayy 复制到 a；"Ayy 追加到 a
"+系统剪贴板"+y 复制到系统，"+p 从系统粘贴
"*X11 主选区（选中即复制）Linux 桌面下常用，SSH 下无效
"_黑洞寄存器，写进去就没了"_dd 删除但不覆盖当前复制内容
"/上一次搜索的模式:s//new/ 直接复用
"%当前文件名插入文件名："<Ctrl-r>%
# 查看所有寄存器的当前内容
:reg

"ayy       # 复制当前行到 a
"ap        # 从 a 粘贴
"Ayy       # 追加到 a（大写 = append）

# 系统剪贴板（需要 +clipboard）
"+yy
"+p
# 或者全局设置，让默认 y/p 直接走系统剪贴板
:set clipboard=unnamedplus

# 黑洞寄存器：删除但不破坏当前复制的内容
"_dd       # 删掉这行，但 "0 里刚复制的代码还在

# 用表达式寄存器做计算

宏：把一段操作录成可回放的脚本

# 语法：q{寄存器} 开始录制，q 结束，@{寄存器} 回放
qa                    # 开始录到 a
  （做你的编辑操作）
q                     # 停止
@a                    # 回放一次
@@                    # 重复上一次回放
10@a                  # 连放 10 次
qA...q                # 大写 = 往已有宏后面追加

# 实战：给每行行尾加分号，并跳到下一行
qa  A;<Esc>  j  q
100@a                # 处理后面 100 行

# 实战：把 a,b,c 改成 c,b,a（三字段互换）
qa  f,d  f,p  j  q

# 对指定范围执行宏（比数次数可靠）
:1,200normal @a
# 对所有匹配行执行
:g/^ERROR/normal @a
宏最容易翻车的三个点：
① 用了会失败的移动。比如宏里写了 j，跑到最后一行就会报错并中断后续所有行的处理。解决：录制时用搜索（/pattern）或文本对象定位，别依赖相对行号。
② 宏里的修改不是一个 undo 块。一条宏如果改了 5 个地方，按一次 u 可能只回滚最后一下。要么接受，要么在录制前用 :set undolevels 配合，或者干脆 u 按到底再重来。
③ 递归宏。让宏自己调用自己可以实现"处理到文件尾"：qq ... @qq，但必须在出错时能停下来，否则会无限循环，只能 Ctrl-c。
模块 6

搜索与替换

搜索

# 基本搜索
/pattern      # 向下搜索，回车后 n 找下一个，N 找上一个
?pattern      # 向上搜索
*             # 向下搜索光标所在的词（自动加 \< \> 词边界）
#             # 向上搜索
g* g#        # 同上，但不加词边界（可以匹配子串）

# 让搜索更好用（写进 vimrc）
:set incsearch      # 边输入边高亮第一个匹配
:set hlsearch       # 高亮所有匹配
:set ignorecase      # 忽略大小写
:set smartcase      # 但只要输入里含大写，就区分大小写
:nohlsearch         # 临时关掉高亮（通常映射成 <leader>h）

# 搜索时的大小写控制（优先级高于全局设置）
/foo\c       # 强制忽略大小写
/foo\C       # 强制区分

替换：:s 的完整语法

:[范围]s/{模式}/{替换}/[标志] [次数]

# 范围
:s/old/new/          # 只当前行，第一个匹配
:s/old/new/g         # 当前行，全部匹配
:%s/old/new/g        # 整个文件（% = 1,$）
:1,20s/old/new/g     # 第 1 到 20 行
:.,$s/old/new/g      # 当前行到文件尾
:'<,'>s/old/new/g    # 可视模式选中的区域（选区后按 : 自动填入）
:?start?,/end/s/a/b/g  # 从上一个 start 到下一个 end

# 标志
g      # global，一行内替换所有匹配。不加只替换第一个
c      # confirm，逐个确认
i      # 忽略大小写
I      # 区分大小写
e      # 没匹配到也不报错（脚本里必加）
&      # 沿用上一次的 flags

# 确认模式的按键
y 替换   n 跳过   a 全部替换   q 退出
l 替换这一个然后退出   <Ctrl-e> 向下滚一行   <Ctrl-y> 向上滚一行
不加 g 只替换每行第一个 —— 这是最高频的误操作。
更危险的是不加 c 就跑 :%s。建议养成习惯：先加 c 看一眼，确认无误再 & 重复执行去掉 c。& 表示"沿用上一次的替换参数"，所以 :%s//new/g 里的空模式会复用上一次的搜索词。

魔法模式：让正则不用满地反斜杠

Vim 的正则有四个"魔法等级"，默认等级里 (、+、?、| 都不特殊，要加反斜杠才生效。这跟 Perl/Python 的直觉完全相反，是新手最大的困惑源。

等级开关规则
very magic\v除了字母数字和下划线，所有字符都特殊。最接近 PCRE 的写法
magic默认. * [ ] ^ $ 特殊，( ) + ? | { } 需要转义
nomagic\m只有 ^ $ 特殊
very nomagic\V只有反斜杠特殊。适合按字面量搜索
# 同一个需求：匹配 foo_123 或 bar_456
/\v(foo|bar)_\d+          # very magic：干净
/\(foo\|bar\)_[0-9]\+      # 默认 magic：一堆反斜杠

# 常用替换实例
# 1. 去掉行尾空白（\s 在 Vim 里可用）
:%s/\s\+$//e

# 2. 交换两个字段（默认 magic 要转义括号）
:%s/\(\w\+\)\s\+\(\w\+\)/\2 \1/g
# 用 very magic 写同一件事
:%s/\v(\w+)\s+(\w+)/\2 \1/g

# 3. 给每行加行号（\= 表示后面是表达式）
:%s/^/\=line('.').'. '/

# 4. 把 a.b.c 改成 a/b/c（点号要转义，否则匹配任意字符）
:%s/\./\//g
# 或者换个分隔符，省掉转义（分隔符可以是任意字符）
:%s#\.#/#g

# 5. 只保留匹配的行，删掉其余
:v/ERROR/d       # v 是 g! 的别名
:g!/ERROR/d

# 6. 对匹配行执行命令
:g/^#/normal >>   # 所有注释行缩进一级
:g/TODO/d          # 删掉所有含 TODO 的行
替换串里的特殊符号：& 代表整个匹配，\1 到 \9 是捕获组，\0 同 &，\r 插入换行，\u 下一个字符转大写，\U 后续全部大写（\e 结束），\l / \L 对应小写。
想插入字面量的 &，写 \&。这个坑在替换 URL 参数时特别常见（?a=1&b=2 里的 & 会被当成"整个匹配"）。
模块 7

缓冲区、窗口、标签页

这三个概念被混用得非常厉害。先把定义分清，很多"Vim 怎么切文件这么别扭"的抱怨就消失了。

概念是什么类比
buffer内存里打开的一个文件。打开就存在，关掉窗口也不消失编辑器里"已打开的文件"
window一个显示 buffer 的视口。同一个 buffer 可以出现在多个 window 里一块玻璃，透过它看文件
tab page一组 window 的布局集合。不是"文件标签"不同的"工作桌面"
# ===== buffer =====
:ls              # 列出所有 buffer，% 是当前，# 是上一个，#h 表示隐藏
:b 3             # 切到 3 号 buffer
:b name<Tab>     # 按文件名补全
:bn :bp         # next / previous
:bd              # 关闭当前 buffer（window 也跟着关）
:bwipeout 3      # 彻底删除 buffer（连撤销历史一起丢）
:bufdo %s/a/b/ge # 对所有 buffer 执行命令

# ===== window =====
:sp              # 水平分屏（split）
:vsp             # 垂直分屏（vertical split）
:sp file.py     # 分屏并打开文件
Ctrl-w s v     # 同上，不用敲冒号
Ctrl-w h j k l # 在窗口间移动
Ctrl-w w       # 循环到下一个窗口
Ctrl-w W       # 循环到上一个
Ctrl-w q       # 关闭当前窗口（buffer 还在）
Ctrl-w o       # 只保留当前窗口（others）
Ctrl-w =       # 所有窗口等宽等高
Ctrl-w _       # 当前窗口最大化高度
Ctrl-w |       # 当前窗口最大化宽度
Ctrl-w r       # 轮换窗口位置
Ctrl-w x       # 与下一个窗口交换
Ctrl-w T       # 把这个窗口挪到新标签页

# ===== tab page =====
:tabnew          # 新标签页
:tabnew file.py
gt gT           # 下一个 / 上一个标签页
:tabc            # 关闭当前标签页
:tabo            # 关闭其他标签页
:tabs            # 列出所有标签页
:tabmove 0       # 把当前标签页移到最前
实践建议（这条能省掉大量困惑）：
① 切文件用 buffer（:b / :bn），不要用 tab。tab 开多了以后 gt 要按很多次，而 buffer 可以直接跳编号。
② 对比两段代码用 window（:vsp + Ctrl-w 移动），这样两边的行号、折叠状态互不影响。
③ tab 只用于"不同的工作布局"：比如 tab1 是"左边代码 + 右边终端"，tab2 是"全屏看日志"。它不是文件切换器。
④ 配 set hidden，这样切换 buffer 时未保存的修改不会被阻止（否则 Vim 会报 E37）。
模块 8

最小可用配置

目标是"十几行解决 80% 的痛点"，不是打造一个 IDE。下面这份可以直接抄。

# ~/.vimrc  —— 按需删减，别全抄
set nocompatible            # 关掉 vi 兼容模式（必须放第一行）
filetype plugin indent on   # 按文件类型加载缩进规则
syntax on                   # 语法高亮

" ===== 显示 =====
set number                  # 绝对行号
set relativenumber          # 相对行号：配合 5j / d3j 极好用
set cursorline              # 高亮当前行
set scrolloff=5             # 光标距上下边缘至少 5 行
set showcmd                 # 右下角显示未完成的命令（比如按下 d 后）
set wildmenu                # 命令行补全菜单
set wildmode=longest:full,full
set laststatus=2            # 总是显示状态栏

" ===== 缩进 =====
set expandtab               # Tab 转空格
set tabstop=4               # 一个 Tab 显示为 4 列
set shiftwidth=4            # >> << 的缩进宽度
set softtabstop=4           # 插入模式下 Backspace 一次删 4 个空格
set autoindent              # 新行沿用上一行缩进
set smartindent             # C 类语言按 { } 自动缩进

" ===== 搜索 =====
set incsearch               # 边输边跳
set hlsearch                # 高亮全部匹配
set ignorecase
set smartcase               # 有大写就区分

" ===== 行为 =====
set hidden                  # 允许切走未保存的 buffer
set backspace=indent,eol,start  # Backspace 能删过插入起点
set mouse=a                 # 开鼠标（SSH 里谨慎，可能和终端选中冲突）
set clipboard=unnamedplus   # y/p 直连系统剪贴板（需 +clipboard）
set undofile                # 关掉文件再打开也能撤销
set undodir=~/.vim/undo     # 需要先 mkdir -p ~/.vim/undo
set noswapfile              # 不生成 .swp（单机编辑可以关，多人共享目录别关）
set ttimeoutlen=10          # Esc 后不用等 1 秒才响应

" ===== 键位 =====
let mapleader = " "         # 空格当 leader（默认是反斜杠，太远）
nnoremap <leader>w :w<CR>
nnoremap <leader>h :nohlsearch<CR>
nnoremap <leader>v :vsplit $MYVIMRC<CR>
nnoremap <leader>s :source $MYVIMRC<CR>
inoremap jk <Esc>          # 插入模式里 jk 退出（比 Esc 顺手，但会影响输入 "jk"）
三个容易抄错的点：
① set nocompatible 必须在最前面，否则后面的配置可能被 vi 兼容模式覆盖。
② undodir 指向的目录不会自动创建，先 mkdir -p ~/.vim/undo，否则保存时静默失败。
③ inoremap jk <Esc> 会让所有输入 "jk" 的地方变成退出插入模式。写英文文档时很烦，可以换成 ;; 或干脆不用。

插件管理器怎么选

方案适用代价
不装只改服务器配置零成本。真的，先这样用一个月
vim-plugVim / Neovim 都能用，单文件需要手动 :PlugInstall；生态成熟、文档多
lazy.nvimNeovim 专用，Lua 配置默认懒加载，启动快；但要写 Lua
原生 packagesVim 8+ 内置~/.vim/pack/*/start/ 放进去即可，零插件管理器。推荐给"只想装两三个插件"的人
Vim 9 的 packadd按需加载:packadd name，配合 pack/ 目录
# 测启动耗时，找出是哪个插件拖慢的
vim --startuptime /tmp/vim-start.log
# 打开日志，按第二列（微秒）排序看
sort -k2 -n -r /tmp/vim-start.log | head -20
别一上来装几十个插件。这不是审美问题，是工程问题：
① 启动时间：空 Vim 启动约 5~20ms，装 50 个插件后很容易到 300ms 以上。每次开文件都付这个税。
② 键位冲突：两个插件抢同一个 <leader> 前缀，排查起来极其痛苦，因为 :map 的输出有几百行。
③ 版本腐化：插件作者停更、依赖旧版 Vim、和你的 Vim 版本不兼容。半年后你打开配置，一堆报错但不知道删哪个。
④ 服务器上根本没有：你练出来的手感，在客户的机器上不存在。核心操作必须只用原生 Vim。
建议路径：先用原生 Vim 一个月 → 只装 3 个（surround、commentary、一个文件树或模糊查找）→ 稳定后再考虑第四个。
常见坑

九个真实踩过的坑

1
以为 dd 是"删除"，其实是"剪切"
被删的内容进了无名寄存器和 "1。之后按 p 会把它粘出来，看起来像"删掉的东西又活了"。要真删就用 "_dd。
2
:%s/old/new/g 忘了加 c
一次改掉全文件，而且 u 只能整体回滚。养成 :%s/old/new/gc 的习惯，确认完再 :%s//new/g 复用。
3
默认 magic 下写 (foo|bar) 匹配不到
Vim 默认要求 \(foo\|bar\)。要么全部改写，要么在模式前加 \v。跨工具复制正则时最容易踩这个。
4
在插入模式里用方向键移动
方向键会打断撤销块，一次输入变成十几个 undo 单元，u 按起来没完。而且手离开主键区，Vim 的优势就没了。
5
看到 .swp 文件就删掉
它可能是另一个终端正在编辑同一文件。删了会让对方的保存冲突。正确做法：看提示里的 PID，确认进程不存在后再删，或者用 :recover。
6
服务器是 vim.tiny，却照着教程配插件
vim.tiny 没有 +eval、没有 +clipboard、不能分屏。先 apt install vim（Debian 系）或 yum install vim-enhanced（RHEL 系）。
7
用 sudo vim 改配置，把家目录的权限搞乱
sudo 会用 root 的 HOME，生成 root 属主的 ~/.viminfo 之类文件。改系统配置用 sudoedit 或 sudo -e，它会保留你的编辑器配置但以 root 写回。
8
宏里用了 j，跑到文件尾就中断
一旦某次 j 失败，宏立刻停止，后面的行全没处理，而你可能没发现。用搜索定位（/pattern）或文本对象，别依赖相对移动。
9
分屏后忘了 Ctrl-w 是前缀
直接按 h 只会在当前窗口里左移光标。Ctrl-w 要先按住 Ctrl 再按 w，松开后再按方向键。也可以映射成 nnoremap <C-h> <C-w>h。
自测

六道题

1. 光标停在 name = "hello world" 的 hello 中间，要一次改掉整个字符串内容，最合适的命令是？
正确答案：ci"。c 是 change（删除并进入插入模式），i" 是"双引号内部"这个文本对象。它不依赖光标在词首，也能正确处理转义引号。
2. d2w 和 2dw 的区别是？
正确答案：两者等价。Vim 的语法是 [count] operator [count] motion，两个位置的次数会相乘。习惯上写 2dw，读起来更自然。
3. 想删除一行，但不覆盖刚才用 yy 复制的内容，应该用？
正确答案："_dd。"_ 是黑洞寄存器，写进去的内容直接丢弃。dd 会把整行塞进无名寄存器和 "1，导致你原来的复制内容被覆盖。
4. :%s/foo/bar/gc 里的 c 表示？
正确答案：confirm。每处匹配都会停下来问：y 替换、n 跳过、a 全部替换、q 退出、l 替换这一个后退出。c 是防止全局误替换的最后一道保险。
5. 关于 buffer、window、tab 的关系，哪个说法对？
正确答案：buffer / window / tab 是三层。同一个 buffer 可以开在两个 window 里，一个 tab 可以包含多个 window。所以切文件应该用 :b，而不是开一堆 tab。
6. 在 Vim 的默认 magic 模式下，匹配 "foo 或 bar" 应该写？
正确答案：\(foo\|bar\)（默认 magic 要转义）。第三项 \v 也对，但它切换到了 very magic 模式。第二项在 Vim 里会把括号和竖线当成字面量，匹配不到。

模式 modalVim 分普通、插入、可视、命令行等模式，同一个键在不同模式下含义不同
普通模式默认模式，按键即命令。按 Esc 从任何模式回到这里
