## 学习笔记与已读（重点功能）

站点右下角有一个**全局悬浮按钮 ✎**，所有页面通用：

- **标记已读**：文档页信息行有「标记已读」按钮，点击即记录；主页每篇文档会显示 **✓ 已读** 徽章，首页统计栏实时显示 **已读 x/246** 总进度。
- **按模块记笔记**：每个模块标题旁有 ✎ 按钮，点击直接给该模块写笔记；每篇还有独立的「⭐ 本篇总结」。
- **一个章节可写多条**：点「＋ 写新笔记」在本章节连续记录，每条独立保存、独立删除，保存后全部计入「全部笔记」；列表里点任意一条可原地编辑（不会新增条目），编辑器里也有「＋ 新建」不用先回列表。
- **Markdown 支持**：标题、粗体/斜体、行内代码、代码块、表格（支持对齐）、有序/无序列表、**待办复选框** `- [ ]`、引用、分割线、链接。编辑/预览一键切换，输入即自动保存（700ms 防抖，切页/关面板前强制落盘）。
- **全部笔记**：抽屉里可浏览所有笔记，按时间倒序，显示所在文档与章节，支持搜索、点击跳转对应章节、单条删除。
- **数据存哪**：默认存在**本机浏览器 localStorage**（`20min.read.v1` / `20min.notes.v1`），换设备看不见。
- **多设备同步（可选）**：设置页填入 GitHub Token（建议用细粒度 Token、仅勾选 Gist 权限，可随时吊销），即可同步到一个**私有 Gist**。合并规则是按记录更新时间取胜者，多设备改不会互相覆盖。也支持导出/导入 JSON 备份。
- **快捷键**：`Ctrl/⌘+Enter` 开关笔记面板，`Ctrl/⌘+S` 保存，`Esc` 关闭。

> 安全说明：Token 只保存在你自己浏览器的 localStorage，除 api.github.com 外不发送到任何地方；笔记内容渲染前全部转义，`javascript:` 类链接会被拦截。

## 设计原则

1. **只讲能用的** —— 不追求体系完整，只回答"这件事我该怎么做、为什么这么做、什么时候会翻车"
2. **术语就地解释** —— 每个术语首次出现就加括注，不让你来回翻
3. **每篇都能独立读** —— 不依赖外部图片、不依赖前后文，正文自包含
4. **文档自己质检** —— 附带 `qa-check.py`，可对全站做 6 轮自动检查（结构完整性、样式一致性、转义规范、灌水检测、占位符残留、组件用量）

## 技术说明

- 纯静态 HTML + 内联 CSS/JS，**零依赖**
- GitHub Pages 分支部署，不使用 GitHub Actions（省额度，也省配置）
- 路径全 ASCII，避免中文 URL 的百分号编码问题
- 每份文档约 40~70 KB
- 笔记系统为单文件运行时模块 `notes-core.js`（ES5、无依赖），246 篇文档只注入一行 `<script>`，UI 全部运行时生成——改功能只动一个文件

## 维护工作流

```bash
# 1. 改完任何文档后，重新生成首页与目录页（自动提取标题/简介）
python build-index.py          # index.html + catalog.html

# 2. 改了 notes-core.js？先把 inject-notes.py 里的 VERSION +1（缓存穿透，必须！），
#    再把笔记模块注入所有页面（幂等；版本号不变则跳过，变了则自动替换旧版本）
python inject-notes.py

# 3. 全站质检
python qa-check.py .

# 4. 测试（可选但推荐）
node test-notes-core.js          # Markdown 渲染器/合并逻辑单测
node test-e2e-notes.js           # 端到端全链路（需 playwright）

# 5. 推送上线（任选其一）
git push                                    # 常规方式
python api-push.py <user>/<repo> <token> .   # 或走 GitHub API 增量推送
```

> ⚠️ **为什么必须升 VERSION**：GitHub Pages 对 `.js` 返回 `Cache-Control: max-age=600`。
> 只改 `notes-core.js` 内容而不换 URL，用户 10 分钟内普通刷新拿到的还是旧文件——
> 曾因这个出现"修复已推送但用户侧仍复现"的事故。`?v=N` 一变，浏览器必然重新下载。
