开始前

三个心智模型，先立起来

后面所有内容都建立在三个事实上。不接受这三个事实，看什么都会觉得"玄"。

模型眼里只有一串整数。文本先被切成 token 再映射成词表 id。你看到的"字"和模型看到的"id"不是一回事 —— 一个汉字可能是一个 token 也可能是两个，取决于词表（详见 tokenization 篇）。
训练 = 调整参数；推理 = 用参数做前向计算。推理时模型不会产生任何新知识，它只是在"根据上文分布给出下一个 token 的概率"。
整个模型只有三类数学运算：矩阵乘法（占 99% 算力）、softmax（注意力）、逐元素运算（激活、LayerNorm）。没有魔法。

30 行代码看懂自注意力

# 不依赖任何框架，把注意力的全过程写出来
import numpy as np

T, d = 4, 8                        # 序列长 4，隐藏维 8
X = np.random.randn(T, d)          # 4 个 token 的输入向量 (T,d)

Wq = np.random.randn(d, d) / d**0.5   # 四个投影矩阵，各 d×d
Wk = np.random.randn(d, d) / d**0.5
Wv = np.random.randn(d, d) / d**0.5
Q, K, V = X @ Wq, X @ Wk, X @ Wv      # 线性投影得到 Q/K/V

scores = Q @ K.T / d**0.5             # (T,T)：每个词对每个词的关注分，除以 sqrt(d) 防过大
causal = np.triu(np.ones((T, T), dtype=bool), k=1)   # 上三角（不含对角线）
scores = np.where(causal, -np.inf, scores)           # 因果 mask：不许看未来

def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)   # 减最大值防 exp 溢出
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)

attn = softmax(scores, axis=-1)       # 每行变成一个概率分布（只对可见位置）
out  = attn @ V                       # 按概率加权求和 V → (T,d)
# out[i] 就是第 i 个 token "吸收了上下文之后" 的新表示。堆 32~80 层，就是 GPT。
本篇不要求你会训模型，但要求你会三件事：① 会用 12·d² 估算每层参数量；② 会用 2·L·d_kv·bytes 估算 KV Cache；③ 知道 temperature/top-p 各自改变分布的哪一部分。这三件事是选型、排障、算成本的日常。
模块 1

Transformer 架构核心

2017 年论文《Attention Is All You Need》的原始结构是 Encoder-Decoder；今天的大语言模型只用其中一半 —— Decoder，而且是带因果 mask 的版本。整栋楼只有一种砖重复 32~80 次。

一栋楼的全貌

部件作用关键事实
Token Embeddingtoken id → d 维向量一张 vocab×d 的大表，查表即可，是模型里最大的单张参数表之一
位置编码注入顺序信息现代方案是 RoPE（模块 6），不再加在 embedding 上，而是加在每层注意力的 Q/K 上
N × Decoder Layer每层 = 掩码多头注意力 + FFN，各带残差和 LayerNorm参数量和计算量的绝对主体，占比 95% 以上
最终 LayerNorm稳定数值分布现代模型用 Pre-LN：先归一化再进子层，训练更稳
LM Headd 维 → vocab 维 logits一张 d×vocab 矩阵；与输入 embedding 共享权重 能省一份参数（GPT-3 不共享，Llama/Qwen 共享）

自注意力：Q、K、V 分别在干什么

用一句话概括：Q 是"我要找什么"，K 是"我有什么标签"，V 是"我实际提供的内容"。每个 token 用自己的 Q 去和所有（可见的）K 打分，softmax 成权重后加权求和 V。三个矩阵都是可学习的 d×d 线性变换，没有别的。

# 单头注意力的完整公式（d_k = 单头维度）
Attention(Q,K,V) = softmax( Q·Kᵀ / sqrt(d_k) + mask ) · V

# 为什么除以 sqrt(d_k)：q·k 点积的方差随 d_k 线性增长，
# d_k=128 时打分方差约 128，直接 softmax 会饱和成 one-hot、梯度趋 0。
# 除以 sqrt(d_k) 把方差压回 1 附近。
因果 mask（causal mask）是生成式模型的灵魂。训练时把"未来位置"的打分置为 -inf，模型永远只能看左边。这带来两个后果：① 训练可以并行 —— 一次前向算出所有位置的下一词预测，这也是 teacher forcing 能成立的原因；② 推理时生成第 t 个 token，天然只能依赖前 t-1 个 —— 这就是自回归，也是 KV Cache 存在的原因（模块 4）。

多头注意力：不是"更多参数"，是"更多子空间"

把 d 维切成 h 份，每份 d/h 维，独立做一次注意力，最后拼接再投影。关键认知：QKVO 四个矩阵总参数不变的前提下，头数只改变"分组方式"。8 头 d=512 和 16 头 d=512 参数量完全一样（各头 d_k=64 或 32，投影矩阵都是 512×512）。

配置典型模型头在学什么
MHA 标准多头GPT-2/3、Llama-2 全系每头独立 Q/K/V，不同头捕捉不同关系（指代、相邻、语义相似）
MQA 多查询单值部分推理优化模型所有头共享同一份 K/V，KV Cache 缩小 h 倍，质量有损
GQA 分组查询Llama-3、Qwen2、Mistral折中：K/V 分 g 组共享。Llama-3-8B：64 个 Q 头分 8 组 KV 头，KV Cache 降到 1/8，质量接近 MHA

FFN：每层里真正"存知识"的地方

注意力负责"搬信息"，FFN 负责"存知识"。业界流行一个粗糙但有依据的观感：FFN 占了每层约 2/3 的参数，更像模型的"记忆体"；注意力更像"寻址电路"。标准 FFN 是 d→4d→d 的两层 MLP，中间用 GELU/SiLU 激活。

# 标准 FFN（GPT-2 风格）：两个矩阵，参数 8·d²
h = gelu(x @ W1 + b1)      # (T,d) → (T,4d)  升维
y = h @ W2 + b2            # (T,4d) → (T,d)  降维

# SwiGLU（Llama/Qwen/Mistral 主流）：三个矩阵 + 门控
h = silu(x @ W_gate) * (x @ W_up)   # 门控分支逐元素相乘
y = h @ W_down
# 三个矩阵但不让参数量膨胀：隐藏维取 2.7d~3.5d 而非 4d（Llama-3-8B：4096→14336）

残差连接 + LayerNorm：深网络不崩的原因

  • 残差连接（x + Sublayer(x)）：梯度可以"抄近路"回传到浅层，没有它 30 层以上训不动。
  • LayerNorm：对每个 token 的 d 维向量做归一化，稳住每层的输入尺度。现代模型用 Pre-LN（先 LN 再进子层）；原始 Transformer 是 Post-LN，训练稳定性差， warmup 要很久。
  • RMSNorm（Llama/Qwen）：LayerNorm 去掉均值中心化，只除以均方根，省一次均值计算，效果几乎无损，已是开源默认。

参数量速算：12·d² 法则

# 每层参数（MHA + 标准 4d FFN）
# 注意力：Q/K/V/O 四个 d×d 方阵 = 4·d²
# FFN：d×4d + 4d×d = 8·d²；每层合计 ≈ 12·d²

def count_params(d_model, n_layers, vocab, inter=4*d_model, tied=False):
    attn = 4 * d_model * d_model          # QKVO
    ffn  = 2 * d_model * inter            # 标准 FFN 两个矩阵
    body = (attn + ffn) * n_layers
    emb  = vocab * d_model                # 输入 embedding
    head = 0 if tied else vocab * d_model   # 输出头，共享则为 0
    return body + emb + head

# 验证：一个 7B 的常见配置（d=4096, 32 层, 词表 32000，SwiGLU inter=11008）
# 用 2 个 FFN 矩阵的公式会低估，实际 = 3×4096×11008×32 + 4×4096²×32 + 2×32000×4096 ≈ 6.7B ✓

模块 2

预训练目标：只有"下一词预测"

把 GPT、Claude、Llama、Qwen 全部划掉，它们共享同一个训练目标：给定前 t-1 个 token，预测第 t 个 token 的概率分布。就这一句话，没有别的。

损失函数：交叉熵

# 一次前向，模型输出词表 V 上的概率分布 p，真实下一个词是 y
loss = -log(p[y])          # 交叉熵（负对数似然）

# 训练时对整个语料的每个位置求平均：
L = (1/N) · Σ_t -log p(x_t | x_<t)

# 直观理解：词表 32000，随机猜的 loss ≈ ln(32000) ≈ 10.37
# 训练良好的 7B 在英文文本上 loss ≈ 1.5~2.0 nats/token
# 困惑度 ppl = exp(loss) ≈ e^1.8 ≈ 6 —— 平均每个位置在 ~6 个候选间犹豫
指标含义与用法
困惑度 PPL= exp(loss)。"等效候选数"。只能在同 tokenizer、同测试集之间比较，跨模型比 PPL 意义有限；与下游任务表现相关但不等价
teacher forcing训练时永远喂"标准答案前缀"而非模型自己的生成，所有位置可并行计算；推理没有这个待遇，只能一个个生成

训练数据与三阶段流水线

阶段目标数据与规模
预训练下一词预测，学世界知识和语言规律万亿 token 级网页/代码/书籍，去重、清洗、过滤。Llama-3：15T tokens
SFT 监督微调学会"对话格式"、遵循指令万~十万条人工撰写示范。目标不变，还是下一词预测，只是数据变成对话
对齐 RLHF/DPO更符合人类偏好：有用、无害、不啰嗦人类对多个回答排序，训奖励模型；再用 RL（PPO）或直接偏好优化（DPO）微调
必须建立的认知：模型没有"理解模块"，也没有"检索模块"。对话能力是 SFT 把"续写"特化成了"问答"；幻觉来自训练目标本身 —— 它优化的是"像不像人话"，不是"真不真"。问模型不知道的事实，它依然会给出概率上最像答案的 token 序列。这就是为什么 RAG、工具调用（见 context-engineering 篇）不是可选项而是必需品。
模块 3

规模定律（Scaling Law）与涌现

2020 年两篇论文给出了大模型时代的"工程公式"：模型效果随参数量、数据量、算力的增长呈平滑的幂律提升。这件事的革命性在于 —— 在小规模上测几个点，就能外推大模型的表现，不用真的把大模型训出来。

两代 Scaling Law

论文核心结论工程含义
Kaplan 2020
（OpenAI）		L(N) ∝ N^(-0.076)，N=参数量；数据量、步数的指数更小早期结论：堆参数优先。后来被证明低估了数据的重要性
Chinchilla 2022
（DeepMind）		L(N,D) = E + A/N^α + B/D^β（α≈0.34, β≈0.28）。算力最优 ≈ 每参数 20 个训练 token70B×1.4T 的 Chinchilla 打败 280B×300B 的 Gopher，且推理更便宜

模型参数量训练 tokenstokens/参数备注

为什么现在都超配数据？因为 Chinchilla 优化的是"训练算力成本"，而开源模型的真实约束是推理成本：模型要部署到别人的显卡上，每 token 推理都要花钱。训练是一次性的，推理是永远的。所以业界选择"往死里喂数据，把模型压小"—— 这是 2023 年之后所有开源基座模型的共同选择（Llama-3、Qwen2.5、Mistral 都是 tokens/参数 > 1000）。

涌现能力（Emergent Abilities）

指某些能力在小模型上"几乎为零"，超过某个规模后突然出现：少样本学习（in-context learning）、思维链（chain-of-thought）、指令遵循。Wei et al. 2022 年系统描述了这一现象，典型阈值在 10²²~10²³ 训练 FLOPs 量级（大致对应 10B 参数以上的成熟训练）。

争议要知道：Schaeffer et al. 2023 提出涌现可能是评价指标的伪影 —— 用"精确匹配"这类 0/1 指标衡量曲线很陡，换成连续指标（如编辑距离）曲线就平滑了。稳妥口径：能力提升大部分是连续的，但确实存在少数"开关式"能力；不要在小模型上验证有效的 prompt 策略，假设大模型一定更好。
模块 4

推理：自回归、KV Cache 与显存账

推理分两个阶段，瓶颈完全不同。搞混这两个阶段的瓶颈，是线上性能问题里最常见的误判。

Prefill / Decode 两阶段

阶段做什么瓶颈
Prefill把整段 prompt 一次前向，算出所有位置的 K/V 并缓存，产出第一个 token算力 bound。1k prompt ≈ 14 TFLOPs（7B），可以吃满 GPU
Decode每生成 1 个 token，就要把全部权重从显存搬到计算单元一遍显存带宽 bound。每 token 读一遍 14GB 权重（7B fp16）

KV Cache：为什么必须存在

没有缓存时，生成第 t 个 token 要对前 t-1 个 token 全部重算 K/V，第 1000 个 token 要重算 1000 次，O(n²) 浪费。缓存后每个位置的 K/V 只算一次，之后直接查表。代价是显存：KV Cache 大小 = 上下文长度 × 每 token 的 KV 字节数。

# KV Cache 显存公式（fp16 = 2 字节）
# 每 token KV 字节 = 2(K和V) × 层数L × KV头数 × 每头维度 × 2字节

def kv_cache_gb(n_layers, n_kv_heads, head_dim, ctx, batch=1, dtype_bytes=2):
    per_token = 2 * n_layers * n_kv_heads * head_dim * dtype_bytes
    return round(per_token * ctx * batch / 1024**3, 2)

# Llama-2-7B（MHA：32 KV 头 × 128 维）
kv_cache_gb(32, 32, 128, 4096)     # → 2.0 GB
kv_cache_gb(32, 32, 128, 32768)    # → 16 GB（32k 上下文！）
# Llama-3-8B（GQA：8 KV 头，缩到 1/4）
kv_cache_gb(32, 8, 128, 8192)      # → 1.0 GB
# Llama-2-70B（80 层，GQA 8 头）
kv_cache_gb(80, 8, 128, 4096)      # → 1.25 GB

把 batch 乘回去，才是线上爆炸的原因：32 并发 × 8k 上下文 × Llama-3-8B（GQA）= 1.0 GB × 32 = 32 GB 纯 KV Cache，还没算 16 GB 模型权重和激活值，一台 A100-80G 直接吃光。这就是 vLLM 的 PagedAttention 要像操作系统管内存页一样管理 KV Cache 的原因：按需分页、序列间共享（system prompt 前缀复用能省一大截）、满了抢占换出。

Decode 速度上限：先算带宽，再谈算力

# 单条生成的理论上限 = 显存带宽 ÷ 模型体积
# A100 80GB：HBM2e 带宽 2039 GB/s；7B fp16 权重 14 GB
# 上限 ≈ 2039 / 14 ≈ 145 token/s（单流）

# 推论 1：batch 是吞吐的解药 —— 权重读一次服务整个 batch，
#   聚合吞吐可达单流几十倍，但单条速度不会超过带宽上限。
# 推论 2：INT4（7B → 3.9GB）把单流上限拉到 ≈520 tok/s，量化最大的收益场景。
排障口诀：首 token 慢（TTFT 300ms~3s+）→ prompt 长度和 prefill，算力问题；出词慢（TPOT 7~15ms）→ batch 和 KV Cache 占用，带宽/显存问题；吞吐低 → continuous batching 开没开、序列长度是否参差。
模块 5

采样策略：temperature、top-p 与 beam search

模型每步输出的是词表上的概率分布，采样策略就是"怎么从这个分布里挑一个词"。它只改变分布的用法，不改变分布本身，更不改变模型的知识。

五个主流旋钮

参数作用机制推荐值与坑
temperaturelogits 先除以 T 再 softmax。T<1 分布变尖锐（更确定），T>1 变平坦（更随机）0 = 贪心；创意任务 0.8~1.0；T→0 与贪心等价，多数 API 直接禁 T=0 而用 greedy 参数
top-k只在概率最高的 k 个候选里采样，其余置零k=1 就是贪心；常用 20~50。k 是绝对数，不随分布形状自适应
top-p
（nucleus）		按概率降序累加，累计超过 p 的候选集合为采样池常用 0.9~0.95。分布尖锐时池子小，平坦时池子大 —— 自适应，通常比 top-k 更优
重复惩罚对出现过的 token 的 logit 打折（presence/frequency penalty）或除以其概率幂治复读机；调太大会伤害正常的名词重复和代码生成

完整采样实现（可直接跑）

import numpy as np

def sample(logits, temperature=1.0, top_k=0, top_p=1.0):
    logits = np.asarray(logits, dtype=np.float64)
    if temperature <= 0:                 # 贪心：直接取最大
        return int(logits.argmax())
    logits = logits / temperature            # ① 温度重塑分布
    logits = logits - logits.max()           # 数值稳定
    p = np.exp(logits); p /= p.sum()

    if top_k > 0:                        # ② top-k 截断
        idx = np.argpartition(p, -top_k)[-top_k:]
        mask = np.zeros_like(p, dtype=bool); mask[idx] = True
        p = np.where(mask, p, 0.0); p /= p.sum()

    if top_p < 1.0:                       # ③ top-p 截断（按累计概率）
        order = np.argsort(p)[::-1]
        cum = np.cumsum(p[order])
        cutoff = np.searchsorted(cum, top_p) + 1     # 累计首次超过 p 的位置
        keep = order[:cutoff]
        mask = np.zeros_like(p, dtype=bool); mask[keep] = True
        p = np.where(mask, p, 0.0); p /= p.sum()

    return int(np.random.choice(len(p), p=p))

# 常见组合：代码/抽取 → greedy；对话/写作 → T=0.7, top_p=0.9；
# 头脑风暴 → T=1.0, top_k=40。注意顺序：先温度、后截断

Beam Search 为什么在开放生成里被淘汰

原因说明
似然 ≠ 质量beam 优化整句概率，但概率最高的句子往往最平庸、最安全（"这是一个很好的问题……"）。人类评价与似然的相关性在长文本上很弱
退化问题Holtzman et al. 2019 实测：beam 生成多样性显著低于采样，长文本更易复读
算力与显存 k 倍k=4 就要维护 4 条序列的 KV Cache 和 4 倍 decode 计算，服务成本翻几倍
稳妥口径：beam search 在封闭式任务（机器翻译、语音识别、有唯一正确答案的序列标注）仍有价值；在开放式生成（对话、写作、代码）已被采样全面取代，主流推理框架默认路径都是单序列 + temperature 采样。
两个高频误解：① temperature=0 不等于完全确定 —— 浮点非结合性、batch 内序列相互影响、硬件差异都可能导致同一输入两次输出不同；要求可复现的抽取任务要用 API 的 seed 参数（支持与否以厂商文档为准）。② temperature 不改变"懂多少"，只改变"敢不敢说"。
模块 6

位置编码与上下文长度外推

注意力本身对顺序是盲的（打乱输入序列，注意力结果只随内容变）—— 必须显式注入位置信息。这一块是 2023~2024 年长上下文竞赛的主战场，也是线上"上下文明明没超窗口却答非所问"的根因高发区。

方案代表模型机制与局限
正弦位置编码原始 Transformer用不同频率的 sin/cos 函数编码绝对位置。理论可外推，实测外推效果差
可学习绝对位置BERT、GPT-2一张 (max_len × d) 的可学习矩阵。训练时没见过的位置没有定义，无法外推

RoPE 为什么不能"直接喂更长"

RoPE 把第 m 个位置的 Q/K 向量按角度 m·θ_i 旋转，θ_i = base^(-2i/d)。模型训练时只见过 m ∈ [0, 4096) 的旋转角度，推理时直接喂 m = 8192 相当于进入训练中从未出现的角度区间，注意力分数分布崩坏，输出质量断崖式下跌（外推崩坏）。

扩展方法做法代价
位置插值 PI把所有位置除以缩放因子 s（4096→8192 就 ÷2），把新位置压回训练区间简单免训练；但高频信息被压缩，短文本性能略降
NTK-aware不均匀缩放：低频少缩、高频多缩，修正插值的频率失真免训练，比 PI 平滑
YaRN按频率分段处理 + 注意力温度修正，少量数据继续训练效果最好的无痛扩展方案之一，长上下文微调模型广泛采用
长上下文继续训练用长文本数据继续预训练/微调，直接教会模型用新长度效果最好，成本最高（Llama-3 的 128k 版即此路线）
选型红线：模型卡上的 128k 是在特定评测和配置下达成的。① 别把 8k 模型硬喂 100k，输出会以"复读、跑题、突然结束"的形式崩掉；② 同一模型的不同量化版、不同推理框架（llama.cpp 的 rope scaling、vLLM 的 --rope-scaling）行为有差异，长上下文必须用生产实际部署的那一套验证；③ "能跑"和"跑得准"是两回事，长文档问答要做自己的检索测试。

影响三：词表决定"什么对模型是难的"

模块 8

量化基础：INT8/INT4/GPTQ/AWQ

量化 = 用更少的比特表示权重，换来显存和带宽下降。对 decode 阶段（带宽 bound）来说，量化几乎等于直接提速。这是把 7B 模型塞进消费级显卡、把 70B 塞进单卡 A100 的唯一实用路径。

位宽与内存账

格式位宽7B 模型内存质量与用途

四大技术路线

技术核心思路适用场景
GPTQ逐层量化，用 Hessian 逆矩阵补偿量化误差，权重分组（group size 常为 128）配 scale/zeroGPU 推理。4bit 下速度接近理论值，生态成熟（AutoGPTQ、Marlin kernel）
AWQ激活感知：约 1% 的"显著权重"通道对输出影响巨大，保护它们、按激活幅度缩放GPU 推理。3~4bit 下常比 GPTQ 略稳

KV Cache 量化把缓存里的 K/V 也压成 FP8/INT8长上下文 + 高并发。显存收益巨大，注意力分数精度略降
# 量化收益的算术（7B 模型，A100 2039 GB/s 带宽）
# FP16：14GB ÷ 2039GB/s ≈ 145 tok/s（单流上限）
# INT4：3.9GB ÷ 2039GB/s ≈ 520 tok/s —— 理论上限 ×3.6，一台卡能扛的并发也按 3~4 倍放大
量化选型的稳妥口径：① INT8 几乎无损，能上就上；② INT4 是显存受限时的正确选择，但必须用你自己的任务集评测 —— 社区量化版本质量参差，同规格不同作者差 5~10 个点不稀奇；③ 数学推理、代码、罕见语言是量化重灾区；④ 各框架实现演进很快，以 vLLM/TensorRT-LLM/llama.cpp 当前文档为准；⑤ 别在 INT4 权重上再叠"长上下文 + 高 batch"却不做 KV Cache 量化 —— 显存会先死在 Cache 上。
收尾

十个认知坑

1
把注意力的 O(n²d) 理解错
n 是序列长度，d 是隐藏维度 —— 不是词表大小。词表只出现在 embedding 查表和最后一步 softmax 里。注意力的 n² 是长上下文成本爆炸的根源。
2
参数量估算漏掉 embedding 和输出头
只算 12·d²·L 会系统性偏小。词表 128k、d=4096 时，输入 + 输出两张表就是 1B 参数，占 8B 模型的 12.5%。现代模型多用权重共享省一份，但不共享的更多。
3
KV Cache 估算漏乘三个因子
最容易漏的是 batch。正确公式：2（K和V）× 层数 × KV维度 × 字节数 × 序列长度 × batch。漏一个就低估几倍到几十倍，上线直接 OOM。
4
以为"窗口 128k"就等于"实际能读 128k"
窗口是训练 + 架构上限，中间信息的利用率会衰减（lost in the middle）。关键信息要放头部或尾部，且必须用自己的数据测有效上下文。
5
以为 temperature 改变模型的知识或"智能"
它只改分布的尖锐程度。温度调高不会让模型更聪明，只会让输出更多样 —— 包括更多样的错误。
6
以为 temperature=0 输出完全可复现
浮点非结合性、batch 组成变化、不同硬件都会让结果有差异。要求逐字节可复现，要么用 seed 参数（以厂商文档为准），要么接受"近似贪心"。
7
给 RoPE 模型直接喂超长序列
位置角度超出训练区间，注意力分布崩坏，输出表现为复读和跑题。要么用长上下文版本，要么按模型卡要求配置 rope scaling / YaRN。
8
以为多头数越多参数量越大
d 固定时 QKVO 四个矩阵总参数恒为 4d²，与头数无关。头数只改变切分方式。真正影响 KV Cache 的是 KV 头数（GQA），不是 Q 头数。
9
用困惑度跨模型比较"谁更聪明"
PPL 依赖 tokenizer 和测试集，词表不同的两个模型的 loss 没有可比性。PPL 只在同 tokenizer 同测试集下有意义，且与下游任务表现只是相关不是等价。
10
优化推理只盯着 GPU 算力，不看带宽和显存
decode 阶段是显存带宽 bound：单流速度上限 = 带宽 ÷ 模型体积。算力再强，带宽跟不上就是慢。这也是量化（缩小体积）比升级算法更直接有效的原因。
自测

六道题

1. 一个标准 Decoder 层（MHA + 4 倍升维 FFN，d_model=4096）的参数量约为多少？
正确答案：约 12·d² ≈ 2.01 亿。注意力 4d²（QKVO 四个方阵）+ FFN 8d²（d×4d 和 4d×d）= 12d²。只算注意力会漏掉 2/3。
2. Llama-2-7B（32 层，MHA，d=4096，fp16）在 4k 上下文、batch=1 时的 KV Cache 约为？
正确答案：约 2 GB。2(K,V) × 32 层 × 4096 维 × 2 字节 = 512 KB/token，× 4096 token = 2 GB。16 GB 是同一配置下 32k 上下文的量，别把上下文搞混。
3. 关于 temperature 与 top-p，哪个说法正确？
正确答案：先 temperature 后截断。顺序反了 top-p 的语义就变了。而且 temperature=0.5 时分布变尖锐，top-p=0.9 保留下来的候选可能只剩一两个。
4. 为什么开放式生成（对话、写作）基本不用 beam search？
正确答案：似然 ≠ 质量。概率最高的句子往往最平庸（"这是个好问题……"），且 beam 有退化（复读）问题、k 倍 KV Cache 和计算成本。它在翻译、识别等封闭任务仍有价值。
5. 把 RoPE 模型的上下文从 4k 直接拉到 32k 使用，会发生什么？
正确答案：外推崩坏。位置 m 对应旋转角 m·θ，超长位置的角度组合训练时从未出现。解法是位置插值/NTK/YaRN 或长上下文继续训练，且必须以实际部署的框架配置验证。
6. 7B 模型单流 decode 速度约为 145 tok/s（A100，fp16），把它 INT4 量化后理论上限约为？
正确答案：约 500+ tok/s。decode 每 token 都要把全部权重从显存读一遍，是显存带宽 bound：2039 GB/s ÷ 3.9 GB ≈ 520 tok/s。量化是 decode 阶段最直接的提速手段。
