模块 1

文生图核心管线：文本编码→潜空间扩散→VAE 解码

所有主流文生图模型（SD 系、Flux 系）共享同一个三段式骨架。理解它，参数和可控性就都通了。

文本编码：提示词先过文本编码器（CLIP，Flux 还加 T5）变成向量，作为"条件"注入去噪过程。注意 CLIP 有 77 token 上限（SD 1.5/SDXL），超长部分被静默截断；Flux 的 T5 编码器上限约 512 token。
潜空间扩散：核心阶段。VAE 的编码器先把训练图压成小 latent（SD 系 8×8 下采样），去噪网络（U-Net 或 DiT）从纯噪声开始，按 steps 指定的步数一步步去噪，同时被文本向量引导（CFG 控制引导强度）。
VAE 解码：把去噪完成的 latent 还原成像素图。大图解码显存峰值高，可以用分块解码（tiled VAE）缓解。

为什么必须用潜空间：算一笔账

# SD 系：512×512 的图，两种表示方式的大小对比
像素空间：512 × 512 × 3 = 786,432 个数
潜空间：  64 × 64 × 4   =  16,384 个数   # VAE 8× 下采样，每 latent 元素覆盖 8×8 像素

压缩比 = 786,432 / 16,384 = 48×

# 推论：扩散计算量直接降约 48 倍，这是"潜空间扩散"存在的全部理由
# SDXL 同理：1024×1024×3 = 3,145,728 → 128×128×4 = 65,536，同样约 48×
# 代价：VAE 编解码本身有损，细节（小字、密集纹理）容易糊
阶段输入 → 输出计算占比备注
文本编码文本 → 条件向量可忽略（毫秒级）77/512 token 截断在这发生
潜空间扩散噪声 latent → 干净 latent90% 以上steps 就是迭代次数，SDXL 30 步典型
VAE 解码latent → 像素图5% ~ 15%大图时显存峰值常出现在这
一句话理解扩散模型：它学的不是"怎么画"，而是"怎么去噪"。每一步做的是"预测当前噪声、按调度器减去一部分"，steps 就是迭代次数。所以 steps 加到头，边际收益递减（20 步之后差异已经很小）；CFG 是"多听文本话"的强度旋钮，太高会过拟合提示词、画面僵硬。
模块 2

主流模型谱系与量级定位

模型原生分辨率架构/规模典型步数定位与注意
SD 1.5512×512U-Net 约 8.6 亿参数，CLIP 编码20 ~ 302022 年发布，生态最大（LoRA/插件最多），硬件门槛最低。质量已过时，适合学习和快速试验
SDXL1024×1024U-Net 约 26 亿参数，CLIP-L + OpenCLIP-G 双文本编码器，另有 refiner25 ~ 40质量分水岭，显存约 10GB 起。生态第二极，绝大多数 ControlNet/LoRA 都支持
SD 3.x1024×1024MMDiT（多模态 DiT）架构28 ~ 40DiT 化改造，文字渲染改善；各版本许可条款不同，商用前逐条看
Flux1024×1024DiT 约 120 亿参数，T5-XXL + CLIP 双编码，512 token 上限dev 20~30；schnell 1~4当前质量天花板之一，fp16 权重约 24GB；schnell 版蒸馏到 1~4 步，速度极快。具体规格以官方为准
商业 API1024 及以上闭源服务服务端决定DALL·E、Midjourney、即梦、可图等。按张计费、免运维、无微调；能力与配额以厂商当前文档为准
选型逻辑：要微调/生态/ControlNet → SDXL（性价比最高的主力）；追求质量上限和文字渲染、卡够大 → Flux；快速上线、无运维、量小 → 商业 API；跑 demo 学原理 → SD 1.5。注意 Flux 的 dev 与 schnell 是两个模型文件，权重、步数、引导值都不通用。
版本口径：这个领域半年一个换代，本篇所有参数量、显存、步数都是量级参考，用于建立直觉。任何具体数字（分辨率支持、许可、价格）以厂商当前文档和实测为准。
模块 3

提示词工程

开源模型的提示词是"标签式"的，不是自然语言。结构比文采重要得多。

推荐结构：主体 → 细节 → 风格 → 画质 → 构图光照

# 差：一句话全包
一只猫

# 好：结构化标签，从粗到细
a fluffy orange tabby cat sitting on a wooden windowsill,        # 主体 + 环境
looking out at rainy street, green eyes, detailed fur,            # 细节
photorealistic, National Geographic style,                        # 风格
85mm lens, shallow depth of field, soft bokeh,                    # 镜头/构图
warm afternoon light, highly detailed, 8k                         # 光照 + 画质词

# 负面提示（不要什么）：
blur, lowres, jpeg artifacts, watermark, text, bad anatomy, extra fingers

权重语法（A1111 / ComfyUI 的 CLIP 编码链路支持）

# 加括号 = 提权，乘方叠加：(word) ≈ 1.1，((word)) ≈ 1.21
(masterpiece:1.3), best quality, a medieval knight,
(crowd of people:1.2), [graffiti], (fog:0.8)
# (crowd of people:1.2) = 权重 1.2；[graffiti] = 权重约 0.9（降权）

# 注意：Flux / 部分商业 API 不识别这套语法，只吃自然语言
# 权重写死的模型里传 (word:1.2) 会被当成普通文字编码
手段作用说明
权重语法词级强调/弱化是"词"的旋钮，注意与全局 CFG 区分
负面提示排除不想要的元素精而准，堆砌会互相冲突、劣化质量
英文优先开源模型训练数据以英文为主英文 prompt 更稳；中文 prompt 可先用翻译或商业 API
触发词激活 LoRA 学的风格/角色训练时定的触发词必须出现在 prompt 里
两个常见误解：① 负面提示不是越长越好。blur/lowres/watermark 三五个精准词足够，堆二十个会显著拖慢并引入伪影。② "8k、masterpiece、best quality"是玄学词，SD 1.5 时代管用，新模型（SDXL/Flux）对自然语言描述响应更好，写清楚构图和内容比堆画质词有效。
模块 4

参数与可控性

基础参数

参数作用典型值坑
steps去噪迭代次数SD 20~30；SDXL 25~40；Flux dev 20~28；schnell 1~4超过阈值收益极小、纯浪费时间；不同模型不能照搬

可控性四件套

技术控制什么用法与注意
ControlNet构图、姿态、深度、边缘输入 canny 边缘图 / openpose 骨架 / depth 深度图作为额外条件，主模型照内容画、照条件构图。可多个叠加，各有权重；占 1~2GB 显存

img2img以图生图的改动幅度strength 0.3~0.8：越低越像原图。是"风格迁移/微调一张图"的主力手段

LoRA：风格与角色的轻量微调

项目量级参考说明
训练数据20 ~ 50 张图同风格或同角色，标注统一、去重
训练步数 / rank1000 ~ 3000 步 / rank 8~32过拟合表现为"只会画训练集里的构图"

生产环境选 ComfyUI 的三个理由：① 工作流是 JSON，可以进 Git、做 diff、按版本回滚；② 同一个图改一个参数就是改一个字段，比点界面可靠；③ API 天然异步，配合队列做批量任务没有适配成本。SD WebUI 更适合给人调试，ComfyUI 更适合给系统调用。

模块 7

应用架构：异步队列、存储 CDN、审核

生成是秒级到分钟级的耗时操作，绝不能放在 HTTP 同步请求里。标准架构是"提交 → 排队 → 异步生成 → 通知"。

提交层：POST /tasks 校验参数、做提示词预审、落库（status=queued）、推队列、立即返回 task_id。客户端拿 task_id 轮询或等回调。
队列层：Redis List / RabbitMQ / Kafka 都行。要有界、要优先级、要超时清理。worker 池消费，按 GPU 显存配并发（4090 上 SDXL 一般 1~2 并发）。
生成层：调 ComfyUI/SD WebUI API，超时设 60~120s；失败重试一次，再失败标记 failed 并保留错误信息。
存储层：原图进对象存储，CDN 加速读；缩略图预生成；设生命周期规则（如 30 天转低频、90 天删）。
审核层：输入侧敏感词/黑名单过滤；输出侧 NSFW 分类器 + 人审抽样；不过审的给兜底图并记录。
# FastAPI + Redis 的最小任务系统（可直接扩展）
from fastapi import FastAPI
from redis import Redis
import uuid, time

app = FastAPI()
rds = Redis(host="127.0.0.1", port=6379)

@app.post("/tasks")
def create_task(prompt: str, width: int = 1024, height: int = 1024):
    tid = uuid.uuid4().hex
    rds.hset(f"task:{tid}", mapping={
        "status": "queued", "prompt": prompt,
        "created": str(int(time.time() * 1000)),
    })
    rds.lpush("queue:txt2img", tid)        # 进有界队列
    return {"task_id": tid}

@app.get("/tasks/{tid}")
def get_task(tid: str):
    info = rds.hgetall(f"task:{tid}")
    return {k.decode(): v.decode() for k, v in info.items()}

# worker 侧
def worker():
    while True:
        tid = rds.brpop("queue:txt2img", timeout=5)[1].decode()
        rds.hset(f"task:{tid}", "status", "running")
        try:
            url = generate(prompt=..., timeout=120)      # 调 ComfyUI/SD WebUI
            rds.hset(f"task:{tid}", mapping={"status": "succeeded", "url": url})
        except Exception as e:

状态机就五个态：queued → running → succeeded / failed，加一个 canceled（用户取消）。所有流转都带时间戳，超时的任务（running 超过 5 分钟）由定时任务兜底置为 failed 并释放 worker。没有超时的队列一定会堆积，这是生产事故的第一来源。
模块 8

成本与延迟特征

方案单张成本（量级）延迟（1024×1024，30 步）说明
本地 4090（自购摊销）几分钱级SDXL 2~6s；Flux 15~40s日均几百张以上才摊得回
云 GPU 按量租几分钱/张（不空转才划算）同上4090 24G 约 2~3 元/小时量级；停机即停费
商业 API0.02 ~ 0.5 元级3 ~ 15s（含排队）厂商差异大，以官网为准；含平台审核兜底
批量离线攒批最低分钟级夜间跑批，适合非实时场景
成本模型的核心是 GPU 利用率，不是单张速度。异步队列 + 攒批可以把利用率从 20% 拉到 80% 以上，等效成本降 3~4 倍。经验口径：日均 1000 张以上、延迟要求松（秒级可接受）→ 自建划算；日均几百张以下、要立等可取 → API 划算。卡在中间的，用"高峰期 API + 夜间自建批跑"的混合策略。
延迟的构成比你想的更杂：排队时间（队列深度）× 生成时间（steps × 分辨率 × 模型）× 下载时间（图大小）× 审核时间。用户感知的"等图慢"，排查时按这四段分别打点，别一上来就换模型。4K 大图 + 高 steps 的 Flux 任务，排队 30 秒是正常的，产品设计上要给进度反馈（进度条、预估时间、完成后推送）。
避坑

十个真实坑

1
不看显存就上 SDXL / Flux
SDXL 峰值 10~13GB、Flux fp16 直奔 24GB。先跑 torch.cuda.max_memory_allocated() 量一遍，再决定 fp16/tiled VAE/换小模型。
2
以为固定 seed 就能复现
换 WebUI 版本、换精度、换 sampler，同 seed 结果照样变。复现要锁全套：模型哈希 + 版本 + seed + sampler + steps + cfg + 分辨率，并完整落库。
3
CFG 拉满想要"更听话"
15~20 的结果是过饱和、对比烧伤、结构僵硬。5~8 足够；要更强的遵循用提示词权重或 ControlNet，不是加 CFG。
4
忽视 77 token 截断
SD 1.5/SDXL 的 CLIP 只编码前 77 个 token，长 prompt 后半段被静默丢弃，你以为生效的修饰全没了。精简 prompt 或拆分权重。
5
负面提示堆砌
blur/lowres/watermark/bad anatomy 五个精准词够用，堆二十个互相冲突、拖慢推理还引入伪影。
6
NSFW 过滤误杀正常内容
医学插图、艺术人体、健身内容最容易被 safety checker 拦。要有兜底图、明确的用户提示和申诉通道；自建部署可以关过滤，但商用场景合规风险自担。
7
版权与合规没让法务过
训练数据来源、风格 LoRA 模仿在世艺术家、模型输出的权属和商用范围，各模型许可条款差异极大。上线前逐条看 LICENSE，商业用途尤其要谨慎。
8
分辨率拍脑袋
在 SD 1.5 上直接出 768×768 以上，多人多手概率陡增。用模型原生分辨率，要大图走 SDXL + hires fix 或 outpainting。
9
队列无界、无超时
突发流量把内存队列撑爆，或一个卡死的任务让后面全部 pending。队列要有界、任务要超时、失败要重试上限。
10
存储不设生命周期
原图 + 缩略图 + ControlNet 中间图全量留存，对象存储账单三个月后失控。配生命周期规则，CDN 只看命中率，冷数据及时转低频或删。
自测

六道题

1. SD 系模型把 512×512 的图编码为 64×64×4 的 latent，扩散阶段的计算量大约降了多少倍？
正确答案：48×。像素空间 512×512×3 = 786,432 个数，潜空间 64×64×4 = 16,384 个数，786,432 ÷ 16,384 = 48。VAE 的 8× 下采样让每个 latent 元素覆盖 8×8 个像素，这就是"潜空间扩散"省算力的全部来源。
2. 把 CFG 从 7 拉到 20，会发生什么？
正确答案：质量下降。CFG 是文本引导强度，过高会让模型过度拟合提示词、牺牲图像自然度。SD 系 5~8 是甜点；要更强的遵循度应该用词级权重或 ControlNet 条件控制，不是拉 CFG。
3. 同样的 seed，昨天和今天跑出来的图不一样，最可能的原因是？
正确答案：复现是系统工程。模型哈希、WebUI/ComfyUI 版本、fp16/fp32、sampler 与 scheduler、steps/cfg、分辨率都要锁定。所以生成参数必须完整落库，否则线上"图变了"无法排查。
4. ControlNet 的作用是？
正确答案：条件控制构图。ControlNet 把 canny 边缘、openpose 骨架、depth 深度图作为额外条件注入去噪过程，实现"构图我说了算、内容模型自由发挥"。多个 ControlNet 可叠加，各自有权重。
5. IP-Adapter 和 LoRA 的核心区别是？
正确答案：推理条件 vs 训练权重。IP-Adapter 不改主模型，推理时把参考图作为风格/主体条件；LoRA 是微调产物（10~150MB），要放进 models/LoRA 目录、设置权重、prompt 里带触发词才能激活。
6. 图像生成服务上异步队列的核心价值是？
正确答案：削峰 + 提吞吐。队列不降低单张延迟（甚至因为排队略增），但能把突发流量摊平、把 GPU 利用率从 20% 拉到 80% 以上，等效成本降数倍。单张延迟靠的是 fp16、高效注意力、少 steps 这些推理优化。
