开始前

ansible all -m ping -o            # 测连通性，成功回 pong
ansible-core 与 ansible 的区别：ansible-core 是引擎 + 少量内置模块，每两个月一个小版本；ansible 大包是 core + 几百个社区集合（collections）。生产建议装 ansible-core 再按需装集合，版本更可控。模块现在都用 FQCN 调用，如 ansible.builtin.copy，短名字只是兼容别名。
模块 1

无 Agent 架构：SSH 推送是怎么跑的

Ansible 的控制节点通过 SSH 连到每台被控机，把"模块代码"推送过去，在远端用 Python 执行，然后删掉临时文件。全程被控机不需要常驻进程。

一次任务的完整生命周期

SSH 连接目标机（复用 ControlPersist 连接，默认并发由 forks 控制，默认只有 5）
上传模块：把模块的 Python 源码写到远端临时目录（默认 ~/.ansible/tmp/ansible-tmp-xxxx/，可用 remote_tmp 改）
远端执行：模块在目标机上运行，结果以 JSON 写到临时文件
回收结果：控制节点读回 JSON，删除临时文件，进入下一个任务

推送（Push） vs 拉取（Pull）

模型代表特点与代价
Push 推送Ansible控制节点发起，实时看到结果；瓶颈在控制节点的并发能力（forks 默认 5，调 20~50 是常态）；规模天花板大致在几千台以内
Pull 拉取Puppet、Chef每台机器上的 agent 定期来拉配置；要维护 agent 及其升级，但天然支持超大规模；配置生效有延迟（默认 30 分钟一次）
Push + 队列AWX / Ansible Tower把 Playbook 执行放到服务端排队、带权限和审计，适合多团队；Ansible 的"企业版"用法
# ansible.cfg —— 最该调的几个参数（按优先级：./ansible.cfg > ~/.ansible.cfg > /etc/ansible/ansible.cfg）
[defaults]
inventory      = ./hosts          # 默认 inventory 文件
forks          = 25               # 并发数，默认 5 太小；机房内网 25~50 是安全区
host_key_checking = False         # CI 里必须关，否则首次连接卡在 yes/no 提示
pipelining     = True             # 模块不落盘，直接在 SSH 通道里跑，大幅提速
remote_user    = deploy           # 默认登录用户
private_key_file = ~/.ssh/deploy  # 默认私钥
nocows         = 1                # 关掉奶牛表情（CI 日志会乱码）

[ssh_connection]
ssh_args = -o ControlMaster=auto -o ControlPersist=60s -o Compression=yes
control_path = /tmp/ansible-ssh-%%h-%%p-%%r   # 连接复用，第二台之后几乎零握手开销
并发是把双刃剑：forks 开太大，几百台机器同时被推送模块，会把内网带宽打满、把目标机 sshd 的 MaxStartups 打满，出现间歇性 unreachable。正确姿势是 forks 20~50 + Playbook 里用 serial 分批，见模块 8。
模块 2

Inventory 与变量优先级

Inventory 就是"有哪些机器、归哪组、各是什么变量"。它支持 INI 和 YAML 两种写法，也支持从云 API 动态拉取。

INI 格式（小规模最直观）

# hosts 文件（INI 格式）
[web]                                   # 组名
web1 ansible_host=10.0.0.1 ansible_user=ubuntu
web2 ansible_host=10.0.0.2 ansible_user=ubuntu

[web:vars]                              # 给整个组设变量
ansible_python_interpreter=/usr/bin/python3
http_port=80

[db]
db1 ansible_host=10.0.1.10 ansible_user=ubuntu

[prod:children]                         # 组的组：prod 包含 web 和 db
web
db

[prod:vars]
env=production

YAML 格式（可读性更强，云场景常用）

all:
  children:
    web:
      hosts:
        web1:
          ansible_host: 10.0.0.1
          ansible_user: ubuntu
          http_port: 8080            # 主机级变量，覆盖组变量
    db:
      hosts:
        db1:
          ansible_host: 10.0.1.10
    prod:
      children:
        web: {}
        db: {}

动态 Inventory

# 机器在云上自动伸缩，静态清单跟不上，用动态 inventory 插件
ansible-inventory -i aws_ec2.yml --graph        # 从 AWS API 拉机器

# aws_ec2.yml 长这样
plugin: amazon.aws.aws_ec2
regions:
  - us-east-1
filters:
  tag:Environment: production
keyed_groups:
  - key: tags.Role
    prefix: role

变量优先级（官方 22 级，记住 4 条就够用）

层级（从低到高）说明
role defaults/defaults/main.ymlRole 的默认值，最容易被覆盖，适合放可调参数
group_vars/all、inventory 组变量按组批量下发
host_vars/*、inventory 主机变量单机特例
play vars / task vars / set_fact / register执行期产生和覆盖的值
extra vars（-e）最高优先级，碾压一切。命令行传参、CI 流水线注入都用它
# 魔法变量（Ansible 自动提供，排查时极有用）
{{ inventory_hostname }}                          # 当前主机在 inventory 里的名字
{{ groups['web'] }}                               # web 组的所有主机名列表
{{ hostvars['web1'].ansible_host }}               # 别的机器的变量，可跨机引用
{{ hostvars[inventory_hostname].ansible_default_ipv4.address }}   # 当前机默认网卡 IP
优先级最常见的翻车点：在 defaults/main.yml 里改了参数以为生效了，结果被 vars/main.yml 或 -e 悄悄盖掉。记住：defaults 是最低优先级，vars 更高；排查时用 ansible-inventory --host web1 直接看最终合并结果，比读六个文件靠谱。
模块 3

Playbook 与 Role 结构

Playbook 是 YAML 写的"剧本"，一个 play 对一组主机执行一组任务。Role 是把 Playbook 按功能切分的复用单元 —— 这是从"脚本小子"到"工程化"的分界线。

# deploy.yml —— 一个最小但完整的 play
---
- name: Deploy nginx to web tier
  hosts: web
  become: true                    # 全程 sudo，等价 -b
  become_user: root
  gather_facts: true             # 收集目标机信息（慢，大集群可关）
  vars:
    nginx_port: 80
    nginx_worker_processes: auto
  tasks:
    - name: Install nginx
      ansible.builtin.package:
        name: nginx
        state: present
      notify: restart nginx          # 状态变化时通知 handler

    - name: Deploy config
      ansible.builtin.template:
        src: nginx.conf.j2
        dest: /etc/nginx/nginx.conf
        owner: root
        group: root
        mode: '0644'
        validate: 'nginx -t -c %s'   # 写完后先自检，失败则不生效
      notify: restart nginx

    - name: Ensure nginx is running
      ansible.builtin.systemd:
        name: nginx
        state: started
        enabled: true

  handlers:
    - name: restart nginx
      ansible.builtin.systemd:
        name: nginx
        state: restarted

Role 的标准目录结构

roles/
└── nginx/
    ├── defaults/main.yml      # 默认变量（最低优先级，可被外部覆盖）
    ├── vars/main.yml         # 内部变量（高优先级，一般不放可调项）
    ├── tasks/main.yml        # 入口，可用 include_tasks 拆文件
    ├── handlers/main.yml     # 事件驱动的重启/重载动作
    ├── templates/nginx.conf.j2   # Jinja2 模板，.j2 后缀
    ├── files/index.html      # 静态文件，copy 模块直接用
    ├── meta/main.yml         # 依赖声明、作者、平台支持
    └── README.md
# 用 Role 重写上面的 play，一行引用
---
- name: Deploy nginx
  hosts: web
  become: true
  roles:
    - role: nginx
      nginx_port: 8080              # 传参覆盖 defaults
      tags: [web, nginx]            # 打标签，方便 --tags 选择性执行

# 引用外部 Role 仓库（Galaxy）：requirements.yml
---
roles:
  - name: geerlingguy.nginx
    version: 3.1.4
  - src: https://github.com/example/ansible-role-redis.git
    scm: git
    version: main
    name: redis

# 安装：
ansible-galaxy install -r requirements.yml
ansible-galaxy init my-new-role       # 生成标准目录骨架

静态导入 vs 动态包含（高频面试题）

import_tasks / import_playbook 执行前静态展开，--list-tasks 能看到全部任务，tags 会传染给子任务，适合结构固定的拆分（如 Debian/RedHat 分文件）；include_tasks / include_role 运行时动态加载，--list-tasks 看不到内容，tags 不传染，适合按条件或循环动态加载。

组织原则：一个 Role 只干一件事（装 nginx 的就别顺手改防火墙）；Playbook 负责编排多个 Role 的顺序和传参。handlers 是"状态机的闭环"——任务只有真的改变了系统（changed）才会触发 handler，所以重启类操作不会每次执行。
模块 4

常用模块详解

Ansible 有 3000+ 模块，日常 80% 的场景只用到 20 个左右。全部支持 FQCN 调用（ansible.builtin.copy）。

执行命令三兄弟：command / shell / raw

模块特点坑
command不走 shell，直接 execve，无管道/重定向/变量展开永远报告 changed=true，破坏幂等
shell经 /bin/sh -c 执行，支持管道、重定向、&&同样永远 changed；变量拼接有注入风险
raw不走模块机制，直接 SSH 执行原生命令，不需要目标机有 Python仅用于 bootstrap 装 Python，之后就别用了
# command：参数列表形式最安全
- name: restart app safely
  ansible.builtin.command:
    argv:
      - systemctl
      - restart
      - myapp
    chdir: /opt/myapp
  changed_when: false                # 声明它不改状态，保持幂等

# command 的两个"智能开关"——有 creates 参数且文件存在就跳过
- name: one-time init
  ansible.builtin.command: /opt/app/bin/init.sh
  args:
    creates: /opt/app/.initialized   # 文件在 → 跳过，任务变 skipped

# shell：只有真的需要管道时才用
- name: count errors in log
  ansible.builtin.shell: grep -c ERROR /var/log/app.log || true
  register: err_count
  changed_when: false

文件与配置管理

# copy：推静态文件
- name: push config
  ansible.builtin.copy:
    src: files/app.conf             # 相对 role/files/ 或 play 目录
    dest: /etc/app/app.conf
    owner: app
    group: app
    mode: '0640'                    # 必须带引号，否则 0640 是十进制 640！
    backup: true                    # 覆盖前留 .bak

# template：Jinja2 渲染后推送（见模块 5）
- name: render app config
  ansible.builtin.template:
    src: templates/app.conf.j2
    dest: /etc/app/app.conf
    validate: '/usr/sbin/appd -t -c %s'   # %s 是渲染后的临时文件路径

# lineinfile / blockinfile：精准改单行或一段
- name: ensure swap off in fstab
  ansible.builtin.lineinfile:
    path: /etc/fstab
    regexp: '^.*swap'
    state: absent
    backrefs: true

- name: append block if missing
  ansible.builtin.blockinfile:
    path: /etc/security/limits.conf
    marker: "# {mark} ANSIBLE MANAGED BLOCK app"
    block: |
      app soft nofile 65535
      app hard nofile 65535

# file：目录/权限/软链一站式
- name: ensure symlink for release switch
  ansible.builtin.file:
    path: /opt/app/current           # state=link 时是软链路径
    src: /opt/app/releases/v1.2.3    # 软链指向，做发布切换
    state: link
    owner: app
    force: true                      # 已存在别的软链时强制替换

服务与用户

# systemd：现代发行版首选，替代老的 service 模块
- name: manage service
  ansible.builtin.systemd:
    name: nginx
    state: restarted                # started/stopped/restarted/reloaded
    enabled: true                   # 开机自启
    daemon_reload: true             # 改了 unit 文件后必须先 reload

# user：建用户、加组
- name: create deploy user
  ansible.builtin.user:
    name: deploy
    groups: [sudo, docker]
    append: true                    # 追加组，不覆盖原有
    shell: /bin/bash
    state: present

# package：自动匹配 apt/yum/dnf，跨平台 play 不用写 when 分支
- name: install packages
  ansible.builtin.package:
    name:
      - nginx
      - git
      - curl
    state: present                  # present/absent/latest

网络下载与等待

# get_url + unarchive：下载解压二连，装二进制软件的标配
- name: install node exporter
  block:
    - name: download
      ansible.builtin.get_url:
        url: https://github.com/prometheus/node_exporter/releases/download/v1.8.2/node_exporter-1.8.2.linux-amd64.tar.gz
        dest: /tmp/node_exporter.tar.gz
        checksum: sha256:https://...    # 校验和，防篡改，强烈建议配
        mode: '0644'
    - name: unarchive
      ansible.builtin.unarchive:
        src: /tmp/node_exporter.tar.gz
        dest: /usr/local/bin/
        remote_src: true                # 已经在目标机上，别从控制机传
        creates: /usr/local/bin/node_exporter   # 已存在则跳过

# wait_for：等端口就绪（滚动发布时等健康检查）
- name: wait for app to listen
  ansible.builtin.wait_for:
    port: 8080
    host: 127.0.0.1
    delay: 2                          # 先等 2 秒再探
    timeout: 60                       # 最多等 60 秒，超时任务失败
    state: started

调试与断言

# assert：前置条件检查，条件不满足直接失败，防止带着错误配置往下跑
- name: validate memory requirement
  ansible.builtin.assert:
    that:
      - ansible_memtotal_mb >= 2048
      - nginx_port | int > 0
      - nginx_port | int < 65536
    fail_msg: "内存不足或端口非法: {{ ansible_memtotal_mb }}MB, port={{ nginx_port }}"
    success_msg: "检查通过"

# debug：打印变量，排查利器（verbosity 控制只在 -vv 以上输出）
- name: show resolved config
  ansible.builtin.debug:
    var: ansible_default_ipv4
  verbosity: 2

# fail：显式失败（配合 when 做业务校验）
- name: refuse to run on prod without approval
  ansible.builtin.fail:
    msg: "需要 APPROVAL_TOKEN"
  when: env == "production" and approval_token is not defined
模块 5

Jinja2 模板与条件循环

Ansible 的变量系统就是 Jinja2。{{ }} 求值、{% %} 控制流、{# #} 注释，全部可以在模板、变量甚至任务名里用。

变量访问与默认值（防御性写法）

# 未定义变量直接报 AnsibleUndefinedError —— 模板崩了整个任务失败
{{ app_name }}                                # ✗ 没定义就炸
{{ app_name | default('myapp') }}             # ✓ 兜底
{{ app_name | default('myapp', true) }}       # ✓ 空字符串/None 也替换（布尔参数=true）

# 嵌套字典安全访问（两种等价写法）
{{ (db_config | default({})).get('host', 'localhost') }}
{{ db_config.host | default('localhost') if db_config is defined else 'localhost' }}

# 类型转换：YAML 里 "8080" 可能是字符串，比较前先转
{{ (nginx_port | int) + 1 }}
{{ (enabled | bool) }}
{{ cpu_cores | float | round(2) }}

常用过滤器（filter）速查

过滤器作用与示例
default(d, true)默认值，第二个参数=true 时 None/空串也替换
map('extract', hostvars)把主机名列表变成 hostvars 字典列表，跨机遍历必备
selectattr / rejectattr按属性过滤对象列表，如只选 os_family == 'Debian' 的机器
to_json / from_jsonJSON 序列化/反序列化，调 API 常用
combine(dict2)字典合并，做配置覆盖：defaults | combine(overrides)
dict2items / items2dict字典与 {key,value} 列表互转，方便 loop
regex_replace正则替换：v | regex_replace('^v', '')
# 实战：把 web 组所有机器的 IP 拼成 upstream 列表
{% for host in (groups['web'] | map('extract', hostvars) | list) %}
server {{ host.ansible_default_ipv4.address }}:{{ host.http_port | default(80) }} max_fails=3;
{% endfor %}

# 实战：按条件渲染配置段
{% if env == 'production' %}
worker_processes {{ ansible_processor_vcpus }};
{% else %}
worker_processes 1;
{% endif %}

条件（when）与循环（loop）

# when 支持 and/or/not，也支持 Jinja2 表达式，还能串列表（列表项是 and）
- name: install on debian family
  apt: name=nginx state=present
  when:
    - ansible_os_family == "Debian"
    - ansible_distribution_version | float >= 20.04
    - "'docker' not in ansible_facts.packages"

- name: skip on containers
  debug: msg="skip"
  when: ansible_virtualization_type == "docker"

# when 里判断 register 的结果（rc=返回码，stdout/stderr/stdout_lines）
when: version_out.rc == 0
when: version_out.stdout is search("1\\.2\\.")      # 正则匹配用 search test
when: version_out.stdout_lines | length > 0

# set_fact：任务间传值，比 register 更适合跨任务复用
- name: compute app root
  ansible.builtin.set_fact:
    app_root: "/opt/{{ app_name }}/{{ version }}"
    cacheable: true                  # 允许 fact caching 缓存（Redis/JSON）

# loop 替代 with_items（with_* 全系已废弃，但存量代码到处都是）
- name: create dirs
  file:
    path: "/var/log/{{ item }}"
    state: directory
    mode: '0755'
  loop:
    - app
    - nginx
    - redis

- name: create users from dict
  user:
    name: "{{ item.key }}"
    groups: "{{ item.value.groups }}"
  loop: "{{ users | dict2items }}"
  when: item.value.create | default(true) | bool

# loop 的高级控制：pause 滚动重启神器，label 防输出刷屏
- name: rolling restart
  systemd: name=app state=restarted
  loop: "{{ groups['web'] }}"
  loop_control:
    pause: 5
    label: "{{ item }}"

# 循环里收集结果再统一判断（健康检查标准写法）
- name: query all nodes
  uri: url=http://{{ item }}/health return_content=true
  register: health
  loop: "{{ groups['web'] }}"
  changed_when: false
  failed_when: false                # 允许失败，下面自己判断

- name: assert all healthy
  assert:
    that: item.status == 200
    fail_msg: "{{ item.item }} DOWN"
  loop: "{{ health.results }}"

测试（test）与查找插件（lookup）

# test：when 里的布尔判断
when: myvar is defined
when: path is ansible.builtin.file          # 目标机上是普通文件
when: result is succeeded                  # 上个任务没 failed（不用管 rc）
when: version is match('\d+\.\d+')         # 正则匹配

# lookup：从外部数据源读值（在控制节点执行）
{{ lookup('env', 'HOME') }}                       # 环境变量
{{ lookup('file', 'files/ssl.crt') }}             # 读控制机文件内容
{{ lookup('password', '/tmp/db_pw length=32') }}  # 生成并落盘随机密码，幂等

# 注意：lookup 在控制节点求值；想在目标机上查文件用 stat 模块
模块 6

Ansible Vault：敏感信息加密

数据库密码、API Token、私钥不能明文提交 Git。Vault 用 AES-256 加密 YAML 文件或单个字符串，解密只在内存里发生。

# 加密整个文件（推荐把机密变量集中放 group_vars 里的单独文件）
ansible-vault create group_vars/prod/vault.yml       # 交互式建文件，写密码
ansible-vault edit group_vars/prod/vault.yml         # 解密编辑，保存后自动重新加密
ansible-vault view group_vars/prod/vault.yml         # 只查看
ansible-vault rekey group_vars/prod/vault.yml        # 改加密密码（批量轮换时用）
# 加密已存在的明文文件（保留 .yml 名，内容变成密文）
ansible-vault encrypt vars/prod-secrets.yml
ansible-vault decrypt vars/prod-secrets.yml          # 解密回明文

# 加密单个字符串，内嵌在普通 YAML 里（!vault 标记）
ansible-vault encrypt_string --stdin-name 'db_password'
# 输入：SuperSecret123  输出：
db_password: !vault |
          $ANSIBLE_VAULT;1.1;AES256
          34623462346234623462346234...

# 加密后文件长这样，Git 里只能看到这个
$ANSIBLE_VAULT;1.1;AES256
31626535656239353263363064366233...

运行时怎么解锁

# 方式一：交互式输入
ansible-playbook site.yml --ask-vault-pass

# 方式二：密码文件（CI 推荐，从 secret manager 注入）
ansible-playbook site.yml --vault-password-file ~/.ansible/vault_prod.txt

# 多密码场景：dev/prod 用不同密码，一个命令全解锁
ansible-playbook site.yml \
  --vault-id prod@~/.ansible/vault_prod.txt \
  --vault-id dev@~/.ansible/vault_dev.txt

# 也可以让 ansible.cfg 记住密码文件（本机开发省事，别提交进 Git）
[defaults]
vault_password_file = ~/.ansible/vault.txt
三个安全实践：① 密码本身怎么管？小团队用密码管理器，大团队把 vault 密码放 KMS/HashiCorp Vault，CI 启动时拉取，密码文件权限设 600；② vault 文件也要进 Git——密文进仓库是常态，密码不进，明文文件忘记加密就提交是最高频的泄露事故；③ 加密不等于权限控制，能跑 Playbook 的人就能解密，需要分机隔离时用不同 vault-id + 不同 inventory。
模块 7

ad-hoc 命令与调试工具链

ad-hoc 是"一次性命令"，适合巡检和救火。学会 --check / --diff / -vvv 三件套，能干掉 90% 的"为什么没生效"。

ad-hoc 常用姿势

ansible all -m ping -o测全部主机连通性，-o 单行输出
ansible web -m shell -a 'df -h | grep -v tmpfs'在 web 组执行 shell，需要管道时用 shell
ansible web -m command -a 'systemctl restart nginx' -b-b 即 become，sudo 执行
ansible web -m copy -a 'src=hotfix.conf dest=/etc/nginx/conf.d/' -b用模块推一个紧急配置
ansible 'web:!web2' -m ping组 + 排除语法：所有 web 除 web2

playbook 调试命令

ansible-playbook site.yml --syntax-check只查 YAML 语法，秒级反馈，提交前必跑
ansible-playbook site.yml --check --diff预演：看会改什么，diff 看文件级差异
ansible-playbook site.yml --limit web1只对 web1 执行，救火时缩小爆炸半径
ansible-playbook site.yml --tags nginx --skip-tags slow只跑打了标签的任务
ansible-playbook site.yml --start-at-task 'Deploy config'从指定任务开始，失败重跑不用从头来
ansible-playbook site.yml --step每步前问 yes/no，危险操作的人工刹车
ansible-doc ansible.builtin.template查模块文档，离线可看，比翻网站快
ansible-lint site.yml静态检查，抓 FQCN、命名、yaml 陷阱
--check 不是万能的：command/shell 在 check 模式下会跳过，某些模块 check 结果可能失真，handler 也不会触发。--check 只能告诉你"大概率会改什么"，正式环境仍然先在预发跑一遍。
模块 8

并发、滚动更新与执行策略

给 5 台机器装软件和给 500 台装软件，是两个世界。控制节奏靠 serial 和 throttle，等待结果靠 wait_for，跳过慢节点靠 async。

三个控制并发的参数

参数作用范围行为
forks全局（ansible.cfg）整个 playbook 同时连多少台机器。默认 5，生产 20~50
serialplay 级每批执行几台，批与批之间串行。支持百分比和列表
throttle任务级单个任务内的并发上限，loop 里限速神器
# serial 的三种写法- hosts: web
  serial: 1                        # 一次一台，最安全的滚动发布
- hosts: web
  serial: "30%"                    # 每批 30%（10 台每次动 3 台）
- hosts: web
  serial: [1, "10%", "100%"]       # 批次梯度：先 1 台试水，再 10%，再全量

# 批内允许失败的百分比，超过就整体中止
- hosts: web
  serial: "20%"
  max_fail_percentage: 25          # 25% 失败即停，防止带着故障滚完全场
# 滚动发布的标准套路：下线 → 更新 → 健康检查 → 上线
- hosts: web
  serial: 1
  tasks:
    - name: remove from load balancer
      uri: url=http://lb/api/deregister method=POST
      delegate_to: localhost        # 在控制机执行，不连目标机

    - name: deploy new version
      copy: src=app.tar.gz dest=/opt/app/

    - name: restart
      systemd: name=app state=restarted

    - name: wait healthy
      uri: url=http://127.0.0.1:8080/health status_code=200
      register: result
      until: result.status == 200   # 直到条件满足，失败重试
      retries: 30
      delay: 2

    - name: re-add to load balancer
      uri: url=http://lb/api/register method=POST
      delegate_to: localhost

# async：长任务丢后台，不占 forks（适合重启、编译、备份）
- name: long compile
  command: make -j4
  async: 3600                      # 最长跑 1 小时
  poll: 0                          # 不等待，立即返回
  register: build_job

# 之后用 async_status: jid={{ build_job.ansible_job_id }} 轮询结果
- name: wait for build
  async_status:
    jid: "{{ build_job.ansible_job_id }}"
  register: job_result
  until: job_result.finished
  retries: 60
  delay: 30

执行策略

# linear（默认）：等当前批次所有机器都完成，才进下一批；free 则每台独立跑完，吞吐最高
- hosts: web
  strategy: linear
  serial: 2

# run_once：任务只在一台机器上执行一次（初始化、选主）
- name: init cluster (only once)
  command: /opt/app/bin/cluster-init
  run_once: true

# delegate_to + delegate_facts：任务在别的机器上跑，变量算给当前 host
- name: wait for peer
  wait_for: host={{ hostvars[item].ansible_host }} port=5432
  loop: "{{ groups['db'] }}"
  delegate_to: "{{ item }}"
  delegate_facts: true             # 结果存到被委托机的 facts 上
规模参考经验值：100 台以内随便跑；100~500 台，forks 25 + serial "10%" + pipelining 开；500 台以上，按业务域拆成多个 Playbook 并行，或上 AWX 做任务队列。一次动 500 台机器的 Playbook，不管写得多优雅，都不该由人手敲触发。
坑库

十个线上坑

1
command/shell 模块永远报告 changed
它们天生不知道"系统状态有没有变"，每次都报 changed=true，导致 handler 每次都被触发、CI 里 diff 全是噪音。解法：能用 file/copy/systemd 等声明式模块就别用命令；必须用时加 changed_when: false 或 creates:。
2
用 shell 拼包含空格的变量，被注入或解析错
shell: echo {{ user_input }} 遇到 a; rm -rf / 就是灾难，遇到空格就变成多个参数。用 command 的 argv 形式，或 shell 里加引号 shell: echo "{{ user_input }}"，并对输入做 regex 校验。
3
become 失败：permission denied
目标机用户没有 NOPASSWD sudo 权限时，任务直接挂。解法：在 sudoers 里给部署用户配 NOPASSWD，或 --ask-become-pass 输入密码；别图省事直接给用户全量 root 登录。
4
handler 名字打错，静默不执行
tasks 里 notify: restart nginx，handlers 里写成 Restart Nginx —— 不报错，但永远不会触发。而且 handler 只在状态变化时触发、在整个 play 结束时统一执行（顺序按 handlers 声明顺序，不是 notify 顺序）。排查用 -v 看 "Running handlers" 段。
5
改了 defaults/main.yml 不生效
变量优先级 22 级，defaults 是最低的一档，被 group_vars、-e、play vars 全方面覆盖。排查终极武器：ansible-inventory --host web1 看最终值，或任务里 debug: var=nginx_port。
6
YAML 布尔陷阱：yes/no/on/off 不是字符串
YAML 1.1 规范里 enabled: yes 解析成布尔 true。密码叫 no、版本写成 on 就会离奇出错。Ansible 用 YAML 1.1 解析，所有当字符串用的值一律加引号，mode: '0644' 同理。
7
gather_facts 太慢，大集群 playbook 卡在第一步
默认收集几百个 fact，几百台机器时这一步就要几分钟。解法：不需要 facts 的任务设 gather_facts: no；需要时开 fact caching（fact_caching = jsonfile 或 redis + fact_caching_timeout = 86400）。
8
copy 分发大文件慢到超时
copy 每次全量传，百 MB 的安装包推 100 台就是灾难。解法：先用 get_url 让目标机自己下载，或 ansible.posix.synchronize（底层 rsync，增量同步）；临时文件记得清理。
9
Jinja2 模板引用未定义变量，任务直接崩
{{ db.password }} 在 db 变量没提供时抛 AnsibleUndefinedError，整个 play 挂掉。防御写法：{{ db.password | default('') }}，或用 assert 在 play 开头集中校验必填变量，失败信息比堆栈友好得多。
10
不设 serial 全集群并发，网络/sshd 被打满
forks 50 打 500 台时，间歇性 unreachable、sshd MaxStartups 丢连接、内网带宽占满。解法：serial: "10%" 控制批次，max_fail_percentage 设熔断，pipelining = True 减少单连接开销，目标机 sshd 调大 MaxStartups。
自测

六道题

1. 需要执行 "ps aux | grep app | wc -l" 这样的管道命令，应该用哪个模块？
正确答案：shell。command 不走 shell，管道、重定向、&& 全部无效。但 shell 也有代价：变量拼接有注入风险，且和 command 一样永远报告 changed，需要显式 changed_when: false。
2. 同一个变量在 role defaults、group_vars/all、命令行 -e 里都定义了，最终生效的是？
正确答案：-e 命令行 extra vars。官方 22 级优先级里它碾压一切，这也是 CI 流水线用 -e 注入环境参数的原因。defaults 反而是最低优先级，专门设计成"容易被盖掉"。
3. 关于 handler，哪个说法是对的？
正确答案：changed 才触发 + play 结束统一执行。这就是为什么 template 推送配置 + notify 重启服务时，配置没变就不会重启。执行顺序按 handlers 声明顺序，不是 notify 顺序。
4. ansible-vault encrypt_string 加密后的值在 YAML 里长什么样？
正确答案：!vault 标记 + $ANSIBLE_VAULT;1.1;AES256 头的密文块。这样单个加密字符串可以内嵌在普通 YAML 里，明文变量和密文变量能混排。运行时 ansible-vault 自动解密进内存。
5. 给 200 台机器做滚动发布，既想控制爆炸半径又想限批内失败，正确的组合是？
正确答案：serial + max_fail_percentage。serial 把 200 台切成每批 20 台串行推进，批内还有健康检查兜底；max_fail_percentage 是熔断器，防止带着故障滚完全场。forks 是全局并发上限，serial 才是发布节奏。
6. 执行 "ansible-playbook site.yml --check --diff" 的结果，下列哪个理解是对的？
正确答案：--check 是预演，有已知局限。command/shell 默认跳过；依赖外部状态的模块 check 结果可能失真；handler 不触发。真正保险的做法是 --syntax-check + 预发环境实跑 + 生产小批量 serial 推进。

术语一句话解释
Control 节点安装 Ansible、发起执行的机器；被控机不需要装任何 agent
Inventory主机清单：定义有哪些机器、分组、组/主机变量，INI 或 YAML 格式

Role可复用的功能单元，标准目录含 tasks/handlers/vars/defaults/templates/files/meta
Task最小执行单元，调用一个模块 + 参数

changed_when手动声明任务是否改变了系统，让 command 类模块也能幂等
serialplay 级分批执行参数，滚动发布控制爆炸半径的核心
