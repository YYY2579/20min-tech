一张全景图

国产数据库不是"一个东西"，而是多条技术路线。先按血统和形态分清楚，再谈选型。

产品厂商血统/协议定位

模块 1

达梦 DM：Oracle 的"平替"路线

体系架构

DM 的架构刻意贴近 Oracle：进程 + 内存池 + 文件三段式。核心进程是 dmserver，一个实例对应一个线程/进程体系；内存分 Buffer Pool、Hash 区、Sort 区等；数据落盘为数据文件（.DBF）、联机日志、控制文件，主配置是 dm.ini。页大小在初始化时指定（常见 8KB）。

形态说明
DM8 单机单节点单实例，最基础的部署形态
DMDataWatch 数据守护主备高可用：主库 + 实时/异步备库，故障自动切换，类似 Data Guard 思路
DMDSC 共享存储集群多实例共享同一份存储，类似 RAC 思路，读扩展 + 故障切换，但存储本身仍是共享单点
读写分离集群基于数据守护备库提供只读分流

与 Oracle 的兼容性

  • 兼容模式可配：dm.ini 中可设置兼容模式（Oracle 模式/MySQL 模式等），行为细节以官方文档为准。
  • PL/SQL 兼容子集：存储过程、函数、触发器、包、游标大部分可用，但高级特性（自治事务、部分 DBMS 内置包、复杂层次查询）需逐项验证。
  • 对象模型兼容：序列、同义词、DB Link、V$ 视图体系、数据字典视图（USER_/ALL_/DBA_）沿用 Oracle 习惯，Oracle 老兵上手快。
  • 大小写与字符集：初始化时用 CASE_SENSITIVE 控制大小写敏感，CHARSET 控制字符集（UTF-8 常用），和 Oracle 默认大写不敏感的行为对齐。
# 典型 Linux 部署：解压安装包 → dminit 初始化 → dmserver 启动
mkdir -p /dm8
tar -zxvf dm8_*.tar.gz -C /dm8

cd /dm8/bin
./dminit PATH=/dm8/data DB_NAME=DAMENG INSTANCE_NAME=DMSVR \
  PORT_NUM=5237 CASE_SENSITIVE=0 CHARSET=1

# 启动（生产建议注册为系统服务后管理）
nohup ./dmserver /dm8/data/DAMENG/dm.ini > /dev/null 2>&1 &

# 命令行客户端 disql 连接（默认端口 5237）
./disql SYSDBA/SYSDBA@localhost:5237

-- 连上后验证
SQL> SELECT arch_mode, status FROM v$database;
SQL> CREATE TABLE t_demo (id INT PRIMARY KEY, name VARCHAR(50));
SQL> INSERT INTO t_demo VALUES (1, 'dm');
SQL> SELECT * FROM t_demo;

# 图形化管理工具 Manager、命令行导入导出 dexp/dimp，用法见官方手册
"兼容 Oracle"≠"能跑 Oracle"。现实里最常翻车的三类：① 带复杂业务逻辑的 PL/SQL 包（批量绑定、自治事务、游标变量）；② 用了 Oracle 特有函数/包（如部分 DBMS_*、层次查询 CONNECT BY 的复杂写法）；③ 依赖 Oracle 错误码和告警日志的运维脚本。兼容性验证必须逐对象过，不能抽样。
模块 2

OceanBase：原生分布式 + 多租户

架构总览

组件说明
OBServer每个节点一个 observer 进程，SQL 服务端口 2881、RPC 端口 2882。无主从概念，节点对等
OCP云平台/运维管控：集群部署、监控、告警、升级
OMS迁移服务：异构数据迁移（MySQL/Oracle/PG → OB）与数据同步
ODC / OBAgent研发协作工具 / 节点监控采集代理
版本社区版开源（2021 年开源，当前社区 4.x 系列），商业版与云版功能更多，以官网为准

存储与一致性：Paxos 多副本

  • 分区（partition）是复制单位：一个分区一个 Paxos 组，多数派副本确认即提交，故障自动选主，无主从切换的人工操作。
  • 副本角色：全功能副本（F，可当选主）、只读副本（R）等，可按副本类型规划读写分离与容灾（角色细节以官方文档为准）。
  • 存储模型：MemTable（内存增量）+ SSTable（基线数据，类 LSM）+ Clog（提交日志），定期 major freeze 做合并，这是 OB 存储运维的核心动作。
  • 多副本 + 多数派意味着单副本故障不中断服务，适合对可用性要求极高的场景。

多租户与资源隔离

-- 租户 = 独立的"数据库实例"：一套 OB 集群服务多个业务
-- 资源单元定义单份资源规格，资源池 = N 个单元，租户按池分配
CREATE RESOURCE UNIT box_4c8g MAX_CPU 4, MIN_CPU 4, MEMORY_SIZE '8589934592';
CREATE RESOURCE POOL pool_box UNIT = 'box_4c8g', UNIT_NUM = 1;
CREATE TENANT obmysql RESOURCE_POOL_LIST = ('pool_box'), charset = 'utf8mb4';

-- 连接：用户名格式 user@租户名，MySQL 客户端/obclient 均可
$ obclient -h127.0.0.1 -P2881 -uroot@obmysql -p
$ obclient -h127.0.0.1 -P2881 -uroot@sys -A     # sys 是系统租户

本地一键部署（obd）

# 安装 obd（OceanBase Deployer）后，一条命令起本地测试集群
obd demo

# 多机生产部署：写配置 → deploy → start
obd cluster deploy obcluster -c ./deploy.yaml
obd cluster start obcluster
obd cluster display obcluster
OB 的独特价值在"租户级隔离"：一个物理集群按租户切分 CPU/内存/IO，业务互相不抢资源，运维上"一套集群几百个租户"是常见形态。代价是资源规划要前置：unit 的 memory_size/max_cpu 和 unit_num 定小了，业务长大就尴尬。
HTAP 与现实约束：OB 社区版 4.x 提供列存副本与向量化执行，可做实时分析。但① 列存副本同步有延迟；② 社区版功能较商业版少；③ MySQL 模式下不支持存储过程/触发器/自定义函数；④ 分区表语法与 MySQL 有差异。迁移前逐项对照官方文档验证。
模块 3

GaussDB 与 openGauss：PG 血统的自主可控

品牌关系先理清

产品说明
openGauss华为开源的关系型数据库（2020 年开源），内核源自 PostgreSQL 演进，许可证为木兰宽松许可证（MulanPSL-2.0），可免费使用、修改、分发
GaussDB华为企业级数据库品牌：for openGauss（集中式/分布式企业版）、for MySQL（MySQL 协议兼容）、for PostgreSQL（PG 兼容）、DWS（MPP 数仓）
关系openGauss 是开源底座，GaussDB（for openGauss）是其企业增强形态；选型时先确认要的是开源版还是商业版

形态与组件

  • 集中式：一主多备，流复制 + 自动故障转移，替代传统单机库。
  • 分布式：CN（协调节点）+ DN（数据节点）+ GTM（全局事务管理器）等组件，数据分片存储，支持水平扩展（组件划分以官方文档为准）。
  • GaussDB(for MySQL)：面向 MySQL 替换，协议与语法高度兼容，同样有集中式/分布式形态。

openGauss 部署实操

# 1. 解压安装包
tar -jxf openGauss-x.x.x-openEuler-64bit.tar.gz -C /opt/software

# 2. 预安装（root 执行，创建 omm 用户、依赖、内核参数）
cd /opt/software/openGauss/script
python3 gs_preinstall -U omm -G dbgrp -X /opt/software/openGauss/clusterconfig.xml

# 3. 安装（omm 用户，按 XML 拓扑执行）
su - omm
gs_install -X /opt/software/openGauss/clusterconfig.xml

# 4. 连接与常用管理
gsql -d postgres -p 26000
gs_om -t status              # 集群状态
gs_guc set -c 'work_mem=64MB' -N all -I all   # 改参数
gs_ctl start/stop/query -D /opt/gaussdb/data/db1   # 单实例管理
gs_basebackup / gs_dump     # 物理/逻辑备份
为什么 PG 血统在政企吃香：① PG 生态开源友好，扩展插件（全文检索、GIS、JSON）成熟；② openGauss 保留了 psql/JDBC/psycopg2 等生态入口，迁移成本低于"全新协议"；③ 木兰宽松许可证没有"开源版功能阉割"的商务顾虑。如果你团队本来就会 PG，openGauss 是四条路线里学习成本最低的。
GaussDB 的坑在"版本族谱"：for MySQL / for PostgreSQL / for openGauss / DWS 是不同产品，协议、驱动、工具都不通用。采购和迁移前第一件事是确认自己用的是哪个形态，别按一个产品的经验套另一个。
模块 4

迁移实操（上）：评估与语法差异

评估七步

对象盘点：表、索引、视图、序列、同义词、存储过程、触发器、自定义函数/类型、定时任务，逐类计数
SQL 语法扫描：用厂商迁移评估工具（如华为云 UGO 类工具、OB OMS 评估）扫全量 SQL，产出兼容率报告和改造清单
数据量与增长：单表行数、最大表、日增数据量、保留周期 —— 决定单机还是分布式形态
性能基线：核心接口的 TPS/QPS/RT 存档，迁移后逐条对比
一致性方案：割接窗口 + 校验工具（行数/checksum/对账 SQL）
回退方案：反向同步链路、回切步骤、决策时限
灰度计划：非核心业务先行，按百分比放量

Oracle → DM：高频语法差异

Oracle 写法DM 兼容情况建议
WHERE ROWNUM <= 10Oracle 兼容模式支持新代码用标准分页（FETCH FIRST / LIMIT）
(+) 外连接语法兼容模式支持，标准写法 LEFT JOIN 更通用老代码保留，新代码统一 JOIN 语法
START WITH ... CONNECT BY层次查询兼容子集复杂树遍历改用递归 CTE
DECODE / NVL / NVL2兼容新代码用 CASE / COALESCE
DATE - DATE = 天数Oracle 语义兼容注意跨库行为差异，显式转换
seq.NEXTVAL / CURRVAL兼容注意缓存（CACHE）与实例重启行为
自治事务 / 高级 DBMS 包逐项验证，不全兼容改造为普通过程 + 显式提交
空串与 NULL 的语义陷阱（Oracle/PG vs MySQL）：Oracle 里 '' 和 NULL 等价，DM 兼容模式类似；而 MySQL/PG 里空串是一个真实值。迁移后：① WHERE col = '' 在 Oracle 系库里匹配不到 NULL 行，在 MySQL 系可以；② 唯一索引对空串/多 NULL 的处理完全不同；③ 应用层"用空串表示无值"的代码，行为会静默改变。这是数据迁移后最常见的逻辑 bug 来源。

MySQL → OB / GaussDB(for MySQL) 的注意点

  • 存储过程、触发器、事件不支持，需上提到应用层。
  • 自增列语义变化，不要依赖连续自增值。
  • 分区表语法、部分函数（特定版本函数清单）需对照官方兼容性文档。
  • PG 血统产品（openGauss/GaussDB for PG）迁移自 PostgreSQL 时，重点验证：扩展插件可用性、外部表/FDW、自定义 C 函数、部分系统视图与参数名。
模块 5

迁移实操（下）：驱动兼容与生态工具

驱动与连接串

产品驱动连接串示例
达梦 DMDM 官方 JDBC（勿用 Oracle JDBC 替代）jdbc:dm://10.0.1.10:5237
OceanBaseMySQL JDBC / obclient（MySQL 协议兼容）jdbc:mysql://10.0.1.10:2881/db

驱动三坑：① 用 MySQL JDBC 连 DM 或 Oracle JDBC 连 DM —— 协议细节不保证兼容，诡异错误频出，必须用厂商官方驱动；② 连接池（Druid/Hikari）验证 SQL 是数据库特定方言，换库要改配置；③ ORM 方言（MyBatis 的 DatabaseId、Hibernate Dialect）忘记切换，分页和函数生成会出错。

生态工具盘点

迁移同步
OB：OMS；DM：官方迁移/同步工具（如 DMDataSync）；PG 系：pg_dump/gs_dump + 逻辑复制。跨库用 CDC/双写兜底
备份恢复
DM：dexp/dimp + 库级备份还原；OB：备份工具 + OCP；openGauss：gs_basebackup / gs_dump。都要做恢复演练，不是只会备
监控巡检
OB 有 OBAgent + Grafana 模板；openGauss 有 DBMind 智能运维；DM 用官方工具或通用 exporter。接入现有 Prometheus 体系
中间件/ORM
ShardingSphere、MyBatis-Plus 等要确认对目标库的方言支持；分库分表中间件在分布式库场景通常不再需要
压测
sysbench / BenchmarkSQL 适配驱动后跑基线，重点看 TPS、RT 分布、资源水位
许可与合规
DM 为商业授权；OB 社区版免费、商业版/云服务另计；openGauss 木兰宽松许可证。授权模式与采购条款以厂商合同为准
信创组合拳的现实：CPU（鲲鹏/飞腾/海光）+ OS（麒麟/统信 UOS/openEuler）+ 数据库（DM/OB/GaussDB）是一起适配的。选型时确认目标库在你们的 CPU/OS 组合上有官方支持矩阵，别在最后一步才发现没适配。
模块 6

选型对比与落地路线

四产品对比

维度达梦 DMOceanBaseGaussDB / openGauss
血统Oracle 兼容为主MySQL 协议兼容PG 血统（for openGauss）；另有 MySQL/PG 兼容线
分布式共享存储集群 DMDSC（存储共享）原生分布式（Paxos 多副本、数据分片）集中式 + 分布式双形态
HTAP有限（行列混合能力以官方为准）列存副本 + 向量化，成熟度较高以官方产品说明为准
开源许可商业授权社区版开源（4.x）openGauss：木兰宽松许可证；GaussDB：商业
典型场景Oracle 系统平移替换金融级高可用、海量数据、MySQL 拆分合并政企全栈自主可控、PG 生态替换
学习成本Oracle DBA 最低MySQL DBA + 分布式概念PG DBA 最低

选型决策顺序

原库是什么：Oracle → 优先评估 DM；MySQL → OB / GaussDB(for MySQL)；PG → openGauss/GaussDB(PG)
规模与增长：单表 < 几千万行、无爆炸增长 → 集中式足够；TB 级 + 高并发写 → 分布式
是否需要 HTAP / 强一致多活：OB 的 Paxos 多副本 + 列存是差异化优势
生态与人力：团队 Oracle/PG/MySQL 哪个积累深，直接选对应血统
成本与许可：商业授权单价、社区版功能边界、云服务 vs 自建
PoC 一票否决：语法扫描 + 样本回放 + 性能基线，三项不过就换候选

落地路线（割接 checklist）

# 阶段 1：PoC（2~4 周）
语法扫描 → 改造清单评估 → 样本数据回放 → 性能基线对比 → 输出可行性结论

# 阶段 2：试点（1~2 个月）
选非核心业务 → 全量迁移 → 灰度放量 → 监控/备份/告警三件套上线

# 阶段 3：并行期（1 个月起）
双写或 CDC 双向同步 → 每日对账 → 核心业务只读流量切流

# 阶段 4：割接
低峰停机窗口 → 最终同步校验 → 写流量切换 → 观察 24~72 小时
# 回退触发条件事先定义：RT 劣化超阈值、一致性校验失败、核心功能缺陷

# 阶段 5：稳态
备份恢复演练（每季度）→ 主备/集群故障切换演练 → 容量评审
血泪共识：国产化替换失败的项目，九成不是败在"数据库不行"，而是败在只做了功能测试没做性能测试、只做了迁移没做回退演练、只换了库没换监控和运维体系。数据库是生态迁移，不是软件安装。
模块 7

十个落地坑

1
把"兼容 Oracle"理解成 100% 兼容
PL/SQL 高级特性、部分 DBMS 包、特殊函数不全兼容。逐对象验证，别抽样，兼容性报告要落到具体对象清单。
2
用错数据库驱动
MySQL JDBC 连 DM、Oracle JDBC 连 DM 都是事故源。DM 用官方 DM JDBC（jdbc:dm://），OB 用 MySQL 协议驱动，PG 系用 openGauss 驱动。
3
忽视空串与 NULL 的语义差异
Oracle 系空串即 NULL，MySQL/PG 不是。查询条件、唯一索引、应用层判断逻辑都会静默变形，且功能测试很难覆盖到。
4
只测功能不测性能
功能全过、上线后 RT 翻倍的案例遍地。PoC 阶段必须做性能基线对比，尤其是批量任务和报表类 SQL。
5
分布式库分片键拍脑袋
按自增 ID 分片导致写入热点、按低基数字段分片导致数据倾斜、高频查询维度不在分片键上导致跨分片风暴。分片键 = 数据分布均匀 + 覆盖高频查询维度。
6
OB 租户资源单元规划过小
unit 的 memory_size/cpu 定小，业务长起来后租户内存打满，拖垮整个 observer 上的其他租户。预留 50% 以上余量，并设置资源上限。
7
共享存储集群当"高枕无忧"
DMDSC 多节点共享一份存储，存储层故障是单点。备份策略不能省，RPO/RTO 按存储故障场景设计。
8
没有回退方案就割接
割接后出问题无法回切，只能停机抢修。并行期必须建反向同步链路，回切步骤事先演练过一遍。
9
周边工具链不评估
监控 exporter、备份脚本、CDC、中间件、报表工具、堡垒机审计全都要适配。数据库换完，运维体系没换，等于裸奔。
10
不演练故障切换和跨大版本升级
主备切换时的闪断、事务丢失、应用重连行为，不演练根本不知道。跨大版本升级先在测试环境完整跑一遍，备份元数据后再动生产。
自测

六道题

1. 达梦 DM 的默认数据库端口是？
正确答案：5237。dminit 初始化时用 PORT_NUM 指定，默认 5237。连接串形如 jdbc:dm://host:5237，客户端 disql 用 SYSDBA/密码@host:5237。
2. 连接 OceanBase 用户租户（MySQL 模式）的正确方式是？
正确答案：2881 端口 + 用户名@租户名。OB 的 SQL 服务端口是 2881，多租户下用户名必须带租户后缀（root@obmysql）；1521 是 Oracle，26000 是 PG 系（openGauss）常见端口。
3. openGauss 采用的开源许可证是？
正确答案：木兰宽松许可证 MulanPSL-2.0。openGauss 是华为开源的关系型数据库，PG 血统，允许自由使用、修改和分发。GaussDB 企业版则是商业产品。具体条款以官方仓库 LICENSE 文件为准。
4. 从 Oracle 迁移到达梦后，最可能出现的"静默逻辑 bug"是？
正确答案：空串即 NULL。Oracle 系空串与 NULL 等价，MySQL/PG 里空串是真实值。迁移后 WHERE col = ''、唯一索引约束、应用层判断都会静默改变行为，且功能测试很难暴露。自增列是 MySQL→分布式库的问题，端口不通根本跑不起来。
5. 分布式数据库选分片键的首要原则是？
正确答案：分布均匀 + 高频查询维度。分片键定错了后期几乎无法在线调整：按自增/时间字段分片会制造写入热点，按低基数字段分片会数据倾斜，查询维度不在分片键上则大量跨分片查询、性能崩塌。
6. 生产割接前，必须就绪的是？
正确答案：回退方案。割接是高风险动作：并行期建反向同步、定义回退触发条件（RT 劣化/校验失败）、回切步骤事先演练。只测功能不测性能、没有回退路径，是国产化替换项目失败的头号原因。
